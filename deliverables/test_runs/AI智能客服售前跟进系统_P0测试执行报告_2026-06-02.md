# AI 智能客服售前跟进系统 P0 测试执行报告

> 执行日期：2026-06-02  
> 测试对象：P0 运营后台联调可测版本  
> 测试环境：本地 Docker `chejin-leads-api` + `chejin-leads-db`，前端静态页 `website/ops-admin.html`  
> API 地址：`http://127.0.0.1:8000/api`  

## 1. 测试结论

**结论：有条件通过，不建议上线。**

当前版本核心链路大部分可用：人工新增、重复预查、自动轮询分配、无销售分配失败、重新分配、标记无效、恢复有效、批量无效、脱敏导出、手机号明文查看审计、销售轮询开关、筛选分页、前端默认空白工作区、后端不可用兜底均已验证通过。

但发现 1 个核心缺陷：**重复手机号保存时应返回 `409 / LEAD_PHONE_DUPLICATED`，实际返回 `500 Internal Server Error`**。该问题会影响运营人员处理重复客户报备的主流程，也导致 UAT 场景“重复客户再次报备”不通过。建议修复后回归，再进入上线准入判断。

## 7. 缺陷记录

| 缺陷编号 | 标题 | 模块 | 严重等级 | 状态 |
|---|---|---|---|---|
| BUG-001 | 重复手机号保存接口应返回 409，实际返回 500 | 线索新增/重复查重 | P1 | 待修复 |

**复现步骤：**

1. 调用 `POST /api/leads` 新增线索，手机号为任意未存在号码。
2. 再次调用 `POST /api/leads`，使用同一手机号新增另一客户。
3. 观察接口响应。

**实际结果：**

- 接口返回 `500 Internal Server Error`。
- 后端日志显示：`TypeError: Object of type datetime is not JSON serializable`。
- 堆栈位置：`app/api/response.py` 中 `JSONResponse` 直接序列化 `DuplicateLeadError.data`。

**预期结果：**

```json
{
  "code": "LEAD_PHONE_DUPLICATED",
  "message": "该手机号已存在，不能重复新建...",
  "data": {
    "created": false,
    "duplicate_lead": {},
    "duplicate_count": 1
  }
}
```

**影响范围：**

- 影响运营重复报备保存场景。
- 影响前端重复错误提示。
- 影响 UAT-002 验收。
- 该问题不影响重复事件和备注追加的数据库写入，但会让调用方收到错误的 500。

## 9. 上线风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 重复手机号保存返回 500 | 高 | 核心去重链路错误响应不符合契约，影响运营判断和前端展示 |
| 正式鉴权未接入 | 中 | 当前 Header 模拟无法证明真实权限隔离 |
| 正式压测目标未确认 | 中 | 本地短时压测不能支撑生产容量承诺 |
| 自动化回归依赖缺失 | 中 | 修复后无法在容器内直接跑现有单测 |

## 10. 上线建议

**不建议当前版本上线。** 建议先修复 BUG-001，并完成以下回归后再评估上线：

1. 回归 TC-004、TC-005、UAT-002，确认重复保存返回 `409 / LEAD_PHONE_DUPLICATED`。
2. 验证前端新增弹窗能展示后端重复错误和原线索信息。
3. 复跑 P0 功能脚本和 UI 冒烟脚本。
4. 补齐容器内 `pytest` 回归能力。
5. 确认正式性能指标，包括并发用户数、目标 QPS、P95/P99、错误率和数据量。
