# P1a 销售管理与 Worker 管理 UI 一比一验收规范

日期：2026-06-05

适用对象：测试工程师、前端工程师、产品/UI。

## 1. 验收结论口径

本规范只用于验收当前已进入 UI 和开发范围的两个模块：

- 销售管理
- Worker 管理

不验收：

- 任务中心
- 任务详情
- Mac Worker 工作台
- 真实 RPA 自动加微信
- AI 自动回复
- 飞书通知
- 自动召回
- 抖音 API
- 批量导入
- Windows Worker

如果前端页面与本规范、当前本地设计稿不一致，默认记为 UI 差异，不得直接用“技术栈不同”或“组件库默认样式”判定可接受。

## 2. 当前唯一设计基准

本地设计稿页面：

```text
http://127.0.0.1:8790/website/ops-admin.html
```

本地设计稿文件：

```text
website/ops-admin.html
website/ops-admin.css
website/ops-admin.js
```

前端工程页面以实际 Vite/React 交付地址为对比对象，由前端提供。

验收时必须记录：

| 项目 | 要求 |
|---|---|
| 设计稿地址 | `http://127.0.0.1:8790/website/ops-admin.html` |
| 前端地址 | 由前端提供 |
| 测试视口 | 主视口 `1440x1000` |
| 数据状态 | 使用固定种子数据或 mock 数据 |
| 后端状态 | 后端可用，避免 loading/error/空数据干扰 UI 对比 |
| 浏览器 | Chrome |

## 3. 固定视口和截图规则

主验收视口：

```text
1440 x 1000
```

辅助检查视口：

```text
1280 x 900
```

截图规则：

1. 设计稿和前端必须使用同一视口截图。
2. 设计稿和前端必须使用同一批数据截图。
3. 截图前必须关闭浏览器缩放，保持 `100%`。
4. 截图前页面不能处于 loading、error、toast 遮挡、弹窗动画中。
5. 弹窗截图必须保证弹窗完整可见。
6. 抽屉截图必须保证抽屉顶部、主体和操作区可见；若业务内容必须滚动，应额外截滚动后状态。

## 8. 通过 / 失败判定

### 8.1 必须修改

出现以下任一情况，判定为必须修改：

1. 页面结构与设计稿不一致，例如销售管理变成卡片布局。
2. 列表出现设计稿没有的 `操作` 列或 `查看详情` 按钮。
3. 新增客户、新增销售、新增 Worker 弹窗宽度或按钮规格不统一。
4. 有取消按钮的弹窗出现右上角 X。
5. 销售状态缺少 `!` 提示图标或提示文案错误。
6. Worker Token 出现在列表里。
7. 编辑销售或编辑 Worker 打开了第二层页面/弹窗，而不是抽屉内原地编辑。
8. 表格字段缺失、顺序错误或文案不一致。
9. 抽屉操作区出现双分割线。
10. 关键按钮、字段、表格内容重叠、遮挡、不可读或不可点。

### 8.2 建议修改

以下情况可列为建议修改：

1. 间距与设计稿差异超过 `2px` 但不影响操作。
2. 阴影、边框颜色有轻微偏差。
3. 文本截断策略与设计稿不完全一致但不影响理解。
4. 表格内部横向滚动体验不够好但字段完整。

### 8.3 可接受差异

以下情况可列为可接受差异，但仍需记录：

1. 原生 select 箭头样式因浏览器不同略有差异。
2. checkbox 原生样式略有差异。
3. 字体渲染因系统抗锯齿不同出现轻微视觉差。
4. 1-2px 的非关键间距差异。

## 9. 测试执行流程

1. 确认后端和前端均已启动。
2. 确认前端使用固定测试数据或 mock 数据。
3. 打开本地设计稿，按 `1440x1000` 截图。
4. 打开前端实现页，按同视口同状态截图。
5. 按第 7 节场景逐项截图。
6. 按第 8 节判定差异等级。
7. 输出差异表。
8. 产品/UI 确认差异等级。
9. 前端修复必须修改项。
10. 测试复测并更新结论。
