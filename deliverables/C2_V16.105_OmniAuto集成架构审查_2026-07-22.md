## 2. 必须修复的问题

### P1-1 Windows 打包仍依赖已不存在的旧 ZIP

`worker-client/scripts/build-windows.ps1` 仍固定读取：

`deliverables/omniauto-add-friend-rpa-pr-candidate-20260618.zip`

该文件当前不存在。即使重新放回旧 ZIP，打包脚本也会忽略本分支刚更新的 `worker-client/omniauto-rpa`，可能把旧 OmniAuto 打进 V16.105。

修改要求：

1. Windows 打包默认直接使用当前分支的 `worker-client/omniauto-rpa`。
2. 删除固定旧候选 ZIP、临时解压目录和 `Expand-Archive` 依赖。
3. 保留 sidecar 存在性校验。
4. 更新 `worker-client/tests/test_packaging_scripts.py`，校验打包使用当前分支源码，不再校验旧 ZIP 名称。
5. manifest 增加 OmniAuto 来源提交或关键文件 SHA256，防止以后再次打错版本。

### P1-2 runner、runtime adapter 与 connector 不是同一版本

本次把最新 `wechat_sidecar_runner.py` 和 `wechat_pr28_runtime_adapter.py` 放入车金，但仍保留旧 `wechat_connector.py`。

最新 runner 会传 `conversation_type`，旧 connector 的 `get_messages`、`transcribe_voice_messages`、`send_text` 等方法不接收该参数。当前车金 Worker 直接调用 `wechat_win32_ocr_sidecar.py`，所以 C2 主链暂时不会触发；但内置 OmniAuto 已经形成一套无法正常组合使用的半集成代码。

推荐修改：同步 `855c218` 的 `wechat_connector.py`，但不要接入通用 Scheduler、Vision 或 Brain 编排。若客户端明确决定车金永远不用通用 runner，则应撤回本次 runner/runtime adapter 变更；不能保留不兼容的半套实现。

### P1-3 新安全逻辑没有带齐对应代码和测试

最新测试对车金合并版验证时发现：

1. 输入框缺少可验证边界时禁止点击：已通过。
2. 输入框点击必须落在观测到的内部区域：已通过。
3. C2 同时长、远距离语音禁止误绑定：已通过。
4. 定向搜索前看不到微信搜索框文字证据时应零点击、零按键：车金合并版失败，仍会执行退格键。
5. `humanized_input.apply_interaction_rhythm` 已存在，但 sidecar 缺少同名代理函数。
6. 集成分支保留旧测试，随机节奏测试没有固定随机种子，因此旧测试会产生假失败。

修改要求：

1. 从 `855c218` 定向移植 `sidebar_search_box_evidence` 和 `clear_sidebar_search_box_without_select_all` 的证据式点击逻辑。
2. 增加 sidecar 的 `apply_interaction_rhythm` 代理函数。
3. 同步最新 `run_wechat_win32_ocr_humanized_input_checks.py`。
4. 加入 `run_wechat_win32_ocr_interaction_evidence_checks.py`。
5. 将“唯一但距离很远的同时长语音必须拒绝”用例补入车金实际运行 sidecar 的测试。
6. 不要整份覆盖车金 V3 sidecar，也不要引入 Vision、图片旧入口或通用多会话 Scheduler。
