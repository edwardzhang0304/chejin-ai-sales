# 飞鱼线索接入要求

适用对象：飞鱼线索接入开发与验收人员。

请将飞鱼线索接入车金现有客户流程。飞鱼接口接入及内部处理方式由你负责；本说明只约定车金需要的数据、业务处理结果和验收标准。

最终效果：有效新线索进入车金后，沿用现有分配、加好友、绑定和 AI 跟进流程。重复推送不产生重复客户或重复动作；同一客户再次留资，保留原客户和原销售，记录这一次新的留资。

## 需要交付的数据

| 数据 | 我们的要求 |
| --- | --- |
| 飞鱼线索唯一编号 | 必须保留稳定编号及所属账号范围，能追溯到飞鱼原线索；重复投递仍能识别为同一次留资。编号按字符串保留，不截断。 |
| 客户名称 | 必填，去首尾空格后 1～50 字。没有姓名时先待补全；默认称呼需双方确认，不能随意编造。 |
| 手机号 | 首期每条线索一个大陆 11 位有效手机号。使用现有手机号校验；脱敏、缺失或无法解析的号码不能直接创建客户。 |
| 客户需求和备注 | 保存预算、意向车型、地区等实际提供的信息，不能误丢或改写客户原意。现有备注上限 1000 字，超长内容的保存方式需对齐。 |
| 来源和时间 | 新客户来源标识为飞鱼；保留原始留资时间、系统接收时间，时区明确。有广告／表单／渠道信息时保留关联，未提供的不伪造。 |
| 事件性质与选填信息 | 能区分首次留资、重复投递、再次留资及资料更新。微信号、邮箱等有则传；抖音昵称或用户 ID 不能当微信号。 |

## 进入车金后的流程

收到线索 → 校验必要数据 → 判断是否已处理／是否已有客户 → 新客户进入统一分配 → 按原规则生成加好友任务 → 由 Worker 执行 → 好友通过并核验绑定后进入 AI 跟进。

接入不能另起一套销售分配、加好友或 AI 调用流程，也不能绕过现有客户绑定审核。现有业务接入可能产生真实加好友任务，联调用测试客户，不能拿真实客户反复试接口。

交付边界：数据送达不等于加好友成功。需要能分清已接收、已建档／已关联、已分配及任务执行状态。

## 重复线索的业务规则

必须同时解决“同一条线索重送”和“同一客户再次留资”，两者不能混算。手机号沿用车金统一规范化与去重规则，不按姓名、昵称或备注猜测是否同一个人。

| 情况 | 应有结果 |
| --- | --- |
| 同一条飞鱼线索反复推送 | 只处理一次。客户、重复次数、备注、分配和加好友任务均不能反复增加。 |
| 同一客户有新的独立留资 | 手机号命中已有有效客户：关联原客户，登记一次新的重复留资，新增备注只追加一次；不新建客户，不重新分配、不再次自动加好友。 |
| 原客户已分配给其他销售 | 保持原销售，不因飞鱼再次推送而抢走或重新轮询。客户转移仍走现有明确操作。 |
| 同一线索资料更新 | 与再次留资区分；不能每次更新都增加重复次数。不得直接覆盖客户归属、绑定和系统短码；手机号变化或身份矛盾时待核对。 |
| 同手机号只有无效旧档案 | 沿用现有规则，可形成新档案；旧历史保留。涉及旧微信托管时，必须经过现有转移审核，不能自动复活或抢绑。 |
| 姓名一样但手机号不同 | 不自动合并；手机号相同但客户名不同也不直接覆盖旧姓名，保留本次提交的信息供核对。 |
| 多条线索同时到达 | 同一投递不能重复处理；不同留资但手机号相同，也不能并发建出两个有效客户。包括人工录入与飞鱼同时提交。 |
| 同一稳定编号对应不同客户身份 | 保留冲突记录并明确待核对，不能随便覆盖、丢弃或当成正常重送。 |

### 合成示例

客户甲第一次留资，建立客户并分给销售 A。飞鱼把这条数据又送来 5 次，车金仍只有一个客户、一次分配，不额外增加重复次数或备注。

第二天客户甲再次主动留资，使用同一个手机号：仍归销售 A；新增一次留资记录和本次需求，不再发一次好友申请。

同一稳定编号反复到达但没有足够证据表明是新留资时，不凭到达次数增加业务重复次数。需要保留飞鱼实际提供的事件／版本信息，便于区分。

## 分配 异常与数据保护

### 不改变已有分配和接单规则

有效新客户沿用车金现有轮询分配；没有可用销售时，线索保留并显示待分配／分配失败，不能丢掉，也不能反复创建客户。恢复条件后沿用原重新分配流程。

销售没有可用 Worker、Worker 离线或暂停、客户绑定待审核时，保留线索和任务，显示具体阻塞原因。接入不能自动解除销售暂停、启用停用账号、跳过审核或强行执行微信动作。

再次收到已转人工客户的留资，不自动切回 AI，不重新邀请，也不清理原来的发送凭证。是否恢复自动跟进，仍由现有业务流程决定。

### 故障后不能漏单或重复执行

接口超时、网络中断、重复投递、服务重启后，能查询到原线索的处理结果并继续收尾。不能出现飞鱼侧以为送达、车金却永久丢失；也不能因响应丢失而重复建档、分配、加好友。

数据错误或处理失败要留下明确原因和可追踪记录，能够修正后继续处理同一条线索。一个客户的数据异常不能堵住其他客户。已经处理过的记录不能通过删数据来重试。

若需要同步历史线索或补拉，先明确起始时间和范围。历史补拉与实时数据重叠时仍须去重，不能默认导入全部历史并触发批量好友申请。

### 来源和统计必须真实

新建客户的来源显示为飞鱼，不能继续记成人工录入。已有客户再次从飞鱼留资，保留原首次来源，同时记录本次飞鱼来源，不抹掉历史。

技术重复投递不计新增客户，也不增加业务重复次数。真正新增客户、重复客户再次留资、失败待处理要能区分；新增客户的销售归属沿用首次自动分配后的记录，不因后来换销售改写历史统计。

### 取证与信息保护

任意一条飞鱼线索都要能查清：是否收到、对应车金哪个客户、是否重复、分给谁、生成哪个任务、失败在哪一步。保留平台编号、车金客户／任务编号和处理时间的关联，不能只留“接口成功”四个字。

密钥和授权凭据留在服务端，不放到销售电脑。日志和对外排查材料默认脱敏，不直接输出 Token、完整手机号和无关客户信息；不让外部字段覆盖车金内部身份、短码或控制状态。

## 验收与交接

验收看最终业务结果，不只看接口返回成功。请保留可对照的测试线索编号、车金客户／任务编号及结果，覆盖以下情况。

| 验收场景 | 通过标准 |
| --- | --- |
| 有效新客户首次进入 | 一个客户、来源飞鱼、按原规则分配一次，任务可追溯。 |
| 同一条线索重复送 10 次 | 最终与只送一次相同：不多建档、不多记备注／重复次数，不多分配或加好友。 |
| 同手机号再次独立留资 | 关联旧客户，保留原销售与首次来源；新的留资、需求只记录一次。 |
| 同手机号并发进入 | 只有一个有效客户；人工录入与飞鱼并发也能正确处理。 |
| 处理成功后响应丢失／处理中重启 | 恢复后找到原结果，不丢线索，不重复业务动作。 |
| 缺姓名／无效或脱敏手机号／身份冲突 | 明确待处理原因，不造数据、不误建客户，不拖住其他线索。 |
| 没有销售／Worker 不可用／暂停 | 线索和任务保留，原因准确；条件恢复后能继续，不擅自恢复接单。 |
| 已有人工接管或旧微信绑定 | 不自动切回 AI、不抢绑定、不清凭证，沿用现有审核和恢复规则。 |
| 历史补拉与实时输入重叠 | 不漏收，不重复计数、建档或产生好友申请。 |
| 完整业务验收 | 一个授权测试客户进入后，分配、邀请、通过、绑定到正常 AI 回复走通；重复推送不再邀请。 |

### 请交接这些内容

1. 最终交付字段及样例，尤其是飞鱼唯一编号、账号范围、手机号、来源、留资时间，以及新留资与更新的区分方式。

2. 接入数据的实际范围和起始时间，是否包含历史线索；哪些类型暂未支持。

3. 接收成功、业务重复、失败待处理各如何查询，异常由谁处理；补处理不能生成重复业务动作。

4. 验收结果、真实线索开放范围和接入启停方式。若需车金侧新增接入入口或字段，提前列清变更点，不能默认现有人工录入接口已全部满足。

本文约定接入业务要求与验收标准，不代表飞鱼接入已经开发完成或上线；具体技术实现由接入方安排。
