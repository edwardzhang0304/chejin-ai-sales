# C2-C3 异常事务统一整改说明

状态：历史整改说明。2026-07-31 复审发现本文仍未拆分 UI 准入、事实结算和业务
推进，也只覆盖了图片专用恢复。恢复状态和实施顺序已由
`C1-C3_事务恢复与事实结算统一架构_v0.1_2026-07-31.md` 取代；本文仅保留
`action_phase`、集中判定器和 add_friend 点击完成点等未冲突原则，不得再单独作为
客户端整改依据。

## 一、整改目标

本轮不再针对单个测试事故增加分支，而是统一解决三类系统问题：

1. 不可逆 UI 动作已经触发但结果无法确认。
2. 同一 Flow 中多条语音或图片部分成功、部分失败。
3. Outbox 失败后的重试、换授权重建和能力暂停自动恢复。

不新增平行接口，不新增第二套角色、消息身份、排序、Vision 或 Brain 规则。

## 二、唯一分层

| 层 | 唯一职责 |
|---|---|
| OmniAuto | 操作微信并返回 observation、`action_phase` 和原始证据；不生成车金业务状态。 |
| Worker | 用唯一判定器映射动作结果、单调合并逐条结果、维护本地 ledger/Outbox；不猜后端业务状态。 |
| 后端 | 签发授权、校验合同、持久化消息/批次/任务/发送结果，并返回正式 `recovery_action`；不重做 OCR、角色或消息身份判断。 |

## 三、客户端工程师整改

1. 建立一个统一的动作结果对象，至少包含：

   ```text
   action_phase
   result
   error_code
   evidence
   source_message_key（逐条消息动作）
   ```

2. `action_phase` 只允许 `not_attempted / trigger_attempted / confirmed`。语音右键、图片复制和消息发送全部复用，禁止各写一套近似字段。
3. 在 Worker 侧只保留一个 `classify_action_result`。业务编排不得直接根据 Sidecar 的 `ok`、错误文字、截图文件名或异常类型自行决定 sent/failed/unknown。
4. 只保留一个 `merge_item_outcomes`。按 `source_message_key` 合并，completed 和 failed 集合只能增加，后一次返回的空数组或局部数组不得覆盖累计结果。
5. 只保留一个 `classify_outbox_recovery`。只消费后端 `recovery_action`，不得在发送循环、C2 主循环和 Outbox 恢复函数中分别维护错误码名单。
6. 不可逆动作前持久化 `not_attempted` 意图；触发后立即写 `trigger_attempted`；取得可靠证据后写 `confirmed`。
7. 发送已经触发但无法确认时，必须上报 `send_result=unknown + action_phase=trigger_attempted`，禁止清除发送证据或自动补发。
8. 语音/图片已经触发但无法确认时，形成带 `*_RESULT_UNKNOWN` 的 failed 事实并阻断 Brain；本轮及后续自动扫描不重复昂贵动作。
9. 允许围绕现有大编排函数提取上述结果对象和三个判定器；本期不全面重写，但禁止继续把新错误分支塞进主函数。
10. add_friend 最终“确定”按钮点击函数返回成功后立即写入 `confirmed + invite_sent`；不等待微信成功页面或成功文案。点击后截图/OCR只诊断明确失败，其自身异常不得降级成功点击。
11. add_friend 的 `ok/result_code/task_status/error_code` 只能由一个集中映射器生成，OmniAuto、Worker bridge 和任务线程不得分别重新推导。
12. 服务端任务租约续租只有在明确失效或本地 `lease_expires_at` 真实到期时才停止；单次网络超时、连接中断或 5xx 必须在到期前重试。

## 四、后端工程师整改

1. 所有 C2 入库失败响应统一返回：

   ```text
   recovery_action=retry
   recovery_action=refresh_and_rebuild
   recovery_action=capability_paused
   ```

2. 在统一异常映射层决定 `recovery_action`。service 和 route 不得分别维护一套错误码到恢复动作的映射。
3. `sent-ack` 在原接口增加并校验 `action_phase`；新 Worker 请求不得缺失。
4. 只允许以下组合：

   ```text
   sent + confirmed
   failed + not_attempted
   unknown + trigger_attempted
   ```

5. `sending` 表示发送许可已经发出、物理动作可能发生。Worker 崩溃、回执丢失或超时后进入 `unknown_send_result`，禁止自动补发。
6. 文本哈希、截图或证据冲突发生在发送可能已经触发之后时，不得强制改写成 `failed`；必须持久化 `unknown` 终态，禁止自动补发。
7. 后端必须先接收可信核心事实。单条语音/图片失败以 `item_state=failed` 正常入库并阻断 Brain；辅助证据问题只返回 warning，不得把整个批次退回。
8. 请求级合同或身份整体不兼容时返回 `capability_paused`。Worker 冻结原 Outbox、停止新 UI 动作并自动探测兼容性；恢复后原样续传，不建立人工消息处理队列。

## 五、禁止的实现方式

- 不得为某一张截图、某一条语音时长、某个测试短码或某段异常文字增加业务特判。
- 不得在 OmniAuto、Worker、后端分别判断一次“动作是否发生”。
- 不得用通用 `ok=false` 直接等价为 `failed`。
- 不得用 `retryable` 单字段继续承载全部 Outbox 策略。
- 不得以最后一次循环返回值替换整轮 completed/failed 集合。
- 不得复制已有角色、消息身份、排序、Vision 或 Brain 判断逻辑。

## 六、表驱动测试矩阵

测试必须由正式状态表生成，至少覆盖以下场景族，而不是只覆盖已发生案例：

1. 三种 `action_phase` 与成功证据、失败证据、证据缺失、证据冲突的全部合法/非法组合。
2. 多条消息的全成功、全失败、先成功后失败、先失败后成功、调用返回空集合、进程中断恢复。
3. 三种 `recovery_action` 在首次失败、重复失败、Worker 重启、能力恢复和授权变化后的行为。
4. 发送触发前失败、触发后确认、触发后截图失败、回执网络失败、Worker 崩溃、后端 `sending` 超时。
5. 三层合同测试：同一输入在 OmniAuto、Worker、后端得到唯一且一致的状态映射。
6. add_friend 点击成功后截图/OCR异常仍恢复 `invite_sent`；明确风控进入唯一 failed 终态；不得出现 `ok=true + task_status=failed`。
7. 任务租约单次瞬时续租失败后恢复时不中断动作；明确 fencing/owner 失配或真实到期时立即停止。

必须持续满足：

```text
completed事实不丢失；
failed集合不缩小；
unknown发送不自动重发；
failed消息事实可入库且不丢失；
capability_paused自动探测恢复且不循环重建；
客户内容不完整时不调用Brain；
同一规则只有一个所有者。
```

## 七、实施顺序

1. 先修改机器合同、统一结果类型和表驱动合同测试。
2. 再修改 OmniAuto Sidecar 动作证据。
3. 再修改 Worker 三个集中判定器和编排调用点。
4. 再修改后端恢复动作、发送回执校验和持久化。
5. 跑三层自动化矩阵和重启恢复测试。
6. 自动化全部通过后再打 Windows 包，执行真实语音、图片、Brain 回复和断网/重启 UAT。

## 八、实施结果（Mac 自动化已对齐）

1. 机器合同升级到 `3.7.0`，统一定义动作阶段、逐条结果单调合并和 Outbox 恢复动作。
2. Worker 只保留一组正式判定器：

   ```text
   classify_action_result
   merge_item_outcomes
   classify_outbox_recovery
   ```

3. OmniAuto 的加好友、发送、语音和图片动作统一返回 `action_phase`；不可逆动作触发后无法确认时，不再降级成普通失败。
4. 语音续处理不再维护相互覆盖的成功、失败、角色和锚点临时数组，全部通过 `merge_item_outcomes` 累计并派生结果。
5. 后端错误响应统一返回 `recovery_action`；Worker 不再解析 HTTP 文案、截图名称或本地错误码名单决定恢复方式。
6. `sent-ack` 三层统一校验合法组合，已触发但无法确认的发送只能记录为 `unknown + trigger_attempted`。
7. 已删除无生产调用或已退役的 UIA 直写、猜坐标发送、旧会话快速分支、旧语音按钮入口和 Worker 旧读取包装器。
8. 图片“剪贴板复制确认”和“Vision 业务结果完成”由同一个
   `classify_action_result` 同时校验；主流程不再自行把复制成功修正为识图成功。
9. Worker 保留 SQLite `c2_action_journal`，用于“OmniAuto 已返回结果后、ledger 尚未完成”这一段的结果检查点。
10. C2 Outbox 状态统一为
    `waiting / retry_waiting / refresh_pending / rebuild_pending / split_pending /
    capability_paused / split_completed / target_terminated /
    conversation_terminated / confirmed`；
    网络重试采用有上限的指数退避间隔，但不因固定次数放弃原事实。
    只有合同版本、SHA 或 schema 暂不兼容时进入 `capability_paused`，后台自动探测；
    能力或合同恢复后转回 `waiting` 并续传原 Outbox。
    请求过大自动拆批；无效媒体只把后端点名的 `source_message_key` 重建为
    failed 事实；解绑目标和身份冲突必须由后端确认终态后结束，禁止原样死循环。
    通用 `VALIDATION_ERROR` 发生在后端保存事实之前，固定进入
    `capability_paused`，不得返回终态确认或清理本地 ledger。
    消息事实或 `sent_ack` 未获后端确认期间，Outbox 是 Worker 级全局门禁：
    不得扫描、切换或处理其他会话。
    任务线程与 C2 线程共用 `c2_outbox_lock`，保证创建、首次提交、重传和状态迁移
    单飞执行。
11. 发送事务按真实动作边界持久化：
    `not_attempted -> trigger_attempted -> confirmed`。仅有发送意图但尚未物理点击时，重启后允许由任务中心恢复；物理动作已经触发后禁止自动补发。
12. 加好友、语音、图片和发送共用磁盘 `ActionJournal`，用于覆盖“物理动作前到 OmniAuto 返回前”的危险窗口：

    ```text
    创建动作日志并写 not_attempted
    → 点击“发送好友申请”/“语音转文字”/“复制图片”/“发送消息”前落盘 trigger_attempted
    → add_friend：最终“确定”按钮点击函数返回成功后立即落盘 confirmed
    → 语音/图片/发送：取得各自合同规定的可靠结果证据后落盘 confirmed
    → Worker 把结果写入 ledger
    → ledger 成功后才删除动作日志
    ```

13. Worker 启动、进入会话以及正常/异常统一收尾时都会恢复遗留
    `ActionJournal`。只要日志显示动作已经触发，即使 Sidecar 崩溃、Worker
    被强杀、停止授权或业务结果未返回，也会自动形成 failed/unknown 事实并禁止重复
    发送好友申请、右键、复制、发送消息或计费。
14. 图片取消不再固定返回 `not_attempted`。图片已经复制时，取消结果继承
    `trigger_attempted/confirmed` 物理阶段；图片字节仍只存在内存，动作日志中
    不保存原图。
15. `capability_paused` 和 `confirmed` Outbox 的 `payload_json` 已冻结；同一个
    `outbox_id` 后续写入不能覆盖原始证据。
16. C2-C3 的失败和发送未知不再描述为“人工修消息”。Worker 只上报消息事实和
    技术门禁，不携带业务接管结论；后端 C3 根据正式状态机决定是否进入
    `sales_handoff`。
17. 保留期清理覆盖所有不再重试的 C2 Outbox 终态，同时永久跳过等待、重试和能力
    暂停记录。
