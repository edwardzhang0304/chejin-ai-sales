# 前端错误展示整改说明

日期：2026-06-03
负责人：前端工程师

## 1. 结论

已完成前端错误展示整改。后端返回业务错误时，前端可展示 `message`、`code` 和 `trace_id`，关键操作失败时用户能看到可提供给后端排障的信息。

## 2. 本次整改范围

- `frontend/src/shared/api/client.ts`
  - `ApiError` 增加 `traceId`。
  - `request()` 从后端响应 envelope 读取 `trace_id`。
  - 新增 `formatApiError()`，统一输出：`message（错误码：code，Trace ID：trace_id）`。
- `frontend/src/features/leads/*`
  - 新增客户、重复手机号、标记无效、恢复有效、重新分配、导出、手机号明文查看等失败提示统一展示错误码和 Trace ID。
  - 导出失败时解析后端 JSON 错误包，不再只显示普通 `Error.message`。
- `frontend/src/features/sales/SalesPage.tsx`
  - 销售列表、销售状态切换、新增销售失败提示统一展示错误码和 Trace ID。
- `frontend/src/features/logs/LogsPage.tsx`
  - 操作日志列表加载失败提示统一展示错误码和 Trace ID。
- `deliverables/test_runs/run_vite_frontend_smoke.js`
  - `VITE-004` 增加 `LEAD_PHONE_DUPLICATED` 和 `Trace ID` 可见性断言。

## 5. 待后端确认

- 生产环境所有错误响应需持续保持 `code/message/trace_id/data` envelope 结构。
