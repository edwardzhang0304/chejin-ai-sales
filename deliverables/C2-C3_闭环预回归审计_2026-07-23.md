## 本轮闭环收口

1. 消息处理完成后统一先写 Outbox，再调用 `messages/ingest`。
2. 后端重启后会自动恢复已提交但未完成的 Brain 批次。
3. Brain 网络调用前释放数据库锁，新客户消息可以正常使旧回复失效。
4. `chat_reply` 只有持有当前会话 UI 锁的 C2 流程可以领取和发送。
5. 物理发送前先持久化发送意图，发送后持久化结果，再向后端回执。
6. 回执网络失败只重传回执，不再次操作微信。
7. 重启时无法确认发送结果则上报 `unknown` 并转人工，禁止猜测补发。
8. 已进入 `sending` 的回复不再被新消息直接篡改，发送回执仍可合法收口。
9. 发送失败、结果未知或长期没有回执会释放任务并创建人工接管事件。
10. 后端的重复领取提示已统一为
    `reconcile_sent_ack_without_resend`，不再误导客户端重复发送。
11. Docker 正式包含 OmniAuto Brain 配置文件；密钥只从环境变量读取。
12. `/readyz` 现在真实检查 Brain 配置和密钥，不再只检查模式名称。
13. 修正 Anthropic 兼容地址为 `https://aiself.vip/v1`，OmniAuto 最终请求
    `https://aiself.vip/v1/messages`。
14. 后端配置读取器允许同一 `.env` 中存在 OmniAuto 供应商变量，车金和
    OmniAuto 各自读取自己拥有的字段。

## 已验证的关键异常

- 消息入库网络失败：原 JSON 原样重传，不重新 OCR/转语音/Vision。
- 后端在 Brain 开始前重启：自动恢复 `collecting` 批次。
- 后端在 Brain 执行中重启或无进展：有限恢复，耗尽后明确失败。
- 发送成功但回执断网：只补回执，不重复发送。
- 发送许可证重复领取：不再次发送。
- 发送后 Worker 崩溃且结果未知：不自动补发，转人工。
- 新客户消息在发送瞬间到达：旧发送回执仍可收口，新消息保持待处理。
- 客户端停止授权：不再继续定向读取、转写、识图或发送。

## 运行配置

Mac 后端密钥已写入被 Git 忽略且权限为 `600` 的本机
`backend/.env`。Windows Worker 仍需通过运行环境提供相同类型的真实模型
凭据。不得将密钥写入 Git、安装包、日志或截图。

```text
OPENAI_API_KEY=<真实密钥>
OPENAI_BASE_URL=https://aiself.vip/v1
OPENAI_MODEL=gpt-5.5
OPENAI_FLASH_MODEL=gpt-5.5
OPENAI_PRO_MODEL=gpt-5.5
OPENAI_FLASH_REASONING_EFFORT=xhigh
OPENAI_PRO_REASONING_EFFORT=xhigh
```

配置完成后必须先确认 `/readyz` 返回 `brain.ready=true`，再开始 Windows
实机回归。
