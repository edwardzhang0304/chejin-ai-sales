## 1. 结论

本轮后端已完成销售管理和 Worker 管理接口开发、自测和容器环境验证。

本轮严格按边界实现：只做销售管理和 Worker 管理，不做任务中心、不做真实 RPA、不做 AI、不做飞书、不做召回；任务状态机未最终确认前，后端未扩展任务中心接口。

## 2. 本次完成范围

### 2.1 销售管理

- 销售列表查询。
- 新增销售。
- 查看销售详情。
- 编辑销售。
- 销售状态只有 `enabled=true/false`，对应启用 / 停用。
- 启用销售可参与后续线索分配。
- 停用销售不再分配新线索，历史线索不变。
- 支持销售绑定 Worker、更换 Worker、清空 Worker。
- Worker 只能绑定一个销售。
- 已绑定其他销售的 Worker 不可再次绑定。
- 已停用 Worker 不可被选择绑定。
- 离线但启用的 Worker 可以绑定。
- 销售详情返回基础信息、当前 Worker、Worker 状态、最近心跳、今日分配、阻塞任务数。
- `blocking_task_count` 本轮先返回 `0`，任务系统完成后再接真实统计【待确认】。

### 2.2 Worker 管理

- Worker 列表查询。
- 新增 Worker。
- 查看 Worker 详情。
- 编辑 Worker。
- 启用 / 停用 Worker。
- Worker 心跳更新在线状态、运行状态、当前任务、最近心跳。
- 新增 Worker 后后端生成 Worker ID 和 Worker Token。
- Worker ID 使用 UUID 唯一字符串，不使用 `WK-001` 这类短编号。
- Worker Token 不在列表接口返回，只在新增返回和详情接口返回。
- 支持重置绑定：
  - 生成新的 Worker Token。
  - 旧 Token 失效。
  - `client_binding_state` 更新为 `reset_required`。
  - 如果 Worker 有进行中任务，返回强提示 `warning`，但允许继续重置。
- Worker Token 使用 HMAC 哈希校验，并加密存储，不落明文 Token。

## 3. 本次新增 / 调整接口

### 3.1 销售管理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/sales` | 销售列表 |
| `POST` | `/api/sales` | 新增销售，支持传入 `worker_id` 直接绑定 |
| `GET` | `/api/sales/{sales_id}` | 销售详情 |
| `PUT` | `/api/sales/{sales_id}` | 编辑销售，支持 `worker_id` 换绑或传 `null` 清空 |
| `POST` | `/api/sales/{sales_id}/worker-binding` | 绑定 / 更换 Worker |
| `DELETE` | `/api/sales/{sales_id}/worker-binding` | 清空 Worker 绑定 |

销售详情关键字段：

```json
{
  "id": "sales_uuid",
  "sales_name": "张伟",
  "enabled": true,
  "worker_id": "worker_uuid",
  "current_worker": {},
  "worker_status": {},
  "worker_last_heartbeat_at": "2026-06-05T03:26:23.745109+00:00",
  "today_assignment_count": 0,
  "blocking_task_count": 0
}
```

### 3.2 Worker 管理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/workers` | Worker 列表，不返回 `worker_token` |
| `POST` | `/api/workers` | 新增 Worker，返回首次生成的 `worker_token` |
| `GET` | `/api/workers/{worker_id}` | Worker 详情，返回 `worker_token` |
| `PUT` | `/api/workers/{worker_id}` | 编辑 Worker |
| `POST` | `/api/workers/{worker_id}/enable` | 启用 Worker |
| `POST` | `/api/workers/{worker_id}/disable` | 停用 Worker |
| `POST` | `/api/workers/{worker_id}/heartbeat` | Worker 心跳 |
| `POST` | `/api/workers/{worker_id}/reset-binding` | 重置绑定并生成新 Token |

Worker 心跳 Header：

```text
X-Worker-Token: wkt_xxx
```

Worker 心跳请求体：

```json
{
  "running_status": "idle",
  "current_task": null,
  "client_binding_state": "bound"
}
```

## 4. 错误码

| 错误码 | HTTP 状态 | 说明 |
|---|---:|---|
| `SALES_NOT_FOUND` | 404 | 销售不存在 |
| `WORKER_NOT_FOUND` | 404 | Worker 不存在 |
| `WORKER_ALREADY_BOUND` | 409 | Worker 已绑定其他销售 |
| `WORKER_DISABLED_CANNOT_BIND` | 400 | 已停用 Worker 不可绑定销售 |
| `WORKER_TOKEN_INVALID` | 401 | Worker 心跳 Token 无效 |
| `WORKER_DISABLED` | 400 | 已停用 Worker 不能上报心跳 |
| `WORKER_TOKEN_DECRYPT_FAILED` | 500 | Worker Token 解密失败 |

所有错误响应均包含 `trace_id`，响应头透传 `X-Request-Id`。

## 5. 审计日志

- 新增销售：`sales_created`

- 启用 / 停用 Worker：`worker_enabled_changed`
- 重置 Worker 绑定：`worker_binding_reset`

说明：Worker 心跳是 Worker 客户端状态上报，不带后台操作人，本轮不写后台操作日志。

## 8. 已知问题 / 待确认

- `blocking_task_count` 当前返回 `0`，任务系统完成后再接真实阻塞任务统计【待确认】。
- Worker 重置绑定后客户端具体清空或刷新哪些本地字段，仅后端先返回 `client_binding_state=reset_required`【待确认】。

- 本轮没有任务中心接口，没有任务领取/回传接口，没有真实 RPA、AI、飞书、召回。
- 正式鉴权未接入，后台操作仍使用 `X-Operator-*` Header 模拟操作人。
