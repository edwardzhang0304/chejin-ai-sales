# AI智能客服售前跟进系统 验收标准

版本：v2.5

日期：2026-05-27

适用范围：第一期正式工程版本。

说明：本文档用于项目交付验收，不包含二期 SaaS 化、多商户、复杂权限、计费体系、高可用集群和长期运维。

## 1. 验收总原则

本期系统的核心验收标准为：

```text
系统能够根据客户消息正常自动回复；
或在无法安全回复、识别失败、命中风险规则、模型失败、图片低置信度、车源证据不足时，正确停止AI并触发人工接管通知。
```

验收不以“完全像真人”“百分百识别所有客户意图”“任何微信环境永久稳定”为标准。验收以约定测试环境、真实样本、可复现操作、系统日志和验收用例结果为准。

性能指标作为优化目标，不作为未经压测的硬性验收承诺。最终结果以测试环境、微信账号状态、网络质量、模型服务、大风车接口和真实样本实测为准。

## 2. 验收前提

| 类型 | 前提条件 | 未满足时处理 |
|---|---|---|
| 测试电脑 | 提供商家侧 Windows 测试电脑，安装指定版本微信桌面客户端和 Worker。 | 无法验收 Worker、加好友、监听、图片另存和发送。 |
| 微信账号 | 提供测试销售个人微信，账号可正常登录、加好友、收发消息。 | 账号受限、风控或登录异常不计为系统功能缺陷。 |
| 销售手机端 | 提供销售微信手机客户端，用于人工回复和接管验证。 | 无法验收销售人工回复后 AI 停止。 |
| 线索样本 | 提供手机号线索样本，包含有效手机号、无效手机号、重复手机号、拒绝客户样本。 | 相关用例顺延。 |
| 知识库资料 | 提供二手车售前知识库、禁说规则、销售话术边界。 | RAG 和 Guard 验收只验证框架，不验证最终业务质量。 |
| 图片样本 | 提供客户发车图、截图、价格图、无关图、低清图等样本。 | 图片链路只能用模拟样本验收。 |
| 大风车条件 | 提供可联调的 appKey、appSecret、appId、shopCode、operator、IP 白名单、接口字段说明。 | 未满足时按本地车源导入/样本索引降级验收。 |
| 千问视觉 | 提供可用 API Key 和额度。 | 图片识别链路无法完整验收。 |
| DeepSeek | 提供可用模型配置和额度。 | AI 文字回复链路无法完整验收。 |
| 飞书机器人 | 提供可向销售个人发送通知的飞书机器人配置。 | 只验收接管事件和错误日志，不验收通知到达。 |

## 3. 验收范围

| 模块 | 本期验收内容 | 不验收内容 |
|---|---|---|
| 云端业务控制面 | 线索、销售、Worker、任务、会话、风控、召回、飞书通知日志、审计。 | 复杂权限、CRM、BI、多商户、计费。 |
| Worker执行台 | 启动/暂停、任务展示、步骤展示、微信连接状态、错误日志、图片缩略图、AI/Guard结果展示。 | 开机自启动、无人值守长期运维。 |
| 备注短码工具 | 生成线下好友可使用的系统短码和推荐备注；短码新增可绑定，短码移除可关闭自动跟进。 | 销售端独立App、复杂审批流。 |
| 加好友 | 手机号搜索、固定申请语、初始备注、已是好友处理、失败原因记录、人工重试入口。 | 规避微信平台风控、突破账号限制。 |
| 会话绑定与监听 | 绑定会话、监听文字/图片、去重、销售人工回复检测、未绑定不自动回复。 | 读取微信数据库、破解协议、非公开微信接口。 |
| AI文字回复 | DeepSeek、OmniAuto、RAG、上下文、轮次限制、风险转人工。 | 模型微调平台、百分百意图识别。 |
| 图片理解与图文回复 | 图片另存、上传、千问视觉、ImageIntent、车源索引、图文候选回复、低置信转人工。 | 建立长期图片库、视觉模型训练。 |
| 大风车与车源索引 | 店铺/车辆/图片接口联调、字段白名单、本地索引、失败保留旧索引。 | 对方未开放字段的能力承诺。 |
| 风控策略 | 总开关、静默时段、上限、黑名单、关键词、接管关键词、单会话限频、风险暂停。 | 复杂机器学习风控、规避平台检测。 |
| 人工接管与飞书 | 接管状态、AI 停止、飞书通知一次发送、sent/failed 日志。 | 飞书二次通知能力、飞书按钮、复杂通知权限。 |
| 自动召回 | 等待用户回复类会话、N 天未回复、固定/配置化召回内容、每日上限、多轮召回、防重复。 | AI 自由发挥式召回、无上限高频触达。 |

## 4. 缺陷等级

| 等级 | 定义 | 验收处理 |
|---|---|---|
| S1 阻塞 | 主链路不可用或存在严重业务风险。包括无法加好友、无法监听消息、无法发送回复、AI 停不住、重复发送同一回复、人工接管后仍自动回复、敏感字段泄露。 | 必须修复后验收。 |
| S2 严重 | 核心功能部分失败但有人工降级。例如图片低置信过多、大风车同步失败但保留旧索引、部分异常未展示清楚。 | 需修复或双方确认降级方案后验收。 |
| S3 一般 | 不影响主流程的体验、文案、展示、配置默认值问题。 | 可进入试运行问题清单，不阻塞验收。 |
| S4 建议 | 优化建议或新增需求。 | 不计入本期缺陷，进入后续变更。 |
| 外部依赖 | 微信版本变化、账号受限、模型服务故障、大风车未开放字段、飞书配置不可用、网络故障。 | 按责任边界和降级方案处理，不直接归为系统开发缺陷。 |

## 5. 核心验收用例

### 5.1 线索与销售

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| A-01 | 导入有效手机号线索 | 导入或录入一条有效手机号。 | 生成线索，手机号默认脱敏展示，状态为 new 或 assigned。 |
| A-02 | 重复手机号去重 | 重复导入同一手机号。 | 不生成多个有效跟进线索，保留来源记录或提示重复。 |
| A-03 | 拒绝客户再次导入 | 将客户标记 rejected 后再次导入。 | 不自动生成加好友、自动回复或召回任务。 |
| A-04 | 销售绑定 Worker | 绑定销售和 Worker。 | 销售、微信账号、Worker 一一绑定，允许换绑且有记录。 |
| A-05 | 销售每日加好友上限 | 设置每日上限后继续生成任务。 | 超出上限后不继续自动生成或执行 add_friend。 |

### 5.2 加好友

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| B-01 | 手机号搜索加好友 | Worker 领取 add_friend 任务。 | 微信桌面端按手机号搜索并提交固定好友申请语。 |
| B-02 | 初始备注 | 添加或识别好友后写入初始备注。 | 备注包含可绑定线索的短码或规则字段。 |
| B-03 | 已是好友处理 | 导入已是好友手机号。 | 不重复发送好友申请，立即尝试绑定会话。 |
| B-04 | 加好友失败 | 使用无效手机号或受限场景。 | 任务失败原因可见，可人工重试。 |
| B-05 | 微信风险提示 | 出现操作频繁、添加受限等提示。 | Worker 暂停对应任务，上报错误，不连续重试。 |
| B-06 | 线下好友生成短码 | 销售线下已有微信好友，在短码工具生成备注短码并修改微信备注。 | Worker识别短码，服务端创建/绑定线索和会话，系统开始跟进。 |
| B-07 | 移除短码关闭自动跟进 | 已绑定会话中销售删除或改掉系统短码。 | 服务端状态进入 closed，AI、召回、销售超时提醒停止。 |

### 5.3 会话绑定与监听

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| C-01 | 会话绑定 | 客户通过好友后发送消息。 | 系统能把微信会话绑定到对应线索。 |
| C-02 | 未绑定不回复 | 制造无法识别客户的会话。 | 系统不自动回复，记录绑定失败原因。 |
| C-03 | 文字监听 | 客户发送文字。 | Worker 上报 message_event，服务端去重并进入 AI 链路。 |
| C-04 | 图片监听 | 客户发送图片。 | Worker 识别图片消息并进入图片另存/上传链路。 |
| C-05 | 销售人工回复检测 | 销售手机端回复客户。 | 桌面端同步后系统识别为 sales_reply，AI 停止。 |

### 5.4 AI文字回复

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| D-01 | 普通咨询回复 | 客户问普通购车问题。 | 系统基于上下文和知识库生成回复并发送。 |
| D-02 | RAG 命中 | 客户问知识库中已有问题。 | 回复引用正确知识，不编造关键事实。 |
| D-03 | 敏感问题转人工 | 客户问底价、事故、泡水、贷款、合同等。 | AI 停止或不直接承诺，进入 handoff_required。 |
| D-04 | 模型失败 | 模型超时或返回异常。 | 不发送兜底话术，触发人工接管。 |
| D-05 | AI持续接待 | 同一客户连续多轮咨询。 | AI不因固定轮次停止；只有转人工、拒绝、关闭或风控禁止时停止。 |

### 5.5 图片理解与图文回复

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| E-01 | 图片另存 | 客户发送车辆图片。 | Worker 点开并保存到配置目录。 |
| E-02 | 视觉识别 | 图片上传服务端调用千问视觉。 | 输出 ImageIntent，包含图片类型、识别摘要、置信度。 |
| E-03 | 图片找车 | 客户发送车型/车辆截图。 | 系统基于识别结果检索本地车源索引。 |
| E-04 | 图文回复 | 图片意图清晰且证据充足。 | OmniAuto 结合图片、知识、车源生成候选回复，Guard 通过后发送。 |
| E-05 | 图片低置信 | 图片模糊、无关或识别失败。 | 不强行回复，进入人工接管。 |

### 5.6 大风车与车源索引

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| F-01 | 鉴权联调 | 使用大风车参数请求接口。 | 鉴权成功或错误日志明确。 |
| F-02 | 店铺查询 | 查询 shopCode 店铺信息。 | 返回店铺基础信息或明确失败原因。 |
| F-03 | 车辆列表 | 按 shopCode 和 operationPhase 拉取车辆 ID。 | 能拉取车辆 ID，并记录可售状态配置。 |
| F-04 | 车辆详情与图片 | 按 carId 拉取详情和图片。 | 可建立 raw_vehicle 和 AI 可见 vehicle_index。 |
| F-05 | 字段隔离 | 检查 AI evidence pack。 | 底价、采购价、车主隐私、内部备注不进入 AI 上下文。 |
| F-06 | 接口失败降级 | 模拟大风车失败。 | 保留上次成功索引，不编造车源，必要时转人工。 |

### 5.7 风控策略

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| G-01 | 自动回复总开关 | 关闭全局或会话自动回复。 | 客户发消息后不自动回复。 |
| G-02 | 静默时段 | 设置当前时间为静默时段。 | 客户主动发消息也不自动回复。 |
| G-03 | 黑名单 | 将手机号加入黑名单。 | 不加好友、不自动回复、不召回。 |
| G-04 | 关键词拦截 | 客户发送投诉、退款、律师等关键词。 | 不直接回复或进入人工接管。 |
| G-05 | 单会话限频 | 短时间内连续发送多条消息。 | 消息合并或限频，不连续高频回复。 |
| G-06 | 风险暂停 | Worker 检测微信风险提示。 | 自动暂停相关任务并记录原因。 |

### 5.8 人工接管与飞书

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| H-01 | 风险触发接管 | 客户问高风险问题。 | 会话进入 handoff_required，ai_enabled=false。 |
| H-02 | 飞书通知 | 触发接管后调用飞书机器人。 | 发送一次通知给销售个人，HandoffEvent 记录 sent。 |
| H-03 | 飞书失败 | 配置错误或模拟失败。 | AI 仍停止，HandoffEvent 记录 failed 和错误摘要。 |
| H-04 | 不重复通知 | 同一接管事件重复触发。 | 同一 handoff_event_id 不重复发送飞书。 |
| H-05 | 接管后客户继续发消息 | 进入 handoff_required 后客户继续发。 | 不再次提醒销售，不自动回复。 |
| H-06 | 销售超时提醒 | 进入 waiting_sales_reply 后销售 N 天未回复。 | 服务端发送一次飞书通知销售并记录 sent/failed。 |

### 5.9 自动召回

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| I-01 | 等待用户回复 | AI、人工或召回发送成功。 | 状态进入 waiting_user_reply、sales_replied_waiting_user 或 recalled_waiting_user。 |
| I-02 | 召回任务生成 | 等待用户回复超过 N 天，且未拒绝、未关闭、未超上限。 | 生成 follow_up 任务。 |
| I-03 | 固定文案发送 | Worker 执行 follow_up。 | 发送固定召回文案并记录 sent_ack。 |
| I-04 | 多轮召回 | 召回后客户仍未回复，到下一周期再次满足规则。 | 可再次生成 follow_up，受每日上限和单客户策略限制。 |
| I-05 | 召回排除 | 客户已 rejected/closed/黑名单，或客户已回复。 | 不生成召回任务。 |

### 5.10 并发、幂等与恢复

| 编号 | 用例 | 操作 | 通过标准 |
|---|---|---|---|
| J-01 | 多客户并发 | A、B、C 依次发消息。 | 不同会话按队列处理，互不串话。 |
| J-02 | 同客户追加消息 | A1 生成中但未发送时 A2 到来。 | 旧 reply_action 作废，基于 A1+A2 重新生成。 |
| J-03 | sending 异常 | Worker 进入 sending 后异常退出。 | 状态进入 unknown_send_result，不自动补发。 |
| J-04 | Worker 重启 | 重启 Worker。 | 以服务端状态恢复，不重复发送。 |
| J-05 | 服务端重启 | AI 生成或任务执行中服务端重启。 | 任务状态可恢复，不重复发送。 |
| J-06 | 重复消息 | 同一 dedupe_key 重复上报。 | 只处理一次。 |
| J-07 | 微信UI操作串行 | 同时触发加好友、图片另存、AI回复、召回任务。 | 所有需要操作微信桌面端的动作按Local WeChat UI Lock串行执行，不并行操作微信窗口。 |
| J-08 | 错误码可解释 | 模拟微信登录失效、模型超时、图片低置信、大风车鉴权失败、飞书通知失败等异常。 | 控制面、Worker执行台和日志均展示稳定 `error_code`、错误说明、建议处理动作和 `trace_id`；不允许只展示“未知错误”。 |

## 7. 验收通过条件

本期验收通过需同时满足：

```text
S1缺陷数量 = 0
核心链路线索 -> 加好友 -> 会话绑定 -> 自动回复/人工接管可演示通过
图片链路可完成图片另存、视觉识别、图文回复或低置信转人工
大风车在已提供接口条件下可同步车源或按降级方案验收
飞书接管通知可发送或失败日志可见
自动召回可按规则生成并发送固定文案
防重复发送用例通过
错误码可解释用例通过
验收证据齐全
```

S2 缺陷如未全部修复，需双方确认是否接受降级方案或进入限期修复清单。S3 和 S4 不阻塞验收。

## 8. 不通过处理

| 场景 | 处理方式 |
|---|---|
| 出现 S1 缺陷 | 暂停验收，修复后重新验证相关用例。 |
| 外部依赖未提供 | 记录为验收前提未满足，相关用例顺延或按降级方案验收。 |
| 业务配置未确认 | 使用临时配置验收系统能力，最终配置由项目方后续调整。 |
| 模型回答质量争议 | 以知识库、Guard 规则、低置信转人工机制和样本集复测为准。 |
| 微信账号/版本异常 | 记录环境异常，恢复账号或版本后重测，不直接归为系统缺陷。 |
