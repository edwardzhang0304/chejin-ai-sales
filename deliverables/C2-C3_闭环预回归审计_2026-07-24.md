# C2-C3 闭环预回归审计（2026-07-24）

## 结论

多轮架构审计提出的读取、图片、Brain、任务中心和回复发送业务阻断项已
逐条复核并收口。最新一轮人工接管顺序、C1 加好友丢锁取消和 P2 冗余代码
也已处理，没有通过 Worker 特判 409 或新增第二套业务规则绕过问题。

Mac 能自动验证的 C2-C3 链路已全部通过。Windows 真实微信 UI、剪贴板、
语音右键和最终发送仍需实机回归。

## 回复发送闭环修复

1. **按 Enter 不再等于发送成功**
   - 正式路径不再使用 Enter 或 Ctrl+Enter。
   - UIA 只负责找到真实输入框和真实“发送”按钮，输入和点击仍使用物理
     `SendInput`。
   - 点击后必须同时看到“输入框已经清空”和“新增一条正文完全一致的
     右侧气泡”，否则只返回 `SEND_RESULT_UNKNOWN`，不得回报 `sent`。

2. **AI 右侧气泡不再冒充人工销售**
   - Worker 在发送确认时取得真正新增的右侧气泡 observation，通过同一套
     消息身份账本生成稳定身份，并保存 `reply_action_id + 文本 hash +
     稳定身份` 回执。
   - 下一轮只有完全相同的稳定气泡才能携带该回执入库；后端还会复核
     会话、ReplyAction、正文、hash、稳定身份和时间窗口。
   - 匹配项保留 `sender_role=self`，来源记为 `sender_source=ai`；没有
     强回执的同文右侧气泡仍是 `sender_source=human`，不能靠内容猜 AI。
   - AI 来源不会触发“销售人工接管”，人工来源仍会进入
     `sales_replied_waiting_user`。

3. **未知人工草稿不再被删除**
   - 发送前发现输入框非空时立即停止自动回复，返回
     `WECHAT_INPUT_DRAFT_PRESENT`。
   - 正式路径不再对未知内容执行 Backspace/Delete。
   - 只有能够证明属于本次程序的发送内容，才允许继续后续动作。

4. **停止监听可以中止正在准备的发送**
   - 领取发送许可前、开始输入前都重新检查会话、授权版本和
     `read_reason`。
   - sidecar 执行期间，父进程持续检查停止状态；授权被撤销时终止
     sidecar，不再继续点击发送按钮。
   - Brain 等待和物理发送期间使用 batch 返回的轻量授权快照复核，不再
     每秒拉取包含历史身份清单的完整 `read-targets`。

5. **输入框和发送按钮只认 UIA 真实控件**
   - 正式发送不再按窗口比例猜输入框或发送按钮坐标。
   - 找不到真实 `EditControl` 或发送按钮时安全失败，不启用第二套盲点
     坐标或 UIA 直接写值/Invoke 路径。
   - UIA 的屏幕坐标统一通过 Win32 `ScreenToClient` 转成客户区坐标，
     不再用减窗口左上角的方式猜标题栏和边框偏移。

6. **Brain 正文、实际输入和 hash 使用同一份文本**
   - 后端先把 CR/LF、制表符和重复空白统一成唯一“最终发送文本”，再计算
     hash。
   - Worker 拒绝任何未规范化正文或 hash 不一致的发送许可。
   - sidecar 不再偷偷改完文字后仍回报原文已发送。

7. **发送动作只验证当前会话**
   - 正式发送必须携带 `current_only`。
   - 当前标题、短码或 `private` 证据不正确时立即停止。
   - 发送动作内禁止调用 `open_chat`、搜索短码或切换会话；崩溃恢复只能
     在进入发送动作以前恢复会话上下文。

8. **失败图片服从后续人工销售回复边界**
   - 图片失败、消息历史断层和身份未确认等所有安全门禁，都服从最后一条
     人工销售消息边界。
   - 如果销售已在门禁问题后面人工回复，旧门禁不会把会话状态重新覆盖回
     `waiting_sales_reply`。

9. **额外收口：旧发送配置不会退回 Enter**
   - 默认和正式配置统一为 `click_only`。
   - 历史 `enter_then_click` 自动迁移为 `click_only`。
   - 显式 `enter_only` 只会返回 `SEND_BUTTON_CONTROL_REQUIRED`，不会按键。

10. **正式包补齐唯一回复路径依赖**
    - Windows 正式依赖锁定 `uiautomation`，PyInstaller 明确收集该模块。
    - 构建脚本会检查安装环境可以 import、安装包归档包含模块，并实际启动
      打包后的 sidecar `--help` 预检。

11. **发送确认不再依赖“同文数量增加”**
    - 发送前后分别建立有顺序的消息 observation 序列。
    - 使用序列差异找到真正新增、位于底部且正文完全一致的 `self` 气泡。
    - 旧同文气泡滚出屏幕或 OCR 数量变化只能作为诊断，不能证明发送成功。

12. **旧发送路径已从正式 sidecar 删除**
    - 删除 `clear_existing_input_draft`、`send_with_guarded_clicks` 和
      `ensure_target_ready_for_send` 及其旧兼容测试。
    - 正式 sidecar 只保留 UIA 控件定位、物理输入、真实发送按钮和发送后
      气泡确认这一条路径。

## 本轮修复

1. **语音最终画面重新验会话**
   - 不增加截图。
   - 直接使用最后一条语音完成后的截图和 OCR，重新确认短码、标题及
     `private`。
   - 最终画面不是原会话时禁止复用，Worker 会走安全复核，不能把 B
     会话消息入到 A。

2. **Brain 超时可以真正终止**
   - 删除线程池外层超时。
   - 每次真实 Brain 调用运行在独立子进程中。
   - 超时后杀死整个子进程，未结束的 HTTP 请求不会继续占线程和重复计费。
   - 正常 Brain 调用仍返回 `send_reply`。

3. **Brain 配置只保留一套**
   - 正式配置为 Anthropic 兼容协议、Doubao 模型和 `/v1` 地址。
   - 删除 `.env.example` 中旧的 OpenAI/GPT 配置。
   - 密钥只由运行环境注入，不写入 Git、日志或报告。

4. **图片候选截图复用**
   - 先截取一张图片候选帧。
   - 同一张图同时用于会话确认和图片气泡重定位。
   - 不再“确认会话截一张，紧接着找图片又截一张”。

5. **图片菜单异常统一关闭**
   - 右键菜单打开后，无论菜单截图、复制项查找还是点击动作在哪一步异常，
     `finally` 都会执行安全关闭。
   - 不使用 `Esc`。

6. **Vision 失败证据保留 30 天**
   - 如果消息读取先成功、后续 Vision 失败，会把同一证据目录从
     `success` 提升为 `critical`。
   - 不保存图片原图，只提升现有全屏截图和结构化日志的保留级别。

7. **旧身份查询消除 N+1**
   - `read-targets` 先确定本轮最多 20 个目标，再用一次窗口查询取得每个
     会话最近 200 条过渡身份。
   - 继续返回带版本的 `identity_transition`。这是为了兼容“Worker
     先升级、后端后升级”的既定合同；在没有客户端完成回执前，不能擅自
     停止返回，否则会重新引入历史消息重复入库风险。

## 2026-07-24 最终审计收口

1. **后端强制按画面顺序处理**
   - Worker 仍负责生成最终画面的 `screen_order`。
   - 后端拒绝批内重复或非法顺序，并在入库和推动状态机前统一按
     `screen_order ASC` 排序。
   - 即使 JSON 数组被网络层或调用方打乱，也不会反转客户与销售消息的
     业务先后。

2. **旧 Outbox 只能补事实，不能倒退状态**
   - Worker 把取得授权时的 `authorization_read_reason` 固化在 V3
     evidence 中。
   - 后端重新读取当前授权原因；两者不一致时仍允许幂等补录合法事实，
     但返回 `state_transition_applied=false`。
   - 该请求不能创建 Brain 批次、不能创建 handoff，也不能把“销售已经
     回复”倒退成“AI 继续回复”。

3. **所有安全门禁带画面位置**
   - 历史断层、身份不确定和图片失败共用 `flow_gate_details`。
   - 只有门禁明确位于后续人工销售消息上方，才允许被该销售回复覆盖；
     位置未知或位于销售消息下方时继续阻断 Brain。

4. **Vision 可以真正响应停止监听**
   - 图片复制和菜单操作各步骤都检查取消状态。
   - 真实 Vision Provider 运行在可终止子进程中，停止监听时父进程会杀死
     子进程，不继续占用模型请求和 UI 锁。
   - 模型返回后再次通过轻量授权接口复核；授权已撤销的结果不写 ledger、
     不进 Outbox、不入库。
   - 图片仍只以 base64 管道进入子进程内存，不写图片文件。

5. **长动作改用轻量授权复核**
   - 新增单会话 `read-authorization` 端点，只返回允许状态、授权版本、
     `read_reason` 和监听状态。
   - 完整 `read-targets` 继续只负责发现和开始动作前准入，不再被长动作
     每秒下载历史身份清单。

## 额外发现

当前 C2 图片适配器曾调用一个已经不存在的旧会话确认函数。该问题不在原
审计清单中，但会让真实图片流程在确认阶段直接失败。现已改为调用唯一的
C2 标题/短码/private 门禁，并复用图片候选帧。

OmniAuto 中仍有一个不被车金严格适配器调用的通用旧 Vision 集成模块。
车金 C2 已通过严格门禁禁止该入口，完整测试确认不会从 C2 调用它。本轮
没有为了清理上游通用模块而改变车金业务流程。

正式包还发现一个独立 P0：源码环境通过 `python sidecar.py` 启动 OmniAuto，
但冻结后的 Windows EXE 如果沿用该命令，会把 `.py` 参数交给 Worker EXE
自身，sidecar 实际不会启动。现已为冻结包增加 `--omniauto-sidecar`
内部入口；源码继续使用 Python 文件入口，正式包使用同一个 Worker EXE
分派。构建后的 sidecar 启动预检会阻止该问题进入安装包。

## 2026-07-24 批次授权闭环收口

1. **`ai_active` 不再阻断当前批次**
   - 全局 `read-targets` 仍保持严格，不把所有 `ai_active` 会话重新开放。
   - 后端为当前 `message_batch` 签发 HMAC 批次续行票。
   - Worker 正常等待、发送前刷新和重启恢复共用这一张票。

2. **旧 Outbox 不能替换新 Brain**
   - 只有精确匹配当前 `batch_id + token + authorization_revision +
     read_reason` 的请求可以推动状态机。
   - 无票或旧票请求仍可补录合法事实，但
     `state_transition_applied=false`，不会创建新批次或 handoff。

3. **回复恢复有明确终态**
   - 重启后的 `chat_reply` 不再从全局 `read-targets` 猜目标。
   - 批次票有效则恢复原会话；无票、停用或过期则终结任务并创建
     handoff，不留下永久 `ai_active`。

4. **所有 `no_action` 出口恢复监听**
   - Brain 明确 `no_action`、业务门禁提前结束和空批次共用同一个状态恢复
     函数。

5. **顺序、文本和本地持久化统一**
   - Brain 历史按 `observed_at + observation_order` 排序，延迟入库不再按
     `ingested_at` 插到新消息后面。
   - 回复正文统一执行 Unicode 空白折叠，再计算 SHA-256；规则已写入
     `c2_contract_v3.json`。
   - 本地 Outbox 只清理过期的 `confirmed/abandoned`；`waiting/intent`
     永不被清理器删除。

6. **资源与泄露保护**
   - 续行 token 改放 `X-C2-Continuation-Token` 请求头，不进入 URL。
   - 消息正文、原始证据、批次条数和请求体均增加硬上限。

7. **召回来源与 Brain 非发送决定收口**
   - 会话进入 `recall_precheck` 前保存 `recall_origin_status`；召回返回
     `no_action` 时按 `waiting_user_reply / recalled_waiting_user /
     sales_replied_waiting_user` 原样恢复。
   - Brain 明确 `pause` 时创建人工接管事实、进入
     `waiting_sales_reply` 并关闭本会话自动回复，不再遗留
     `ai_active`。
   - 真实 OmniAuto Brain Adapter 显式映射 `no_action / pause /
     retry_later`，不再把合法非发送决定统一降级为合同错误。

8. **人工接管与 pause 闭环收口**
   - `handoff_event.closed_at IS NULL` 成为唯一人工接管门禁，不再仅凭
     `conversation.status` 或 `ai_enabled` 各自猜测。
   - 门禁期间客户消息照常入库并返回 HTTP 200，但不改变
     `waiting_sales_reply`，也不创建 Brain 批次。
   - 销售人工消息关闭对应 handoff，写入 `sales_replied + closed_at`；
     AI 自发消息不能解除人工接管。
   - pause 关闭后由销售实际回复恢复 `ai_enabled=true`，不存在永久 409
     或 Outbox 持续堵塞。
   - SQLite 使用显式外层事务；批次创建失败时，之前插入的消息随请求一起
     回滚，与 PostgreSQL 语义一致。

9. **无逐条时间时仍能安全识别真实销售回复**
   - 真实 OmniAuto 当前不生成逐条 `occurred_at`，后端不再因此永久保留
     handoff。
   - 同一最终画面中，稳定消息身份和 `screen_order` 是第一证据：销售
     消息必须位于 handoff 触发客户消息下方。即使时间字段显示较新，
     销售消息在触发消息上方时也不得解除 handoff。
   - 只有触发消息不在最终画面、无法比较上下顺序时，才允许使用来源明确、
     置信度足够的微信消息时间辅助判断；普通 `occurred_at`、扫描时间和
     入库时间都不能代替。
   - 触发消息不可见、身份不匹配或销售在上方时，顺序无法证明，继续保持
     人工接管；绝不退回使用扫描时间。

10. **C1 加好友共用 UI 锁取消门禁**
    - 加好友 `run_add_friend` 接收 Worker 停止和当前 lease 状态。
    - 停止 Worker 或 UI 锁续租失败时，父进程终止最长 360 秒的 sidecar，
      不允许与新取得锁的 C2 流程同时操作微信。

11. **P2 旧入口独立清理**
    - 删除四段无生产调用的旧辅助入口：
      `_messages_need_voice_transcribe`、`_run_c2_once`、
      `_compact_identity_text`、`_resolve_current_visible_target`。
    - 删除 `_wait_and_send_current_c3_batch` 未使用的 `locate_payload`
      参数及仅验证退役入口的旧测试。
    - 现行 C2 循环、首屏优先定位和统一语音候选函数保持不变。

12. **证据不足时禁止猜测**
    - OmniAuto 是会话身份、消息类型和同行头像角色的唯一事实来源。
      Worker 不再根据标题行号生成 `rpa_session_key`，也不再根据时长、
      内容或旧别名重新猜 `message_type/sender_role`。
    - 缺少真实 `rpa_session_key` 的侧栏行直接排除，并记录
      `missing_session_key_excluded_count`；不得点击、授权或读取。
    - 最终画面只有在所有消息槽位都有气泡坐标时，统一标记
      `order_source=visual_top`。缺少任一坐标时，整帧只能使用
      `observation_index_fallback`。
    - `observation_index_fallback` 只允许恢复普通消息数组顺序，不能证明
      “销售消息位于客户消息下方”，不能关闭 handoff、清除安全门禁或推动
      Brain。
    - 后端拒绝携带弱位置来源却声称具有 `min/max_screen_order` 的门禁，
     错误码为 `MESSAGE_FLOW_GATE_POSITION_SOURCE_UNTRUSTED`。

## 2026-07-24 任务并发与时间证据收口

1. **服务端任务租约正式落地**
   - `add_friend / chat_reply` 领取后由后端签发
     `worker_id + client_instance_id + fencing_token + lease_expires_at`。
   - Worker 默认每 15 秒续租；每次更新步骤、完成、失败和领取发送许可
     都必须携带当前 fencing token。
   - 旧客户端、旧进程或过期 token 不能继续改任务，也不能继续操作微信。
   - 租约过期后任务明确结束为 `TASK_LEASE_EXPIRED`，发送类动作绝不自动
     重放。

2. **任务线程不再抢 C2 的微信锁**
   - 拉任务和领取任务前后共用本地调度锁。
   - 真正向后端拉任务前再次检查 C2 是否已经取得 UI 锁；若已取得，任务
     留在后端队列等待，不会先领成 `running` 再因为 20 秒抢不到锁而失败。

3. **人工销售回复以最终画面为主**
   - 同一最终画面能比较时，稳定身份和上下顺序拥有最高优先级。
   - “销售在客户触发消息上方”永远不能解除新 handoff，即使普通
     `occurred_at` 看起来较新。
   - 只有画面无法比较时，才允许使用明确来自微信消息时间且置信度不低于
     合同要求的时间证据。

4. **历史消息不能倒退会话时间**
   - `last_inbound_at / last_outbound_at / last_sales_reply_at` 更新时，
     统一取“数据库已有值”和“本次消息值”中的较新者。
   - 延迟发现的历史消息照常补录事实，但不能让召回和客户回复判断回到
     更早时间。

5. **C1 与 C2 取消原因分开**
   - Sidecar 取消回调可以返回明确错误码。
   - C1 加好友因 Worker 停止、任务租约丢失或 UI 锁丢失时，分别保留真实
     原因；不再统一伪装成 `C2_TARGET_NOT_ALLOWED_BY_READ_TARGETS`。

6. **消息请求体按数据流实时限流**
   - `/wechat/messages/ingest` 不再只相信 `Content-Length`。
   - 即使请求不带该请求头或故意写小，ASGI 接收每个数据块时都会累计
     大小；超过上限立即返回 413，不再先把完整超大请求读进内存。

7. **C2 领取回复任务后心跳保持忙碌**
   - C2 在原会话领取 `chat_reply` 后立即设置 `current_task`，租约有效期间
     心跳上报 `running + task_id`。
   - 回复结束、失败或取消统一在 `finally` 清理任务、租约和任务展示状态，
     不会出现“任务仍在发送，但监控显示 idle”。

8. **任务领取改为数据库原子操作**
   - `claim_task()` 使用 `SELECT ... FOR UPDATE` 锁住任务行，再判断
     `pending` 并签发租约。
   - 两个请求同时领取时，只允许先取得行锁的一方成功；后一方等待后看到
     `running`，返回 `TASK_CLAIM_NOT_ALLOWED`。
   - 已增加 SQL 行锁合同测试和 PostgreSQL 并发测试；本机 SQLite 跳过
     PostgreSQL 专项，正式服务器数据库环境执行。

9. **未执行 Vision 的图片不再伪装成失败**
   - 历史断层或身份冲突时仍然不右键、不复制、不调用 Vision，并继续阻断
     Brain。
   - 这类图片只记为本轮 `deferred`，不写本地图片终态，也不上报
     `image/failed`。
   - 门禁后续消失时，同一图片仍可按稳定身份正常处理一次。只有真实调用
     Vision 后发生超时、模型错误或结果非法，才写永久 `failed`。

## Windows 必测

1. 客户文字、语音、图片混合上报，顺序与微信从上到下一致。
2. 转写期间切换会话时，最终帧不得复用、不得串会话入库。
3. 图片只截取一次候选帧做确认和定位，只右键/复制/Vision 一次。
4. 图片复制点击失败时右键菜单必须关闭，文字和语音仍能收口。
5. 分别在微信“Enter 发送”和“Ctrl+Enter 发送”设置下验证，程序都只点击
   真实发送按钮，且只发送一次。
6. 输入框已有销售人工草稿时，必须原样保留并停止自动回复。
7. 在开始输入前、输入过程中分别停止监听，均不得继续发送。
8. 输入过程中抢走焦点，必须停止且不得误报 `sent`。
9. 点击发送后只有输入框清空、但没有新增同文右侧气泡时，不得回报
   `sent`。
10. AI 发送成功后重新扫描，右侧气泡应为 `self + ai`；销售人工发送同文
    消息时仍应为 `self + human`。
11. 失败图片后已有销售人工回复时，不得重新触发旧图片转人工门禁。
12. 发送结果未知或客户端崩溃后，不得再次物理发送同一回复。
13. 在 100%、125%、150% DPI 和不同窗口尺寸下验证 UIA 能找到真实输入框
    和发送按钮；找不到时必须安全失败。
14. Brain 正常回复由当前 C2 会话流程领取并发送。
15. 停止监听后不再定位、转写、识图、入库或发送。
