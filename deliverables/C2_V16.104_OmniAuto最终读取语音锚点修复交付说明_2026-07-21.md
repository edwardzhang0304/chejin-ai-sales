# C2 V16.104 OmniAuto 最终读取语音锚点修复交付说明

## 结论

V16.104 直接修复 OmniAuto 公共消息解析底层，不放宽 V16.103 的 Worker/后端 V3 严格门禁。Windows 真实失败包已完成结构化重放，最新安装包已完成 Windows 真实微信回归；V16.104 可作为当前 C2 文字/语音基线。

## 已证明根因

V16.103 实机中，23 秒和 5 秒语音都已成功展开。语音动作的临时 `transcribed_messages` 带有稳定锚点，但同一画面在最终消息读取中重新解析后，两条 `messages` 均丢失：

```text
parent_voice_anchor_key
voice_anchor_stable_key
voice_anchor_key
```

因此唯一 observation 合同确定输出：

```text
OBSERVATION_REQUIRED_FIELD_MISSING:parent_voice_anchor_key
OBSERVATION_ROLE_SOURCE_INVALID
```

Worker 在 `c2_final_sidecar_contract_invalid` 门禁处整批阻断，未调用 `messages/ingest`。

## 底层修复

1. OmniAuto 原始 `parse_messages_from_ocr()` 在组合出“语音时长气泡 + 下方转写正文”后，立即为记录生成父语音锚点。
2. 语音动作、最终消息读取和重复读取共用同一 `voice_structural_anchor_key()`，删除结构锚点的重复生成规则。
3. 同侧、同时长的多条语音使用从下往上的相对序号区分。绝对 y 坐标不进入锚点身份，页面整体位移不会改变锚点。
4. 语音转写正文的 `sender_role_source` 仍强制为 `parent_voice`；父锚点或同行头像事实缺失时仍整批阻断。

## 不变范围

- 不新增点击、截图、OCR 或滚动。
- 不修改语音自下往上的物理操作顺序。
- 不放宽 Worker 和后端 V3 合同。
- 不接入 Vision，不恢复旧图片入口。
- 不使用被转写文字顶出当前屏幕的语音诊断列表制造消息。

## Windows 实机结论

以下项目已使用 V16.104 最新安装包完成回归，结论通过：

1. 当前屏幕同时放置两条 customer 语音，包含一条多行长语音。
2. 确认两条都只转写一次，不重复右键、不点头像、不滚动。
3. 最终 Worker 必须调用 `messages/ingest`，两条都以 `customer + voice + completed` 入库。
4. 新增一条 self 语音，确认同行右头像角色继承为 `self`。
5. 两条同侧、同时长语音必须生成两个不同锚点，页面轻微位移后不得重复入库。
6. 停止监听后不得新增定向读取、语音转写或入库。
