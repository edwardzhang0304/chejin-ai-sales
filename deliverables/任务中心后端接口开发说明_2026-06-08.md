# 任务中心后端接口开发说明

日期：2026-06-08
提交人：后端负责人

## 1. 结论

本次后端已完成任务中心相关接口、统一任务表和 P1a add_friend 任务状态流转开发，并已完成本地单测、迁移验证和 Docker 容器接口 smoke。

字段口径以技术方案 v0.4 为准。任务中心接口不得继续新增同义字段、兜底字段或临时兼容字段。

## 2. 本次完成范围

- 统一任务表：`tasks`
- 任务事件表：`task_events`
- 任务备注表：`task_notes`
- 任务列表查询，支持任务类型、状态、业务结果、异常原因、阻塞原因、销售、Worker、时间和关键词筛选
- 任务详情，返回基础信息、业务对象、执行信息、事件流、备注和可用操作
- 任务事件查询
- 任务备注追加
- 任务取消：仅 `blocked / pending / running` 可取消
- 任务重试：仅 `failed / cancelled` 可重试，创建新任务并记录 `original_task_id`
- 任务领取、步骤更新、完成、失败状态流转
- 线索成功分配销售后自动创建 `task_type=add_friend` 任务
- 销售未绑定可用 Worker 时任务进入 `blocked + block_code=SALES_WORKER_NOT_BOUND`
- 销售绑定可用 Worker 后，该销售名下 `SALES_WORKER_NOT_BOUND` 阻塞任务恢复为 `pending`
- 关键动作写入 `task_events` 和操作日志

## 3. 不包含范围

- Worker 新增、编辑、启停、重置绑定接口重做
- 销售 Worker 绑定接口契约重做
- 微信 / RPA 自动执行
- AI 回复
- 飞书通知
- 召回任务配置
- chat_reply / follow_up 真实任务创建和状态机

## 5. 状态口径

- `task.status` 只允许：`blocked / pending / running / completed / failed / cancelled`
- `invite_sent` 只写入 `task.result_code`，不允许作为 `task.status`
- `result_code / error_code / block_code` 独立存储，不混用
- 任务事件流统一使用 `events`，不得继续返回或读取 `status_flow`
- 执行方状态从 `execution.worker` 计算展示，不得新增 `executor_status`
- 任务详情里的线索状态从 `business_object.lead.status` 读取，不得新增 `lead_status`
- 当前 `POST /api/tasks` 仅支持 `task_type=add_friend`，传 `chat_reply / follow_up` 会返回 `TASK_TYPE_NOT_SUPPORTED`

## 8. 已知问题 / 待确认

- 当前正式鉴权仍未接入，继续使用 Header 模拟操作人。
- P1a 仅实现 `add_friend`，`chat_reply / follow_up` 只在表结构上预留。
- 任务领取接口当前按 `worker_id` 入参校验 Worker 是否启用，未接入 Worker Token 鉴权；真实 Worker 客户端接入时需补 token 鉴权【待确认】。
- 任务失败错误码枚举未最终产品化，当前按前端/Worker 上报的 `error_code` 透传保存【待确认】。
- 线索分配自动创建任务已接入现有分配流程；如后续产品要求任务只由独立调度器创建，需要调整创建入口【待确认】。
