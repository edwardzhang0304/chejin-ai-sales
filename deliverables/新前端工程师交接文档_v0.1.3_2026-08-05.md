## 3. 当前工程是什么样

### 3.1 正式前端

正式工程只有：

```text
frontend/
```

技术栈：

- React 19。
- TypeScript 严格模式。
- Vite 6。
- 原生 CSS，集中在 `frontend/src/styles/global.css`。
- 没有 React Router、组件库或全局状态库。
- 模块切换当前由 `frontend/src/App.tsx` 的本地状态控制。
- API 返回统一使用 `{ code, message, data, trace_id }`。

现有模块按功能分目录：

```text
frontend/src/features/leads
frontend/src/features/sales
frontend/src/features/workers
frontend/src/features/tasks
frontend/src/features/logs
```

车辆模块应继续使用同一结构，不要另起第二个前端工程：

```text
frontend/src/features/vehicles/
  api.ts
  types.ts
  VehiclesPage.tsx
  components/
    CreateVehicleModal.tsx
    VehicleDetailDrawer.tsx
    VehicleImageManager.tsx
    VehicleImportModal.tsx
```

组件名可以按实际职责微调，但 API、类型、页面和复杂弹层必须分开，不能把整个车辆模块
堆进一个超长组件。

### 3.2 视觉基准

现有运营后台视觉基准是：

```text
website/ops-admin.html
website/ops-admin.css
website/ops-admin.js
```

它是视觉和交互参考，不是正式代码来源。`20260804b` 版本已经包含车辆管理列表、详情抽屉、
新增、编辑、图片管理、上下架、异常状态和 Excel 三步导入设计。因此：

- 车辆功能可以直接在正式 React 工程中开发。
- 布局、表格、抽屉、弹窗、按钮、提示和间距沿用现有运营后台风格。
- 车辆页面必须以 `http://127.0.0.1:8790/website/ops-admin.html?v=20260804b` 为视觉与交互基准逐状态验收。
- 设计稿未覆盖或与正式接口冲突的内容必须标注并由产品/UI确认，不能由开发随意发挥。
- 禁止先补一套车辆静态 HTML，再另写一套 React 页面。

### 3.3 当前前端状态与缺口

当前未提交工作区已经包含 `frontend/src/features/vehicles/`、车辆导航、共享 UI 和文件
请求封装，客户端工程师已报告生产构建、前端测试和车辆接口专项通过。这证明车辆展示层
和自动化实现已经存在，不等于代码已经合并或完成独立测试库的真实写入验收。

当前明确缺口是正式登录页、Cookie 会话接入、退出和失效处理，以及旧 Bearer Token、
`role/viewer/readOnly` 权限分支清理；车辆侧还需完成干净提交、真实后端联调和独立测试库
写入验收。不得从零重写已有车辆页面，也不得把未提交工作区描述为主分支已完成能力。

## 6. API 接入时最容易踩的坑

### 6.1 JSON、文件和下载不是同一种请求

`frontend/src/shared/api/client.ts` 当前 `request()` 默认发送 JSON，并固定设置
`Content-Type: application/json`。它不能直接用于以下请求：

- 图片多文件上传。
- Excel 文件预览。
- Excel 模板下载。
- 车辆图片读取。

这些请求应复用 `buildUrl()`、`buildOperatorHeaders()` 和 `apiErrorFromResponse()`，但使用
原生 `fetch`：

- 上传使用 `FormData`，不要手写 `Content-Type`，让浏览器生成 multipart boundary。
- 下载和图片使用 `response.blob()`。
- 所有请求仍必须带现有鉴权和操作人 Header。

### 6.2 受保护图片不能直接拼 `<img src>`

车辆图片接口受后台鉴权保护，普通 `<img src="/api/...">` 无法附带现有 Authorization
Header。正确方式是：

```text
带鉴权 fetch 图片
→ response.blob()
→ URL.createObjectURL(blob)
→ 绑定到 img
→ 图片替换、抽屉关闭或组件卸载时 URL.revokeObjectURL()
```

不得把 Token 放到图片 URL 查询参数中。

### 6.3 不做乐观上架

上架由服务端最终校验展示名称、公开售价和有效图片。页面可以提前列缺失项，但必须以
服务端响应为准；不能先把列表改成“已上架”再等待接口。

### 6.4 图片上传允许部分成功

多图上传返回逐文件结果：成功图片保留，失败图片显示文件名和错误原因。不能因为一张
失败把全部成功结果从页面移除。

### 6.5 Excel 预览不是正式写入

完整状态必须按三步维护：

```text
上传文件
→ preview 返回 preview_id、统计、rows 和 can_confirm
→ can_confirm=true 后人工确认
→ confirm 成功才刷新正式车辆列表
```

预览存在任何错误时，确认按钮必须禁用。不要在浏览器自行解析 Excel 并替代服务端校验。

## 7. 车辆页面固定行为

### 7.1 列表

- 左侧导航新增“车辆管理”。
- 顶部提供新增车辆、导入车辆、状态分段筛选和搜索。
- 搜索范围由后端统一处理：展示名称、车辆编号、品牌、车系等。
- 表格无“操作”列，点击整行打开右侧详情抽屉。
- 没有数据时展示空状态，并保留新增和导入入口。
- 新增、编辑、图片变化、上下架或导入成功后刷新列表。

### 7.2 新增和详情

- 新增使用居中弹窗，只要求车辆展示名称。
- 服务端生成车辆编号，新车默认已下架。
- 新增成功后关闭弹窗并自动打开新车辆详情抽屉。
- 详情使用右侧抽屉；点击“编辑车辆”后在原抽屉切换编辑态。
- 车辆编号、创建时间、更新时间只读。
- 编辑后未保存就关闭抽屉，必须二次确认是否放弃。

### 7.3 字段分区

客户可用资料：展示名称、图片、品牌、车系、车型、公开售价、首次上牌、表显里程、
内外饰颜色、所在地、车辆描述。

仅内部可见资料：车辆编号、VIN、车牌号、采购价格、内部备注、上下架状态和系统时间。

“内部可见”是数据安全边界，不只是页面分组样式。前端不得把这些字段复制到任何客户
回复预览、对客证据或客户侧组件中。

### 7.4 图片

- 创建车辆后才能上传图片。
- 支持 JPEG、PNG、WebP；单张不超过 10MB；支持一次多选。
- 支持大图查看、删除和拖动排序。
- 第一张自动为主图，不增加“设为主图”按钮。
- 排序接口必须提交该车辆全部图片 ID，不能只提交移动的一张。
- 已上架车辆不能删除最后一张图片。

### 7.5 上下架

- 状态只有“已上架 / 已下架”。
- 列表不放快捷开关，避免误操作。
- 资料不全时直接列出缺失项，不打开确认弹窗。
- 资料齐全后，上架和下架均需二次确认；下架不要求填写原因。

### 7.6 Excel

- 下载系统最新模板。
- 只接受 `.xlsx`，最大 8MB，最多 2000 行。
- 车辆编号留空表示新增并由系统生成；已存在编号表示更新；填写了不存在的编号必须报错，不得转为新增。
- 预览显示总数、新增数、更新数、错误数和逐条错误。
- 有任意错误时禁止确认，不提供“跳过错误继续”。
- 确认失败必须明确提示“本次未写入任何数据”和错误编号。
- 第一期不做独立导入历史页面。

## 8. 登录与权限

- 第一期只做指定账号的账号密码登录。
- 接口固定为 `POST /auth/login`、`GET /auth/session`、`POST /auth/logout`，统一由
  `VITE_API_BASE_URL` 补 `/api` 前缀。
- 所有登录成功账号均可查看和操作全部后台模块；删除 `admin/operator/viewer/sales`
  权限集合、车辆只读分支和 `AuthSession.role`。
- 未登录用户不展示后台页面，所有业务接口也必须由后端拒绝。
- 会话失效或接口返回 401 时返回登录页并提示重新登录；退出后清空页面状态，浏览器
  后退不能重新看到后台数据。
- 账号创建、停用和密码重置由服务端或实施工具处理，本期不做账号管理页。
- 不得误删微信消息的 `sender_role / sender_role_source / subject_sender_role`，这些
  是消息身份字段，不是后台账号权限。

## 9. 第一期明确不做

- 车辆删除。
- 批量上下架或批量删除。
- Excel 导入图片。
- 外部车源自动同步。
- 独立知识规则页面。
- AI 自动生成车辆资料。
- 独立导入历史页面。
- 客户看车商城或车辆展示站。

看到以上需求时先回产品确认，不要顺手实现。

1. 接入登录、查询会话和退出接口，统一请求携带 Cookie。

3. 增加 `vehicles` 类型、API 封装和 API 单元测试。
4. 在 `App.tsx` 接入车辆导航和 `VehiclesPage`，同步更新旧阶段文案。
5. 完成列表、筛选、搜索、分页、加载态、空态和错误态。
6. 完成新增、详情编辑、图片、上下架和 Excel 三步导入。
7. 完成登录审计和车辆操作日志联调。
8. 跑自动化、固定视口浏览器验收和真实后端联调。
