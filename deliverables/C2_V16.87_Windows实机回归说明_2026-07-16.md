## 二、本次根因与修复

V16.86 实机中两条语音已正确转写，但首屏命中队列只带了“会话在哪里”，没有带后端 `read-targets` 下发的 `authorization_revision`。V3 ingest 因此两次返回 `409 MESSAGE_AUTHORIZATION_REVISION_EXPIRED`。

V16.87 改为：

```text
首屏 scan-result：只提供当前可见会话和点击位置
read-targets：唯一提供当前读取授权和 authorization_revision
Worker：按 conversation_id + remark_code 合并两者后才允许读取
```

同时增加两道阻断：

- 没有当前 `read-targets` 或没有授权版本，不定位、不读取、不操作微信。
- V3 payload 缺少授权版本时在 Worker 内部终止，不向后端发送无效请求。
- 执行中授权版本发生变化时，当前旧任务立即取消。

## 三、本轮重点测试

1. 准备一条全新 customer 语音和一条全新 self/sales 语音。
2. 确认两条都真实转写，左侧为 `customer + voice`，右侧为 `self + voice`。
3. 确认 `messages/ingest` 返回 200，不再出现 `MESSAGE_AUTHORIZATION_REVISION_EXPIRED`。
4. 确认 V3 事件的 `authorization_revision` 非空，且与当轮 `read-targets` 一致。
5. 监听过程中点击停止，旧任务不得继续定位、转写或入库。
6. 继续观察 V16.86 已有口径：不重复右键、不点头像、不用 Esc、不滚动追屏外语音。

## 四、通过标准

- 两条新语音均生成 V3 voice 事件，角色、正文和 anchor 一致。
- `messages/ingest` 不得返回 409。
- 不得出现空 `authorization_revision`。
- 同一条语音不得同时产生 text 和 voice，不得跨轮重复入库。
- 停止监听后该目标无新定位、读取、转写和入库；常驻首屏扫描仍允许继续。

## 五、Windows 启动命令

以下命令可整段粘贴到 PowerShell：

```powershell
cd $env:USERPROFILE\Desktop
Expand-Archive -Force .\chejin-worker-client-20260716-v16.87.zip .\chejin-worker-client-20260716-v16.87
cd .\chejin-worker-client-20260716-v16.87\worker-client
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:CHEJIN_API_BASE_URL="http://172.16.9.116:8000/api"
$env:CHEJIN_RPA_MODE="real"
$env:CHEJIN_C2_VOICE_TRANSCRIBE_MAX_DURATION_SECONDS="240"
.\.venv\Scripts\python.exe -m chejin_worker_client.main
```
