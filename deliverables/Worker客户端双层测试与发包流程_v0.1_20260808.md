# Worker 客户端双层测试与发包流程 v0.1

日期：2026-08-08

## 1. 固定结论

Worker 普通功能修复不再每次构建正式 EXE。固定流程如下：

```text
本地自动化通过
→ 构建 Windows 快速调试 ZIP
→ Windows 实机执行 C0—C4 和专项回归
→ 有普通功能问题时更新快速调试 ZIP
→ 全流程稳定通过
→ 人工批准并统一构建一次正式 EXE
→ 正式 EXE 最终回归
```

快速调试 ZIP 仅用于 DEBUG/UAT，不得发给正式客户。只有 PyInstaller、安装包依赖、
正式凭据嵌入等打包专属问题，才允许直接修复并重新构建正式 EXE。

## 2. 本地自动化门禁

- 保留已审计的原 607 项 Worker 测试，不因数量或耗时直接删除。
- 补充绑定真实状态行为测试：已有绑定启动、绑定成功切页、初始状态与状态事件乱序、
  页面实际离开绑定页。
- `run_checks.py` 同时执行 Python 行为测试和无 Qt 依赖的真实运行桥事件测试。
- 悬浮球和键鼠锁零残留、状态机、幂等、图片、语音、Vision、发送安全、
  ActionJournal、Outbox、故障证据和打包安全测试继续作为强制门禁。

测试债务只登记，不在本轮通过删测试处理：

- 下一次删除旧 PySide UI 时，按受影响范围同步删除约 9 项旧界面测试。
- 将约 20～30 项源码字符串测试逐步替换为真实行为测试。
- 将约 11 项依赖真实等待的慢测试替换为可控时钟或事件同步。

## 3. Windows 快速调试 ZIP

快速调试 ZIP 包含固定的便携 Python 3.12.10 运行环境和全部依赖。Windows 测试机
不需要安装 Python，也不需要手工配置 Vision 环境变量。

运行底座按 `requirements.txt` 哈希缓存；普通功能修复只重新覆盖以下内容：

- Worker 业务代码；
- 同源 OmniAuto 客户端代码；
- Worker Web UI 生成资源；
- 固定 Vision Provider、地址、模型、请求格式及由 CI Secret 注入的专用凭据；
- 必要合同和启动配置。

快速调试 ZIP 与正式包使用 `%LOCALAPPDATA%\CheJinWorker` 数据目录，因此可直接复用
已保存的 Worker 绑定和运行状态。它必须在公开清单中明确记录：

- Worker 版本；
- 车金完整 Git 提交；
- OmniAuto 完整来源和代码树哈希；
- `debug_uat=true`；
- `formal_release=false`；
- `not_for_customer_release=true`。

公开清单、预检报告和日志不得包含 Vision Key。包内凭据仅供与正式包一致的 UAT
运行验证，不改变“低权限、限额、可吊销轮换”的既定安全边界。

## 4. 快速 ZIP 实机范围

至少验证：

- 已有绑定启动后直接进入工作台；
- 新绑定成功后立即进入工作台；
- 开始接单、暂停接单；
- C0—C4；
- 文字、语音、图片、Vision、Brain、发送和证据导出；
- 重启后绑定、页面和数据目录恢复正确。

发现普通功能问题时继续迭代快速 ZIP，不升级正式客户版本，也不构建正式 EXE。

## 5. 正式 EXE 门禁

正式 EXE 工作流只允许人工触发，并必须填写“C0—C4 快速 UAT 已通过”的验收记录。
除完整业务回归外，正式 EXE 仍需单独验证：

- PyInstaller 依赖收集；
- Vision Key 和锁定配置；
- OCR/Vision 独立子进程；
- 中文路径和不同盘符；
- PowerShell 5.1 启动脚本解析；
- 启动探针；
- 来源清单和文件哈希；
- 启动及运行故障证据。

正式 EXE 最终回归通过后，才可作为客户候选版本交付。
