manifest，不得沿用旧版本号或旧 SHA。

## 3. 命名和递增规则

正式包统一命名：

```text
chejin-worker-client-YYYYMMDD-vRELEASE_TAG.zip
```

`RELEASE_TAG` 沿用现有打包规则：内部版本 `16.130.0` 对应文件标签 `v16.130`；
manifest 必须保存完整内部版本，不能只靠文件名反推。

- 代码、依赖、内嵌 OmniAuto、合同、打包清单或运行资源发生任何变化，都必须递增
  版本。
- 同一版本号不得对应两个不同 SHA；测试后修改代码必须再发新版本。
- 纯文档修改且不重新发包，不递增客户端版本。
- 后续候选版本必须高于 `16.132.0`。

## 4. 正式构建门禁

构建正式包前必须满足：

1. 从唯一 Git commit 构建，工作区 `git_dirty=false`。
2. `python3 worker-client/run_checks.py` 通过，且不得靠新增永久 skip 变绿。
3. 后端 C2/C3 合同和 API 回归通过。
4. 机器合同、canonical SHA、生成 observation schema 与后端一致。
5. 内嵌 OmniAuto 来源提交和完整目录 tree SHA 动态计算并写入 manifest。
6. ZIP 内不得包含 `.git`、`.env`、Token、API Key、原始客户图片、运行日志、
   SQLite、`__pycache__`、`.pytest_cache` 或开发产物。
7. manifest 校验 ZIP 文件数、字节数、SHA、顶层目录、禁止项和预检结果。

## 5. 双仓来源规则

- `v16.130.0` 的历史来源是 OmniAuto `855c218` 基础、`2318bd8` 选择性接入和
  `ff9e0de` 车金首次集成；必须原样保留用于审计。
- 双仓统一已经完成，`.chejin-source.json` 使用 schema v3：活动
  `upstream_base_commit=35b0eee`、`selective_integrations=[]`；旧
  `855c218 + 2318bd8 + ff9e0de` 放入只读 `historical_integrations`。manifest
  必须记录审核后的固定提交 `35b0eee`，不得只写 `master`、分支名或“最新版本”。
- OmniAuto 通用代码先进入独立 OmniAuto PR；车金只引用固定提交并保留 Worker/后端
  适配。禁止从车金目录反向覆盖独立仓库。

## 6. 产物保存规则

- 活跃 Git 工作区不长期保存 ZIP 和 manifest；正式产物应上传到发布存储或随
  GitHub Release/CI artifact 保存。
- 仓库只保留技术方案、版本规则、验收报告以及足以定位发布物的 commit 和 SHA。
- 测试人员只安装明确标注版本和 SHA 的包；不得使用聊天中同名文件或本地手改包。
- 旧包需保留时放到仓库外只读归档，并设置保留期；不得重新解压后继续开发。

## 7. Windows 故障证据

要求用户或测试提供日志时，工程师必须在同一条消息给出一段可直接复制执行的完整
PowerShell 命令。命令必须：

- 明确本次问题的开始、结束时间；
- 自动收集该时段 Worker 脱敏日志、Sidecar JSON、review、动作日志和必要截图；
- 生成一个可直接发送的证据 ZIP 并显示路径；
- 排除原始 SQLite、Token、Vision/Brain Key、`.env` 和客户原始图片；
- 记录客户端版本、Git commit、Worker/Client Instance、合同 revision、flow/run/
  trace ID，确保不盯现场也能串起一次故障。

## 8. 回滚规则

1. 停止新任务和发送，不把未知发送结果当失败重发。
2. 保留故障证据和当前 Outbox/ledger，不人工删除业务事实。
3. 卸载或停止故障候选版，恢复已验收 `v16.130.0`。
4. 校验恢复包 SHA256 与本文件一致后再启动。
5. 缺陷在源码分支修复并发布新版本；禁止直接修改测试电脑安装目录。
