# 车金 Worker 客户端版本管理文档

更新时间：2026-08-02

## 结论

后续所有 Worker 客户端源码包统一使用以下命名规则：

```text
chejin-worker-client-[日期]-v[版本号].zip
```

示例：

```text
chejin-worker-client-20260618-v12.zip
```

不再使用以下非标准命名：

```text
chejin-worker-client-formal-ui-source-20260618-v9.zip
chejin-worker-client-formal-ui-source-20260618-v5-omniauto-speedfix.zip
chejin-worker-client-formal-ui-source-20260618-v5.1.zip
```

## 前端/客户端排障协作硬约束

任何工程师、审计人员或 AI 助手要求用户提供 Windows 客户端日志时，必须在同一条消息中直接给出可整段复制执行的完整 PowerShell 命令，不得只说“请提供日志”后再让用户追问命令。

命令必须满足：

- 明确写入本次排查的开始时间和结束时间，禁止无时间范围地导出全部历史数据。
- 自动收集该时间段内的 Worker 脱敏日志、Sidecar JSON、review 文件、动作日志和截图。
- 自动生成一个可直接发送的 ZIP，并明确显示 ZIP 输出路径。
- 禁止打包原始 SQLite、Worker Token、Vision/Brain API Key、`.env` 或其他秘密。
- 命令必须适配当前正式客户端目录，不得要求用户自行拼接路径、文件名或筛选条件。
- 如果已有“导出最近一次故障证据”可以覆盖本次问题，也仍须提供对应的命令行导出方式。

## 命名规则

| 字段 | 规则 | 示例 |
|---|---|---|
| 固定前缀 | 必须为 `chejin-worker-client` | `chejin-worker-client` |
| 日期 | 打包日期，格式 `YYYYMMDD` | `20260618` |
| 版本号 | 正式递增使用 `v数字`；已发版本的小范围候选修订可使用 `v数字.数字` | `v12` / `v15.1` |
| 后缀 | 固定 `.zip` | `.zip` |

完整格式：

```text
chejin-worker-client-YYYYMMDD-vN.zip
chejin-worker-client-YYYYMMDD-vN.N.zip
```

## 版本递增规则

每次重新交付给 Windows 实机测试、测试工程师或架构师验收，都必须递增版本号。

以下情况必须递增版本：

| 场景 | 是否递增 | 说明 |
|---|---:|---|
| 客户端 UI 改动 | 是 | 包括窗口、任务链路、截图预览、滚动条、设置页等 |
| Worker 接口/任务模型改动 | 是 | 包括 pull 字段、步骤上报、结果上报 |
| OmniAuto RPA 代码改动并重新打进客户端包 | 是 | 即使客户端 UI 没变，也必须递增 |
| 依赖或打包清单变化 | 是 | 包括 requirements、PyInstaller、内置资源 |
| 只改文档，不重新发客户端包 | 否 | 文档版本单独管理 |
| 只在本地临时调试，未交付测试 | 否 | 不形成正式包 |

同一天已有 `v12`，下一次客户端交付包就是：

```text
chejin-worker-client-20260618-v13.zip
```

跨天后版本号是否延续，由项目统一口径决定；当前建议继续全局递增，避免 `v1` 重复造成混淆。

## 出厂状态与本地绑定缓存红线

Worker 客户端安装包出厂状态必须满足：

```text
未绑定
无 Worker Token
无 worker_id
无 client_instance_id
```

首次启动规则：

```text
首次启动必须展示绑定页。
用户输入 Worker ID / Worker Token 后，才允许在本机本地保存绑定信息。
退出重启后，可以从本机缓存恢复绑定状态。
```

重新发包红线：

```text
重新打包或重新交付测试包时，绝不能带入当前开发机、测试机或任意真实机器的本地绑定缓存。
正式包不得包含 runtime、local storage、SQLite 本机数据、client_instance_id、worker_id、Worker Token 或任何机器级缓存。
```

后续每次发包和测试准入都必须检查该项。若发现安装包内带机器缓存、Token 或绑定状态，直接判定为发包不合格，需要重新清包并递增版本重新交付。

## 2026-06-24 v0.6 口径修订

结论：v16.1 中关于“主动扫描 + 补偿扫描 + 去重入库”的旧描述已废弃。当前 C2/C3/C4 统一按技术方案 v0.6 和测试口径调整说明执行：

```text
C2 = 第一屏主动扫描 + 第一屏命中优先读取 + 状态机定向读取 + 去重入库
C3 = 发送前必须 pre_send_refresh，客户有新消息时旧 reply_action=superseded，不发送旧回复
C4 = 召回到期先 recall_precheck，读取微信事实后再决定是否 follow_up
watching 不作为主状态
```

以下内容不再作为当前版本开发、测试或验收依据：多屏滚动补偿扫描、第二屏/第三屏滚动扫描、sessions compensation、滚动页数、滚动到底判断、滚动恢复位置、补偿扫描任务、补偿扫描验收项。
