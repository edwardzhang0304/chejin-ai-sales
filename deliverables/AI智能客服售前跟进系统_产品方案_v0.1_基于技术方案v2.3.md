# AI智能客服售前跟进系统 产品方案

版本：v0.1

依据文档：AI智能客服售前跟进系统_技术方案手册_v2.3_详细设计全量版

日期：2026-05-26

文档定位：基于技术方案 v2.3 输出的产品方案初稿，用于业务确认、研发拆解、页面设计和验收对齐。本文中标注“待确认”的内容，需要项目方确认后才能进入冻结版 PRD。

## 1. 一句话结论

本产品一期可以做，但要按“线索加微 + AI 售前回复 + 风险转人工 + 低频召回”的闭环交付，不做通用客服机器人、完整 CRM、复杂销售管理和 SaaS 化平台。

## 2. 需求背景

当前二手车销售线索主要来自抖音小风车、线索表单、广告投放或人工导入。客户留下手机号后，需要销售及时加微信、跟进咨询、推荐车源、处理价格/车况/金融等问题。

现有方式通常依赖人工逐条处理，存在以下问题：

- 销售跟进不及时，线索热度下降。
- 客户咨询高峰时，销售回复压力大。
- 普通咨询重复度高，人工处理效率低。
- 涉及底价、车况承诺、金融、合同等问题时，错误回复风险高。
- 线索是否已加微信、是否已回复、是否转人工、是否召回缺少统一记录。

本系统的核心价值不是替代销售成交，而是在售前早期帮助销售完成基础跟进，在不确定或高风险场景下及时停手并通知销售接管。

## 3. 用户与场景

### 3.1 目标用户

| 用户角色 | 核心诉求 | 使用系统的方式 |
|---|---|---|
| 项目管理员/运营 | 管理线索、销售、Worker、风控、任务和异常 | 使用云端后台 |
| 销售人员 | 接收高意向或高风险客户，人工继续跟进 | 使用手机微信和飞书 |
| 技术/运维人员 | 查看 Worker 状态、失败原因、接口状态和系统日志 | 使用云端后台和 Worker 执行台 |
| 客户 | 在微信里获得基础售前咨询回复 | 不直接使用系统 |

### 3.2 核心业务场景

1. 新线索进入系统，系统分配给销售并创建加好友任务。
2. Worker 在商家侧电脑微信上搜索手机号并发送好友申请。
3. 客户通过好友后，系统绑定微信会话并开启 AI 跟进。
4. 客户发送文字或图片咨询，AI 根据知识库、车源和风控规则生成候选回复。
5. 系统通过 Guard 校验后，由 Worker 发送微信回复。
6. 客户触发底价、事故、泡水、金融、合同、投诉等风险问题时，AI 停止并通过飞书通知销售。
7. 销售手机端人工回复后，该客户进入人工接管状态，AI 不再自动回复或召回。
8. 客户进入观望状态且长期未互动时，系统按规则创建低频召回任务。

## 4. 产品目标

### 4.1 业务目标

- 提升新线索首次微信触达效率。
- 降低销售处理重复售前问题的时间成本。
- 对高风险、高意向和 AI 不确定场景及时转人工。
- 保证系统在断网、重启、失败恢复时不重复发送微信消息。
- 让项目方能看到每条线索、任务、回复、失败和接管原因。

### 4.2 成功指标

| 指标 | 建议口径 | 类型 |
|---|---|---|
| 线索入库成功率 | 有效手机号线索成功入库并可追踪 | 一期验收指标 |
| 加好友任务可追踪率 | 每个加好友任务有状态、失败原因和截图/日志 | 一期验收指标 |
| AI 安全停手率 | 触发高风险、模型失败、低置信时 AI 停止并进入接管流程 | 一期验收指标 |
| 重复发送次数 | 同一回复动作重复发送次数为 0 | 一期硬指标 |
| 转人工后自动回复次数 | 进入 handoff_required 或 human_active 后自动回复次数为 0 | 一期硬指标 |
| 飞书通知可见性 | 接管事件有通知状态，失败可重试、可追踪 | 一期验收指标 |
| AI 自动回复率 | 灰度期统计，不作为首期硬承诺 | 优化指标 |
| RAG 命中率 | 建立样本集后统计，不作为首期硬承诺 | 优化指标 |

## 5. MVP 范围

### 5.1 MVP 必做范围

| 模块 | MVP 内容 | 优先级 |
|---|---|---|
| 线索管理 | 线索导入、去重、分配销售、状态查看 | P0 |
| 销售与 Worker 绑定 | 销售配置、Worker 绑定、启停状态查看 | P0 |
| 加好友任务 | 按手机号加好友、写初始绑定备注、失败回传 | P0 |
| 会话绑定与监听 | 绑定微信会话、识别客户消息、识别销售人工回复 | P0 |
| AI 文字回复 | 基于上下文、知识库、风控生成候选回复并发送 | P0 |
| Guard 安全检查 | 敏感承诺、底价、事故、金融、合同等风险拦截 | P0 |
| 人工接管 | 风险/高意向/失败时停止 AI 并飞书通知销售 | P0 |
| Worker 执行台 | 展示状态、任务、步骤、截图证据、错误和控制按钮 | P0 |
| 防重复发送 | message、batch、reply_action、sent_ack 幂等 | P0 |
| 自动召回 | watching 客户低频固定文案召回 | P1 |
| 图片理解 | 客户图片另存、上传、识别、转 AI 或转人工 | P1 |
| 车源索引 | 本地车源导入/样本索引优先，大风车 API 联调后接入 | P1 |
| 配置中心 | 上限、静默、关键词、文案、图片保留等基础配置 | P1 |
| 日志审计 | 任务、消息、AI 候选、Guard、飞书、人工操作留痕 | P1 |

### 5.2 一期不做范围

- 不做多商户 SaaS、计费、套餐、租户隔离。
- 不做复杂 CRM、销售业绩管理、订单合同系统。
- 不做复杂 BI 看板，只保留基础状态和任务统计。
- 不做短信通知，只做飞书通知。
- 不做微信协议破解，不读取微信数据库，不使用非公开微信接口。
- 不承诺规避微信平台风控。
- 不让 AI 自由生成召回话术。
- 不让 Worker 持有模型、大风车、飞书密钥。
- 不把性能 P95 作为未压测前的硬验收承诺。

### 6.3 销售侧

销售一期不需要登录后台，主要通过以下方式参与：

- 手机微信接收客户消息并人工回复。
- 飞书接收系统转人工通知。
- 当销售手机微信回复客户后，系统识别为人工接管并停止 AI。

待确认：销售是否需要后台账号查看自己的线索。建议一期不做，避免权限和操作复杂化。

## 7. 业务规则

### 7.1 线索规则

| 规则 | 产品口径 |
|---|---|
| 手机号标准化 | 以标准化手机号作为核心去重键。 |
| 手机号脱敏 | 后台列表默认只展示手机号后四位，详情页按权限展示完整手机号。 |
| 重复线索 | 同手机号存在未关闭线索时，不新建有效线索，只追加来源记录。 |
| 拒绝客户 | 客户标记 rejected 后，后续重复导入不自动加好友、回复或召回。 |
| 线索来源 | 支持手工、CSV/Excel、API 三类来源，API 先预留适配器。 |

待确认：完整手机号是否允许后台直接查看。建议只有管理员可查看，普通运营默认脱敏。

### 7.2 分配规则

| 规则 | 产品口径 |
|---|---|
| 默认策略 | 建议一期默认手动分配，保留轮询配置。 |
| 分配条件 | 销售启用、已绑定 Worker、未超过每日加好友上限。 |
| 运行中换绑 | 销售换绑 Worker 后，新任务走新 Worker；运行中任务需人工确认处理。 |
| 未分配线索 | 保持 new 状态，不创建 add_friend 任务。 |

待确认：是否必须自动轮询分配。建议一期先手动分配，试运行稳定后再开启轮询。

### 7.3 加好友规则

| 规则 | 产品口径 |
|---|---|
| 任务生成 | 线索已分配且满足条件后生成 add_friend 任务。 |
| 已是好友 | 不重复发送好友申请，直接尝试绑定会话。 |
| 失败处理 | 可重试失败允许人工重试；风险/受限类失败不自动连续重试。 |
| 好友申请语 | 作为配置项，支持销售姓名、门店名、线索来源变量。 |
| 初始备注 | 用于线索和微信会话绑定，转人工后不修改备注。 |

建议默认好友申请语：您好，我是{门店名}{销售姓名}，看到您咨询过车辆信息，方便通过一下，我给您发具体车况和价格。

待确认：好友申请语、初始备注格式、是否允许销售自定义申请语。

### 7.4 会话与 AI 回复规则

| 规则 | 产品口径 |
|---|---|
| 未绑定不回复 | 微信会话未能绑定到线索时，AI 不自动回复。 |
| AI 回复上限 | 单会话最多 20 条 AI 回复，达到后进入 watching。 |
| 销售人工回复 | 检测到销售人工回复后，状态转 human_active，AI 停止。 |
| 高风险问题 | 底价、事故、泡水、金融、合同、投诉等触发接管。 |
| 模型失败 | DeepSeek、RAG、图片识别、车源查询失败且无法安全回复时，转人工。 |
| Guard 不通过 | 原文不发送；根据结果改写、转人工或阻断。 |
| 不兜底冒险 | 不使用不确定兜底话术继续自动回复。 |

### 7.5 消息合并与防重复规则

| 规则 | 产品口径 |
|---|---|
| 同会话合并 | 客户短时间连续消息合并为一个 message_batch。 |
| 旧回复作废 | 新消息到达且旧回复未发送时，旧 reply_action 作废并重新生成。 |
| 发送中不强撤 | Worker 已开始发送时不强行取消，后续消息进入下一轮。 |
| 服务端为准 | 是否可发送由服务端状态决定，Worker 只执行最新有效 action。 |
| 发送确认 | sent_ack 成功后才认为发送完成。 |
| unknown_send_result | Worker 发送中异常退出时，不自动补发，需要人工确认或重新生成。 |

建议默认消息合并窗口：3 秒；最大等待时间：8 秒。待确认。

### 7.6 人工接管规则

| 触发来源 | 处理 |
|---|---|
| 风险关键词 | 状态转 handoff_required，AI 停止，飞书通知销售。 |
| 高意向关键词 | 状态转 handoff_required，AI 停止，飞书通知销售。 |
| 模型/图片/车源失败 | 无法安全回复时转 handoff_required。 |
| 销售主动回复 | 状态转 human_active，AI 停止，不再召回。 |
| 手动操作 | 后台或 Worker 执行台可手动接管/禁用 AI。 |

接管后客户继续发消息，系统不再次发送 AI 回复。默认不做二次飞书提醒。

待确认：销售长时间未接管是否需要二次提醒。建议一期不做，先避免通知轰炸。

### 7.7 召回规则

| 规则 | 产品口径 |
|---|---|
| 适用客户 | status=watching、已加好友、已绑定会话、未拒绝、未转人工、未关闭。 |
| 触发条件 | 最近 N 天无客户/销售消息。 |
| 召回次数 | 每个客户最多召回 1 次。 |
| 文案 | 固定配置文案，不由 AI 自由生成。 |
| 排除条件 | rejected、handoff_required、human_active、closed、黑名单、静默时段、达到上限。 |

建议默认召回周期：7 天；每日召回上限：每销售 30 条；召回文案：您之前关注的车型我这边还有几台类似车源，预算和车型如果有变化也可以发我，我帮您重新筛一下。待确认。

### 7.8 风控规则

| 风控项 | 产品口径 |
|---|---|
| 总开关 | 支持全局、销售、Worker、会话级关闭自动回复。 |
| 静默时段 | 静默时段内不自动回复和召回。 |
| 每日上限 | 加好友、AI 回复、召回均可配置上限。 |
| 黑名单 | 黑名单客户不自动处理。 |
| 白名单 | 仅用于测试手机号，不绕过高风险接管。 |
| 微信风险提示 | 出现操作频繁、添加受限、环境异常时暂停 Worker 或相关任务。 |

建议默认静默时段：22:00-09:00；加好友上限：每销售 50 条/天；AI 回复上限：每销售 300 条/天；单会话突发限频：1 分钟最多 3 条 AI 回复。待确认。

- 每日召回上限
- 人工接管关键词
- 关键词拦截词
- 黑名单
- 测试白名单
- 随机发送延迟
- 单会话突发限频
- 风险暂停恢复方式

待确认：配置是否支持按销售单独覆盖。建议 P1 支持销售级覆盖，P0 先全局配置。

### 8.8 飞书通知

通知内容：

- 客户标识/线索短码
- 手机号后四位
- 销售
- 触发原因
- 最近客户消息
- 建议动作
- 触发时间

通知记录字段：

- handoff_event_id
- 销售
- 状态：pending、sending、sent、failed、cancelled
- 失败原因
- 重试次数
- 最近发送时间

主要操作：

- 查看通知详情
- 手动重发

待确认：飞书是否需要“我已接管”按钮。建议一期预留，不作为必做。

### 8.9 Worker 执行台流程

启动流程：

```text
打开 Worker 执行台 -> 检查服务端连接 -> 检查微信登录 -> 点击启动 -> 领取任务 -> 执行微信操作 -> 回传结果
```

加好友流程：

```text
领取 add_friend -> 获取 UI 锁 -> 搜索手机号 -> 判断结果 -> 发送申请/识别已是好友 -> 写初始备注 -> 回传状态 -> 释放 UI 锁
```

聊天回复流程：

```text
监听客户消息 -> 上传服务端 -> 等待 AI/Guard -> claim 最新 reply_action -> 获取 UI 锁 -> 发送回复 -> sent_ack -> 释放 UI 锁
```

召回流程：

```text
领取 follow_up -> 获取 UI 锁 -> 打开会话 -> 发送固定文案 -> 回传状态 -> 释放 UI 锁
```

## 10. 状态流转

### 10.1 主状态

```text
new
 -> assigned
 -> add_friend_pending
 -> add_friend_sent / friend_added / failed
 -> ai_chatting
 -> watching / handoff_required / human_active / rejected / closed
```

### 10.2 状态说明

| 状态 | 产品含义 | 自动动作 |
|---|---|---|
| new | 新线索，未分配销售 | 可分配 |
| assigned | 已分配销售和 Worker | 可创建加好友任务 |
| add_friend_pending | 等待 Worker 加好友 | 可执行加好友 |
| add_friend_sent | 已发好友申请，等待通过 | 不自动回复 |
| friend_added | 已加好友或已是好友 | 可绑定会话 |
| ai_chatting | AI 自动跟进中 | 可回复、可风控接管 |
| watching | 观望或 AI 达上限 | 可按规则召回 |
| handoff_required | 需要人工接管 | 发飞书，AI 停止 |
| human_active | 销售已人工介入 | 不自动回复，不召回 |
| rejected | 客户拒绝/黑名单 | 不自动处理 |
| closed | 人工关闭 | 不自动处理 |

## 11. 异常场景

| 异常 | 产品处理 |
|---|---|
| 手机号无效 | 线索入库失败或标记无效，展示原因。 |
| 重复手机号 | 不创建重复有效线索，追加来源记录。 |
| Worker 离线 | 任务保持 pending，后台展示 Worker 离线。 |
| 微信未登录 | Worker 暂停任务并提示登录。 |
| 搜不到手机号 | 加好友任务 failed，原因 phone_not_found。 |
| 已是好友 | 跳过申请，进入会话绑定。 |
| 操作频繁/添加受限 | 暂停相关任务，截图留痕，后台告警。 |
| 会话绑定失败 | 不自动回复，进入待人工处理。 |
| AI 超时/失败 | AI 停止，转人工。 |
| RAG 证据不足 | 不编造，转人工。 |
| 图片保存/上传/识别失败 | 不强行回复，转人工。 |
| 大风车接口失败 | 保留旧索引；无可用证据时价格/车源问题转人工。 |
| 飞书通知失败 | AI 仍停止，通知队列重试，后台告警。 |
| Worker 发送中崩溃 | 状态进入 unknown_send_result，不自动补发。 |
| 销售人工回复 | 状态 human_active，AI 停止且不召回。 |
| 客户明确拒绝 | 状态 rejected，后续不自动处理。 |

## 12. 验收标准

### 12.1 P0 验收

- 可以导入有效手机号线索，并在后台查看。
- 同手机号重复导入不会创建重复有效线索。
- 可以手动分配销售并绑定 Worker。
- 可以生成 add_friend 任务，并在 Worker 执行台看到执行步骤。
- Worker 可以识别微信未登录、窗口找不到、搜索失败、已是好友等结果。
- 已绑定会话的客户发送文字后，系统可以生成 AI 候选回复并通过 Guard。
- Guard 拦截底价、事故、泡水、金融、合同、投诉等高风险内容。
- Worker 只发送服务端最新有效 reply_action。
- 同一 reply_action 不会重复发送。
- 销售手机端人工回复后，AI 自动停止。
- 触发 handoff_required 后，飞书通知销售，AI 停止。
- 飞书失败时后台可见，AI 不恢复自动回复。
- Worker 重启、断网、服务端恢复后，不重复发送历史回复。

### 12.2 P1 验收

- watching 客户满足 N 天未互动后，可生成 follow_up 任务。
- 每个客户最多召回 1 次，重启后不重复召回。
- 图片消息可以被保存、上传、识别，并进入 AI 或转人工流程。
- 车源索引可通过本地导入/样本数据供 AI 查询。
- 后台可配置关键词、上限、静默时段、召回文案。
- 日志审计可追踪 AI 候选、RAG 证据、Guard 结果和人工操作。

### 12.3 不作为一期硬验收

- AI 自动回复率达到某个固定比例。
- RAG 命中率达到某个固定比例。
- 图片理解准确率达到某个固定比例。
- 大风车 API 一定可联调成功。
- 性能 P95 达到未压测前的固定数值。

## 13. 风险与待确认问题

### 13.1 Gate 0 阻塞项

| 问题 | 影响 | 建议 |
|---|---|---|
| 大风车 API、字段、鉴权、IP 白名单未确认 | 影响车源同步和价格回答 | 先用本地车源导入验收主链路 |
| 销售手机端人工回复同步结构未实测 | 影响 human_active 判断准确性 | 用真实微信环境做专项验证 |
| OmniAuto RAG 能力未评估 | 影响 AI 回复质量和知识库方案 | 开发前输出可复用/需重构清单 |

### 13.2 产品待确认项

| 待确认项 | 建议默认值 |
|---|---|
| 线索接入方式 | P0 CSV/Excel，P1 接 API |
| 小风车真实来源 | 先确认落在抖音来客、飞鱼 CRM、企业号还是小程序 |
| 分配策略 | P0 手动分配，P1 轮询 |
| 好友申请语 | 使用门店名、销售姓名、咨询来源变量 |
| 初始备注规则 | 建议格式：CJ-{线索短码}-{手机号后4位} |
| 每日加好友上限 | 每销售 50 条/天 |
| 每日 AI 回复上限 | 每销售 300 条/天 |
| 每日召回上限 | 每销售 30 条/天 |
| 静默时段 | 22:00-09:00 |
| 消息合并窗口 | 3 秒，最大等待 8 秒 |
| 随机发送延迟 | 1-5 秒 |
| 单会话突发限频 | 1 分钟最多 3 条 AI 回复 |
| 召回周期 | 7 天 |
| 召回次数 | 每客户最多 1 次 |
| 召回文案 | 固定配置，不由 AI 生成 |
| 飞书“我已接管”按钮 | P1 预留，不作为 P0 |
| 销售后台账号 | 一期不做 |

### 13.3 主要风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 微信 UI 自动化不稳定 | 微信版本、窗口结构、账号状态变化会影响 Worker | 锁定版本、截图留痕、失败暂停、人工降级 |
| 外部接口不可控 | 大风车、飞书、模型服务可能受限 | 降级路径和外部依赖边界写入验收 |
| AI 回复风险 | 可能产生不当承诺或编造 | 字段隔离、Guard、低置信转人工 |
| 重复发送风险 | 断网/重启/发送未知时可能重复 | 服务端幂等、sent_ack、unknown_send_result 不自动补发 |
| 销售接管识别风险 | 人工回复识别不准会导致 AI 误继续 | 真实环境专项测试，必要时保留手动接管 |
| MVP 范围偏大 | 同时包含 Worker、AI、图片、车源、召回 | P0 先保主链路，P1 再上图片/车源/召回优化 |

## 14. 建议研发拆解

### 14.1 第一阶段：基础闭环

- 线索导入、去重、销售和 Worker 绑定。
- add_friend 任务创建和状态回传。
- Worker 执行台基础状态和控制按钮。
- 微信 UI 锁和任务串行执行。
- 基础日志和失败原因。

### 14.2 第二阶段：AI 文字回复与接管

- 会话绑定和客户消息监听。
- message_event、message_batch、reply_action、sent_ack 幂等。
- DeepSeek 文字回复。
- RAG 基础接入。
- Guard 检查。
- 风险转人工和飞书通知。

### 14.3 第三阶段：异常恢复与风控配置

- Worker 断网/重启恢复。
- pending_action 作废和 unknown_send_result。
- 总开关、静默、上限、黑名单、关键词配置。
- 飞书通知队列和重试。
- 日志审计。

### 14.4 第四阶段：召回、图片与车源

- watching 标记和 follow_up 任务。
- 固定召回文案发送。
- 图片另存、上传和视觉识别。
- 本地车源导入/样本索引。
- 大风车 API 联调。

## 15. 结论

本方案建议一期以“可控、安全、能停手”为核心，不追求 AI 全自动成交。只要 P0 完成线索到微信、AI 文字回复、风险转人工、防重复发送和可追踪后台，就已经具备试运行价值。图片理解、车源深度联动、自动分配和召回可以作为 P1 增强项推进。
