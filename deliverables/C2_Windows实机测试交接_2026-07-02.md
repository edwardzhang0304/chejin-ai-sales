日期：2026-07-02

## 1. 当前测试目标

本轮只测 C2，不测 C3 真实 AI 自动回复。

需要验证：

| 测试项 | 验收标准 |
|---|---|
| 第一屏主动扫描 | 微信第一屏出现短码会话时，Worker 能识别 `remark_code` 并绑定会话 |
| 第一屏命中优先读取 | 当前第一屏命中目标后，应进入目标会话并读取消息 |
| 非第一屏定向读取 | 服务端下发 `read-targets` 后，Worker 能按短码搜索目标会话并点击进入 |
| 二次确认 | 进入会话后，标题/备注必须包含短码，确认不是发错/读错会话 |
| 消息入库 | 客户消息入库为 `customer`，销售消息入库为 `sales_candidate/self` |
| 语音识别 | 客户语音入库为 `message_type=voice`，`content` 为微信转写文本 |
| 语音失败保护 | 语音转写失败时，不触发 AI，不把语音时长当正文 |
| 去重 | 重复扫描不得重复入库 |
| UI 锁 | add_friend / send / scan / voice-transcribe 不得并行控制微信 |
| 停止测试 | 停止后 `read-targets` 必须为空，Worker 不得继续操作微信 |

## 6. 已发现问题

### BUG-C2-TARGET-CLICK-001 / P0

标题：短码搜索结果出现后未点击联系人，定向读取卡住。

复现步骤：

1. Windows 实机打开微信和 Worker。
2. 后端开启 `CJVOICE01` 读取目标。
3. 当前微信不在 `CJVOICE01` 会话。
4. Worker 执行短码搜索。

实际结果：

- 微信搜索框已输入 `CJVOICE01`。
- 搜索浮层展示 `CJVOICE01 虾丸子大人`。
- Worker 没有继续点击联系人进入会话。
- 未发生二次确认、消息读取、语音入库。

预期结果：

- 搜索结果出现后自动点击目标联系人。
- 进入会话后校验标题/备注包含 `CJVOICE01`。
- 校验通过后读取消息并上报后端。

影响：

- C2 非第一屏定向读取阻塞。
- 语音识别链路无法继续验收。
- C3 发送前 `pre_send_refresh` 后续也会受影响。

当前定位：

- 短码搜索本身成功。
- 失败点在“搜索结果候选出现后点击进入会话”。
- 若 Worker 日志没有发起候选点击，偏客户端流程问题。
- 若日志已发起点击但微信未进入会话，偏 OmniAuto 候选点击/坐标识别问题。

### BUG-C2-VOICE-001 / P0

标题：语音气泡被发现但未入库为 voice 消息。

实际结果：

- `CJVOICE01` 绑定预览出现 `[语音] 2"`。
- Worker 曾进入 `voice_transcribe_starting`。
- 后端 `message_events` 中 `message_type=voice` 数量仍为 `0`。
- 没有看到语音转写文本入库。

预期结果：

- 客户语音应入库为 `message_type=voice`。
- `content` 应为微信转写文本。
- 转写失败时应记录失败，不得把语音时长当正文，不得触发 AI。

影响：

- 如果销售发消息后客户回语音，系统可能一直误判为等待客户回复，影响业务闭环。

### BUG-C2-STOP-001 / P0

标题：仅设置 `listen_status=paused` / `allow_listening=false` 后，`read-targets` 仍可能返回目标。

复现现象：

1. 将 `CJVOICE01` 设置为 `listen_status=paused`、`allow_listening=false`。
2. 调用 `read-targets`。
3. 仍返回 `CJVOICE01` 目标。
4. 后续强制将 `bind_status=disabled` 后，`read-targets` 才为空。

预期结果：

- 只要 `allow_listening=false` 或 `listen_status=paused`，该会话不得出现在正常 `read-targets` 中。

影响：

- 测试结束后可能无法停干净。
- 真实业务中可能出现已暂停会话仍被 Worker 操作。

### BUG-C2-LOCK-002 / P0，待继续观察

标题：历史版本中 Worker 停止目标后仍持有 UI 锁并继续扫描。

最新观察：

- 新包中 `voice_transcribe_starting` 后，Worker 曾释放锁并回到 idle。
- 当前未复现长时间锁死。

状态：

- 暂按“部分回归通过，需继续观察”处理。
- 不得把“重启客户端后恢复”作为通过标准。

### BUG-C2-VISIBLE-QUEUE-003 / P0，待继续观察

标题：历史版本中 disabled 的 `CJTEST01` 会被第一屏扫描重新拉回队列。

最新观察：

- `CJTEST01` 被第一屏看到后，`last_seen_at` 会更新。
- 但当前未重新变成 `listening`，也未进入 read-targets。

状态：

- 暂按“本轮未复现，需继续观察”处理。

## 10. 新测试接手建议

1. 先不要一上来测 C3。
2. 先验证 `read-targets=[]` 和 Worker 空闲。
3. 每次只打开一个短码目标。
4. 先测 `CJVOICE01` 的非第一屏定向读取是否能点击进入会话。
5. 只有进入会话成功后，再测语音入库。
6. 每轮结束必须停目标并确认 `read-targets=[]`。
7. 不接受“重启客户端后正常”作为通过结论。
8. 截图必须包含微信窗口、Worker 窗口和时间。
9. 后端验证必须查 `message_events`，不能只看 Windows 画面。
10. 如果发现搜索浮层有联系人但不点击，直接判 P0 阻塞，不继续测语音。
