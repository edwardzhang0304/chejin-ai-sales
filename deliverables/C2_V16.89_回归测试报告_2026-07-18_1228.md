# C2 V16.89 Windows 实机回归测试报告

## 1. 测试结论

**结论：不通过，C2 暂不得进入 C3。**

V16.89 已修复 V16.88 实机中的 customer 语音遗漏：从零数据基线开始，当前屏幕的 2 条 customer 语音和 1 条 self 语音均生成完整、唯一的 V3 voice 事件，角色、正文、anchor 和完成状态正确，`messages/ingest` 返回 200。

但长时多轮读取中出现两类数据正确性问题：同一条 self 文本“哦”因页面位移跨轮重复入库；系统/界面文字“你正在其他设备进行切换”和“通话时长06:53口”被当作 customer/self 聊天文本入库。这会污染 C2 对话上下文，属于上线阻断。

## 6. 高风险缺陷

### BUG-C2-V1689-001：同一文本因页面位移或 OCR 抖动跨轮重复入库

| 字段 | 内容 |
|---|---|
| 严重等级 | P0 |
| 复现步骤 | 1. 从事件数 0 开启目标；2. 完成首轮读取和入库；3. 保持屏幕不发新消息；4. 继续多轮定位和读取；5. 查询 `message_events` |
| 实际结果 | “哦”在页面 y=293 和 y=173 时使用不同 visual ID/dedupe key 两次入库；“你正在其他设备进行切换”在同一气泡坐标因多一个句点再次入库 |
| 预期结果 | 同一物理文本消息应具有稳定身份，坐标位移或小幅 OCR 标点抖动不得生成新事件 |
| 影响范围 | C2 对话序列、消息计数、后续意图判断和 C3 自动回复 |

### BUG-C2-V1689-002：系统/通话界面文字被误当作用户聊天文本

| 字段 | 内容 |
|---|---|
| 严重等级 | P1（若业务明确要求不采集通话记录，应升为 P0） |
| 复现步骤 | 保持当前微信会话连续多轮读取，查询新增 text 事件 |
| 实际结果 | “通话时长06:53口”被上报为 `self + text`；“你正在其他设备进行切换”被上报为 `customer + text` |
| 预期结果 | 非用户气泡的系统/通话界面文字不得以 customer/self 普通 text 进入业务对话 |
| 影响范围 | 聊天上下文污染、角色误判、后续意图与自动回复 |

## 9. 上线建议

1. 修复文本消息的稳定身份，不得使用页面纵坐标和 OCR 微小标点变化生成新消息。
2. 明确通话记录和系统提示的产品口径；若不属于聊天消息，应在 OmniAuto 观察层过滤，不得等到后端清洗。
3. 修复后覆盖“页面位移后重读”和“OCR 标点抖动”回归，事件数必须保持稳定。
4. 需另行构造真实 `duration_conflict=true`、`structural_candidate_count=1` 的实机样本，才能验收 `unique_structure_with_duration_conflict` 精确分支。
5. 现场已停干净：revision 25，`disabled/paused/allow_listening=false`，`read-targets=[]`，停止后新增事件 0，最终锁已释放。
