## 冲突处理

### 图片身份

上游 `visual_anchor.py` 和 `visual_collector.py` 自带 occurrence/group 身份。
车金没有接入这套身份。继续由：

```text
OmniAuto：提供当前截图的图片物理证据
Worker：生成跨轮 source_message_key / dedupe_key
后端：最终唯一约束去重
```

图片当前屏重新定位继续使用车金已有的：

```text
C2 同行头像角色
+ 图片视觉指纹
+ 前后稳定消息
+ 当前截图内重复组序号
```

其中当前截图内序号只用于本次定位，不进入跨轮消息身份。

### 角色

上游部分入口默认 customer。车金保留 Worker 已确认的
`customer/self + same_row_avatar`，Vision 只能核对物理侧，不能重新决定角色。

### 调度

未引入以下上游运行流程：

- `scheduler_capture.py`
- `runtime.py`
- `wechat_group_worker.py`
- OmniAuto 自带 Scheduler、Brain、上报和历史回查

车金继续使用现有单图片 `VisionHostPorts` 适配事务。

## Worker 当前屏收敛

图片模型结束后，Worker 在原会话和同一 UI 锁内执行：

```text
当前屏最终读取
→ Worker 跨轮身份对齐
→ 新语音继续转写
→ 新图片按 Ledger 只处理 NEW_IMAGE
→ 再次读取当前屏
→ 当前屏无待处理语音和图片后统一组包
```

约束：

- 所有读取均为 `target_mode=current`。
- 不传滚动参数，不主动上滚。
- 被顶出当前屏的旧图片不追。
- 旧图片命中 Ledger 后不重复复制或调用 Vision。
- 身份无法唯一确认时返回
  `MESSAGE_CROSS_ROUND_IDENTITY_AMBIGUOUS`，阻断图片、入库和 Brain。
- Vision 配置缺失或不可逆动作未发生时，不增加无意义的最终截图。
