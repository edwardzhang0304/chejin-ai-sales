## 三层统一与职责边界（最高约束）

- **OmniAuto 只负责事实和 AI 结果**：微信观察与操作、OCR、同行头像角色证据、语音父子绑定、Vision 和 Brain 结果。
- **Worker 只负责获得授权后串行编排并翻译合同**：单会话 UI 锁、统一消息槽位和顺序、稳定消息身份、本地处理清单、Outbox 和 V3 映射。
- **车金后端只负责业务决策、状态和落库**：短码/private 授权、批次、状态机、Brain Adapter、主动开场、召回、handoff、reply action 和数据库最终去重。

同一字段必须只有一个所有者；其他层只能校验、透传或映射。禁止私自增加同义 action、临时字段、图片接口、Vision/Brain 实现或第二套角色规则。三层使用 `contracts/examples/c2_v3_mixed_roundtrip.json` 作为共同回归样例。

## 结论

代码、机器合同、数据库迁移和离线自动化已完成。真实 OmniAuto 模型协议已验证；完整 Brain Prompt 当前以 `retry_later` 超时收口，未产生可见回复。RAG 架构沿用 OmniAuto 的租户知识库、分块索引和可选 PostgreSQL 存储，车金业务内容按产品决定留空，待上线后由车金人员维护；不得用许聪的个人知识内容或伪造命中替代。

三层职责保持唯一：OmniAuto 产出观察事实、Vision 文字结果和 Brain 结果；Worker 负责授权后的串行执行与 V3 翻译；后端负责授权、状态机、批次、动作和最终落库。

## 图片持久化

- 不新增图片上传或图片专用后端 API，继续复用 `messages/ingest`。
- 不接收原图、图片字节、本地路径、缩略图、`asset_id` 或完整 Provider 响应。
- 正式结果仅为 `raw_payload.customer_image_understanding` 与 `visual_bridge_input`；后端递归扫描完整图片 `raw_payload`。
- Worker 使用显式文字白名单投影，丢弃 Provider 原始响应、局部视觉画像、`picture_ref`和任何可还原图片的内容。
- Vision 失败可作为带 `image_processing_reason` 的失败图片事实入库并进入确定性 handoff；不阻断同批文字/语音落库，也不创建 reply action。忽略态不生成 canonical message。
- 后端保留 `unique(conversation_id, dedupe_key)` 作为最终去重；Worker ledger/Outbox 仅减少重放。
- 后端每条结果必须返回 Worker 生成的 `source_message_key`；Worker 只用该 key 确认 ledger。`ignored` 记为本地终止，不重复 RPA/Vision。

## 图片可观测性

图片链路使用同一个 `source_message_key` 贯穿以下结构化事件：

```text
c2_image_slot_discovered
-> c2_image_role_confirmed / c2_image_role_rejected
-> c2_image_authorization_checked
-> c2_image_slot_started
-> c2_image_stage
-> c2_image_slot_finished
-> c2_image_slot_terminalized
-> c2_image_slot_assembled
-> c2_image_outbox_staged
-> c2_image_ingest_finished
```

- `c2_image_stage` 覆盖会话确认、内存截图、右键、复制菜单、剪贴板序号、内存位图读取和 Vision 调用，记录阶段顺序与耗时。
- 复用初始读取或最终权威画面已有的完整截图引用，不为图片识别新增截图、裁切文件或图片目录。
- 每次内存截图只生成不可逆的缩小画面 SHA-256、尺寸、OCR 数量和消息数量；不记录像素或 base64。
- 右键菜单 OCR 只记录固定白名单菜单词及其边界，不记录聊天正文。
- Vision 只记录非敏感配置名、耗时、结果长度和结果 SHA-256，不记录 Token、图片字节或 Provider 原始响应。
- Outbox 重传有独立事件，能证明恢复时只重传结构化 JSON，没有重复右键、复制或调用 Vision。
- 所有图片事件均显式记录 `image_persisted=false`，用于日志审计和 Windows 实机问题定位。

## C3 状态与幂等

- 新客户事实在同事务内创建/复用 `message_batch`，并以会话行锁串行化并发批次收集。
- 同一批次只有一个 current reply action；新客户消息作废旧 batch/action。
- `send_reply` 创建 reply_action；`handoff/handoff_for_approval` 创建 handoff_event。
- Brain 无可见回复、非法结果、Provider 异常统一为 `failed + retry_later`；只有模型调用前业务门禁可 `no_action`。
- claim-send 和 sent-ack 幂等；`unknown_send_result` 为终态，禁止自动补发。
- 好友确认可幂等创建 `friend_welcome`，不伪造客户消息。
- 召回先下发 `recall_precheck`，无新消息才创建带 `recall_cycle_id` 的 recall batch；有静默时段、周期和每日上限。
