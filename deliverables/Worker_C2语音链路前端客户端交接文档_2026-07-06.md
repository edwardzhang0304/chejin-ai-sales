## 当前未通过的核心问题

### 问题：C2 语音真实转文字仍未稳定通过

现象：

- 客户侧/销售侧语音都必须纳入 C2 采集。
- 左右两侧语音都有三种形态：
  - 未读未转文字
  - 已读未转文字
  - 已读已转文字
- 当前失败集中在“右键菜单语音转文字”链路：
  - 有时右键菜单没有打开；
  - 有时右键菜单打开了，但没有点击“语音转文字”；
  - 有时 OCR 得到的是语音时长/占位文本，不是真正转写正文。

V16.51 针对该问题做了两处修复：

1. 右键菜单打开后等待再截图：

```text
WECHAT_WIN32_OCR_VOICE_CONTEXT_MENU_WAIT_MS
默认 1200ms
```

2. 右键菜单截图改为全屏可见截图：

原因是微信右键菜单是系统浮层，右侧 sales/self 语音菜单可能伸出微信窗口边界；只截微信窗口会漏掉菜单。

当前 voice-transcribe 逻辑大致是：

```text
截图当前会话
-> OCR 识别语音气泡/转文字按钮
-> 优先点击显性“转文字”按钮
-> 如果没有显性按钮，右键语音气泡
-> OCR 右键菜单
-> 点击“语音转文字”
-> 等待微信生成转写文本
-> 再 OCR messages
-> 输出 transcribed_messages
```

## 语音入库规则

必须遵守：

```text
只有真实转写成功，才能入库 message_type=voice。
```

不能入库：

```text
[语音] 3"
の3"
2"
2" 转文字
の3"\n还很凉快。
```

这些都是 OCR 占位/噪声，不能当业务正文。

允许入库：

```text
voice_transcribe_completed
且 transcribed_messages 里能拿到真实正文
```

## 日志/报告怎么打包

开一个新的 PowerShell 窗口执行，不用停客户端：

```powershell
$from = (Get-Date).AddMinutes(-30)
$to = Get-Date
$stamp = Get-Date -Format "yyyyMMdd_HHmmss"
$out = "$env:USERPROFILE\Desktop\c2_debug_recent_$stamp.zip"

$roots = @(
  "$env:LOCALAPPDATA\CheJinWorker\artifacts\wechat_c2\voice",
  "$env:LOCALAPPDATA\CheJinWorker\artifacts\wechat_c2\messages",
  "$env:LOCALAPPDATA\CheJinWorker\artifacts\wechat_c2\sessions",
  "$env:LOCALAPPDATA\CheJinWorker\runtime",
  "$env:LOCALAPPDATA\CheJinWorker\logs"
)

$tmp = Join-Path $env:TEMP "chejin_c2_debug_$stamp"
New-Item -ItemType Directory -Force -Path $tmp | Out-Null

foreach ($root in $roots) {
  if (Test-Path $root) {
    $name = Split-Path $root -Leaf
    $dest = Join-Path $tmp $name
    New-Item -ItemType Directory -Force -Path $dest | Out-Null

    Get-ChildItem $root -Recurse -File -ErrorAction SilentlyContinue |
      Where-Object { $_.LastWriteTime -ge $from -and $_.LastWriteTime -le $to } |
      ForEach-Object {
        $relative = $_.FullName.Substring($root.Length).TrimStart('\')
        $target = Join-Path $dest $relative
        New-Item -ItemType Directory -Force -Path (Split-Path $target -Parent) | Out-Null
        Copy-Item $_.FullName $target -Force
      }
  }
}

Compress-Archive -Force -Path (Join-Path $tmp '*') -DestinationPath $out
Write-Host "已打包: $out"
explorer.exe /select,$out
```

如果测试超过 30 分钟，把第一行改成：

```powershell
$from = (Get-Date).AddMinutes(-60)
```

## 看报告时优先看什么

语音链路重点看：

```text
artifacts/wechat_c2/voice/**/voice_transcribe_review.json
artifacts/wechat_c2/voice/**/voice_transcribe_before*.png
artifacts/wechat_c2/voice/**/voice_transcribe_context_menu*.png
artifacts/wechat_c2/voice/**/voice_transcribe_after*.png
```

判断顺序：

1. `voice_transcribe_before*.png` 里是否能看到目标会话和语音气泡。
2. 是否找到了显性“转文字”按钮。
3. 如果走右键，`voice_transcribe_context_menu*.png` 是否真的能看到右键菜单。
4. 菜单 OCR 是否识别到 `语音转文字`。
5. 点击后 `voice_transcribe_after*.png` 是否出现真实转写文本。
6. `voice_transcribe_review.json` 里的 `state` 是不是 `voice_transcribe_completed`。
7. `transcribed_messages` 是否有干净正文。
8. 后端 `message_events.content` 是否是真实正文，不是占位/整段 payload。

## 下一步建议

先不要继续大改流程。下一步应该基于 V16.51 的 Windows 实机日志确认：

1. 右键菜单截图是否真的出现。
2. 如果出现，OCR 是否识别到 `语音转文字`。
3. 如果识别到，点击坐标是否正确。
4. 如果点击正确，微信是否生成转写文本。
5. 如果微信生成了转写文本，`transcribed_messages` 为什么没有正确输出。

只有确认断点后再修对应环节。

## 不要做的事

- 不要把语音时长或 `[语音]` 占位当正文入库。
- 不要为了通过测试把 voice 强行标记成功。
- 不要新增临时字段绕过技术方案字段口径。
- 不要恢复多屏补偿扫描。
- 不要在 C2 只读监听里启用悬浮球/键鼠守护。
- 不要用缓存命中绕过真实 OCR/点击根因。
