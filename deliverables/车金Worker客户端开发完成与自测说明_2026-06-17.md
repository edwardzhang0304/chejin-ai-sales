## 4. OmniAuto 接入说明

Worker 客户端正式真实链路固定调用 OmniAuto：

```text
add-friend-entry-click-plan-windows
```

Worker 调用参数：

```text
--phone 或 --wechat
--verify-message
--remark-name
--remark-code
--artifact-dir
```

字段规则：

- `phone` 或 `wechat` 必填。
- `verify_message` 必填。
- 服务端生成 `verify_message` 的当前模板为：`您好，我是车金二手车的[销售名]，您刚咨询过二手车`。
- `remark_name` 必填。
- `remark_code` 必填。
- `remark_name` 当前必须等于 `remark_code`，即 Worker/RPA 自动写入微信备注的内容仅为客户短码。
- 销售后续可以在微信备注中追加人工说明，但必须保留原客户短码；删除或改写短码会影响后续自动识别和绑定。
- Worker 不生成 `verify_message / remark_name / remark_code`，只消费服务端 Worker pull 返回的字段。
- 普通后台 `GET /api/tasks` / `GET /api/tasks/{id}` 不暴露明文手机号；Worker 专用 `GET /api/workers/{worker_id}/tasks/pull` 可以返回执行所需明文联系方式。

正式包内置 OmniAuto 来源：

```text
deliverables/omniauto-add-friend-rpa-pr-candidate-20260618.zip
```

打包后预期内置路径：

```text

```

## 9. 已知问题 / 待确认

- Windows + 微信桌面端真实 RPA 已通过 1 次闭环验证，但仍需测试工程师进行专项回归和多环境复测。
- 不同 Windows 分辨率、DPI 缩放、多屏幕、微信窗口位置可能影响 OmniAuto 点击定位，需通过 OmniAuto 报告中的窗口 bounds、OCR items、候选目标、最终点击点排查。
- 若发现鼠标坐标不准，应在 OmniAuto 仓库修复定位逻辑，再产出新的 OmniAuto RPA 候选包；Worker 只升级内置 OmniAuto 包，不在 Worker 内部维护微信 UI 坐标规则。
- Vitest worker pool 在本机环境存在启动超时，当前 `npm run test` 已切换为无 worker 的 Node 轻量单测入口；如后续恢复 Vitest，需单独验证 worker pool。
- Windows 打包脚本已改为解压 `omniauto-add-friend-rpa-pr-candidate-20260618.zip`，但尚未在 Windows 实机完成打包校验。
- `ACCOUNT_RESTRICTED` 不主动制造风控场景，需真实触发或专门账号条件下复测。
- `PHONE_NOT_FOUND` 可通过安全号码专项复测。
- 生产环境日志、证据文件保留周期和上传策略【待确认】。
