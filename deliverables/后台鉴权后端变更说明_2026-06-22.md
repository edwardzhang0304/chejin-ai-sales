# 后台鉴权后端变更说明

日期：2026-06-22

状态：后续安全治理跟踪项

## 1. 结论

当前阶段采用后台固定 Admin Token 与 Worker Token 分离的过渡方案，目的不是完成完整账号体系，而是先建立基础安全边界：

- Worker Token 只能访问 Worker 客户端相关接口。
- 后台管理接口不能被 Worker Token 访问。
- 运营后台访问权限与 Worker 机器权限必须隔离。

完整账号登录、角色权限、菜单权限、接口权限和真实账号审计不进入当前 C2 checkpoint，后续应作为单独安全治理专项处理。

## 2. 当前过渡方案

当前阶段保留两类 Token：

| Token 类型 | 用途 | 边界 |
|---|---|---|
| Admin Token | 运营后台访问管理端接口 | 用于测试、联调和阶段性交付 |
| Worker Token | Worker 客户端绑定、心跳、任务领取和结果上报 | 不得访问线索、销售、操作日志等后台管理接口 |

该方案可满足当前联调和基础隔离要求，但不等同于生产级账号权限体系。

## 3. 后续必须跟踪的问题

| 问题 | 当前处理 | 后续要求 |
|---|---|---|
| 后台无真实账号登录 | 暂用 Admin Token | 后续补账号登录、退出、Token 过期 |
| 无角色权限 | 暂不区分管理员、运营、销售主管、只读查看 | 后续设计角色表、权限表、菜单权限和接口权限 |
| 操作日志身份不完整 | 当前只能记录模拟操作人或固定身份 | 后续绑定真实账号 ID、姓名和角色 |
| Token 生命周期弱 | 当前主要服务测试联调 | 后续补过期、刷新、吊销、异常访问处理 |
| 密钥管理 | 当前以环境配置为主 | 后续补生产密钥轮换、泄露处置和告警 |
| 敏感操作审计 | 当前不完整 | 后续对手机号查看、导出、批量操作、分配等增加审计和必要二次确认 |

## 4. 不作为当前阻塞项的原因

当前系统仍在补齐 Worker 客户端、C2 会话绑定/微信监听、RPA 执行链路和运营后台联调。完整权限体系会影响：

- 前端登录页和路由守卫
- 后端用户表、角色表、权限表
- Token 生命周期
- 操作日志身份
- 测试用例
- 部署配置

如果在主业务链路仍频繁调整时同步展开完整权限体系，会增加联调复杂度并带来返工风险。

## 5. 后续立项建议

建议在系统主链路稳定后，单独立项：

```text
账号登录与角色权限体系专项
```

建议范围：

- 管理员 / 运营 / 销售主管 / 只读查看等角色
- 账号登录、退出、Token 过期
- 菜单权限和接口权限
- 操作日志绑定真实账号
- 敏感操作二次确认或审计
- 生产环境密钥轮换和异常访问告警

## 6. 当前项目管理口径

- 当前阶段不因完整账号权限体系未完成而阻塞 C2。
- 当前阶段必须保证 Worker Token 不能访问后台管理接口。
- 后续进入生产化、客户试运行或多人运营前，必须重新评估并排期账号权限专项。
