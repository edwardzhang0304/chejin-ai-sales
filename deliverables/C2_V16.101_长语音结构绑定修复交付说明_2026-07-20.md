# C2 V16.101 长语音结构绑定修复交付说明

## 结论

V16.100 的 23 秒语音不是 OCR 没识别出来，而是 OmniAuto 在转写后仍用转写前的顶部坐标寻找同一条语音。正文展开使气泡顶部从 `352` 移到 `188`，超过旧规则允许的 `112px`，因此完整正文被错误拒绝，Worker 只能上报三条初读文字。

V16.101 已修复该根因，并增加 Worker 矛盾门禁。Windows 真实微信仍需回归，当前不能仅凭本机自动化测试判定 C2 通过。

## 修改内容

1. OmniAuto 的转写后绑定改为结构匹配：发送方、左右通道、语音时长、气泡纵向重叠或邻接、候选唯一性。
2. 删除跨帧顶部坐标最大偏移门槛；页面因展开正文发生位移时不再误判为另一条消息。
3. 多个候选同时满足时仍阻断，不靠最近坐标猜测。
4. Worker 检测到“完整语音正文存在、但 `transcribed_messages` 为空”时，返回 `VOICE_TRANSCRIPT_BINDING_INCONSISTENT`，禁止该授权轮次退化为部分文字上报。
5. 不新增物理点击、截图、OCR、滚动或后端接口。

2. 确认 23 秒语音转写后生成一条 `voice`，正文完整，`frame_source=final_read`。
3. V3 `messages` 应包含连续的 `screen_order=1,2,3,4`，不得再次只有 `1,3,4`。
4. 语音展开导致页面位移后，不应重复右键、不应滚动、不应点击头像或空白处。
5. 若制造多个结构歧义候选，应明确阻断，不得把正文绑到错误语音。
6. 群聊/unknown、图片旧入口、停止监听和去重需做一轮基本回归，确认未受影响。
