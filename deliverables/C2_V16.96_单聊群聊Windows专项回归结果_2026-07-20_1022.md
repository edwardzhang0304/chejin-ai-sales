# C2 V16.96 单聊/群聊 Windows 专项回归结果

## 1. 测试结论

**结论：部分通过，暂不能判定 V16.96 单聊/群聊专项整体通过。**

按本轮缩小后的范围，仅验证单聊准入和群聊阻断，不验证语音、图片等消息类型。

1. **普通单聊准入：通过。** 当前打开 `CJTEST01` 单聊后，Worker 进入 `visible_hit_message_read` 并成功读取入库。
2. **唯一群聊安全阻断：通过。** 当前打开顶部标题为 `CJTEST01 (6)` 的群聊，Worker 未进入消息读取，`message_events` 新增 0。
3. **群聊当前已打开时的执行路径：不符合预期。** 在无人工干预的干净轮次中，Worker 仍打开搜索框搜索 `CJTEST01`，没有直接依据当前顶部标题完成群聊判定和阻断。
4. **单聊与群聊同短码时自动选择单聊：未通过。** 两者都叫 `CJTEST01` 且当前打开群聊时，Worker 没有切换到同码单聊，也没有进入读取；人工先打开单聊后才可正常读取。
5. 服务端没有收到 Windows 本地 `raw_title / conversation_type / conversation_type_reason`，因此只能确认群聊未被读取，不能确认“不点击搜索结果”具体是由群聊识别规则触发，还是其他定位失败导致。

## 5. 问题记录

### BUG-C2-V1696-TITLE-001

**标题：** 当前群聊已经打开时仍进入短码搜索，未直接使用顶部标题完成群聊阻断。

**严重等级：** P1

**前置条件：**

- V16.96 Worker 在线。
- 单聊已改名为 `CJONE001 许聪`，不包含 `CJTEST01`。
- 群聊名称为 `CJTEST01`，顶部真实标题为 `CJTEST01 (6)`。
- 群聊在左侧第一屏且当前已经打开。

**复现步骤：**

1. 保持 `CJTEST01 (6)` 群聊为当前会话。
2. 开启 `CJTEST01` C2 监听。
3. 全程不操作 Windows 微信。
4. 观察 Worker 是否直接判定当前群聊，是否打开搜索框。

**实际结果：**

1. Worker 持续处于 `target_chat_locating` 约 40.53 秒。
2. Windows 现场看到搜索框被打开并搜索 `CJTEST01`。
3. 搜索结果没有被点击，群聊没有被读取或入库。

**预期结果：**

1. 使用当前页面顶部标题 OCR 识别 `CJTEST01 (6)`。
2. 判定 `conversation_type=group` 并在读取前阻断。
3. 当前群聊已明确时不应再次打开搜索框。

**影响范围：** 群聊安全边界最终守住，但多走搜索流程，增加耗时和微信 UI 操作风险；也无法从服务端证明顶部标题 OCR 分支实际生效。

### BUG-C2-V1696-TITLE-002

**标题：** 单聊和群聊使用同一短码时，当前停留群聊无法自动选择唯一单聊。

**严重等级：** P1

**复现步骤：**

1. 将单聊和群聊都命名为 `CJTEST01`，并放在左侧第一屏。
2. 当前打开 `CJTEST01` 群聊。
3. 开启 C2 监听并保持 Windows 无人工操作。

**实际结果：** Worker 未切换到单聊，未进入消息读取。首屏扫描统计曾显示 `private_candidate_count=2 / group_excluded_count=0`。

**预期结果：** 群聊不参与 private 唯一性判断；唯一同码单聊应被安全选中并准入。

**影响范围：** 客户单聊与群聊同短码时，合法单聊可能无法被读取。
