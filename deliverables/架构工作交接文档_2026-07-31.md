## 3. 三层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| OmniAuto | 微信观察与操作、OCR、语音转写、图片事务、Vision/Brain 通用合同和证据 | 车金授权、会话业务状态、任务中心、数据库和最终去重 |
| Worker | read-target 准入、单会话 UI 锁、顺序、稳定消息身份、Outbox、三层合同映射 | 自己生成授权、回复文案或第二套 Vision/Brain 结果 |
| 后端 | 授权、conversation、批次、任务、reply_action、状态机、持久化和最终去重 | 重做微信角色、语音父子、图片位置或消息顺序判断 |

## 4. 已冻结流程

```text
首屏事实扫描
→ 后端返回当前read-target授权
→ private + 有效短码 + revision准入
→ 文字/语音/图片建立统一槽位和身份
→ 只有NEW事实执行物理动作
→ V3 ingest/Outbox
→ 后端形成message_batch
→ Brain/Guard生成reply_action
→ 仍持有当前会话锁的C2 flow执行发送并sent-ack
```

- 不点击“开始接单”时，可保留首屏事实扫描；不得执行定向读取、媒体操作、入库或
  发送。
- PID/剪贴板 owner 不是图片业务身份，不得恢复为硬门禁。
- 图片和语音共用 `media_fact` 恢复协议；事实结算与 UI 授权、状态机推进分离。
- 通用 OmniAuto 改动继续先进入上游；车金只保留业务适配，禁止重新制造内嵌分叉。

- OmniAuto 通用逻辑再次只存在车金内嵌副本，或来源记录与真实代码不一致。

- 合同/schema/生成物不同步，或测试靠永久 skip 通过。
