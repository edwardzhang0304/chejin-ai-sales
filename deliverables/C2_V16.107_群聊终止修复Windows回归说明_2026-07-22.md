## 本次修复

V16.106 实机日志证明，客户端已正确识别右侧标题 `CJTEST01 (6)` 为群聊，但 `open_chat` 漏掉了群聊的立即终止分支，继续点击左侧会话并进入短码搜索。

V16.107 改为：

1. 现有右侧标题 OCR 确认“目标短码 + group”后，在 OmniAuto `open_chat` 内立即终止。
2. “目标短码 + unknown”同样立即终止，不默认为 private。
3. 终止证据直接传给外层，返回 `C2_GROUP_CHAT_NOT_ALLOWED` 或 `C2_CONVERSATION_TYPE_UNKNOWN`。
4. Worker 将上述错误作为定位终止态，不再点击左侧、不再打开搜索框。
5. 当前右侧不是目标短码时，仍保留“首屏候选 -> 短码搜索”正常定位能力。
6. 未新增截图、OCR、坐标、点击、HTTP 接口或数据库迁移。

## 必测项

1. 客户端必须显示 `V16.107`。
2. 打开带半角人数后缀的群聊 `CJTEST01 (6)` 后开启监听：必须立即阻断，不再点击左侧，不打开搜索框。
3. 全角人数后缀 `CJTEST01（6）` 结果必须相同。
4. 群聊阻断后不得进入 `visible_hit_message_read`、`voice_transcribe_current_chat`、`messages/ingest` 或回复状态机。
5. 当前停在其他会话，目标 private 单聊在首屏：应点击唯一目标并进入正确会话。
6. 目标 private 单聊不在首屏：仍应使用短码搜索定位，不得被本次群聊阻断误伤。
7. private 单聊的文字、语音、V3 顺序、去重和停止监听做一轮基本回归。
