# AI 智能客服售前跟进系统 测试交接说明 v0.1

> 交接日期：2026-06-02  
> 交接范围：P0 运营后台联调可测版本

## 1. 结论

当前版本可以转测试工程师进行第一轮 P0 测试。测试目标不是验收最终生产系统，而是验证“人工新增客户线索、去重、轮询分配、线索状态流转、审计、导出、销售轮询配置”这一条核心业务链路是否闭环。

测试时请优先记录：

- 功能是否可用。
- 接口返回是否正确。
- 页面状态是否同步。
- 错误提示是否清晰。
- 操作日志是否留下审计记录。

## 3. 当前已知限制

- 当前鉴权是开发态 Header 模拟，不是真实登录态。
- 前端是静态 HTML + 原生 JS 联调版，不是正式工程化 SPA。
- 操作人名称暂不通过中文 Header 传递，避免 Header 编码导致日志乱码。
- `.env` 可选；开发环境不创建 `.env` 也能跑。
- 批量导入 Excel/CSV 不在 P0 范围，本阶段只测人工新增客户线索。
- 如果后端未启动，前端会回落到静态预览并提示后端未连接，此时不能作为真实功能测试结果。

## 5. P0 测试用例

### TC-001 默认进入空白工作区

步骤：

1. 打开 `ops-admin.html`，不带 `module` 参数。
2. 观察右侧工作区。

期望：

- 左侧没有默认选中的模块。
- 右侧显示“请选择左侧模块”。
- 不自动进入线索管理。

### TC-002 进入线索管理并加载真实列表

步骤：

1. 点击左侧“线索管理”。
2. 观察指标卡、线索列表、详情抽屉。

期望：

- 页面请求真实后端数据。
- 列表总数与 `/api/leads` 返回一致。
- 第一条线索详情自动显示。
- 没有 loading 卡死。

### TC-003 人工新增客户线索

步骤：

1. 点击“新增客户”。
2. 输入客户名称、手机号、微信、备注、自定义信息。
3. 点击“保存”。

期望：

- 弹窗提交成功。
- toast 显示“客户线索已新增”。
- 列表总数 +1。
- 新线索出现在列表。
- 状态为“已分配”或“未分配”，取决于是否有可用销售。

### TC-004 手机号重复预查

步骤：

1. 打开“新增客户”弹窗。
2. 输入已存在手机号。
3. 观察重复手机号提示。

期望：

- 弹窗内“重复手机号提示”区域更新。
- 可提示原线索客户、销售或重复信息。
- 保存时后端仍会进行事务内查重。

### TC-005 保存时重复手机号查重

步骤：

1. 使用已存在手机号新增客户。
2. 点击“保存”。

期望：

- 不创建新线索。
- 返回重复错误。
- 页面展示重复提示。
- 原线索重复次数或重复记录可追溯。
- 操作日志中可看到重复相关记录。

### TC-006 自动轮询分配

步骤：

1. 确保至少有启用且参与轮询的销售。
2. 新增一条不重复手机号的线索。
3. 查看列表和详情。

期望：

- 线索自动分配给销售。
- 详情中显示当前销售。
- 任务链路显示“轮询分配完成”。
- `/api/leads/{id}/assignments` 有分配记录。

### TC-007 无可用销售时分配失败

步骤：

1. 在销售管理中关闭所有销售的参与轮询，或停用销售。
2. 新增一条线索。
3. 查看线索状态和分配信息。

期望：

- 线索保持未分配。
- 分配失败原因可见。
- 任务链路显示分配失败。
- 修复销售配置后可点击“重新分配线索”。

### TC-008 重新分配线索

步骤：

1. 选择一条未分配线索。
2. 点击“重新分配线索”。

期望：

- 触发 `/api/leads/retry-auto-assign`。
- 有可用销售时分配成功。
- 列表和详情状态刷新。
- 操作日志记录重新分配。

### TC-009 标记无效

步骤：

1. 打开线索详情。
2. 点击“标记无效”。
3. 选择无效原因，输入补充说明。
4. 点击“确认标记无效”。

期望：

- 线索状态变为“无效”。
- toast 显示“已标记为无效线索”。
- 无效线索不再参与自动分配。
- 操作日志记录标记无效。

### TC-010 恢复有效

步骤：

1. 在列表中找到无效线索。
2. 点击“恢复有效”。
3. 点击“确认恢复有效”。

期望：

- 如存在当前销售，状态恢复为“已分配”。
- 如不存在当前销售，状态恢复为“未分配”。
- toast 显示“已恢复为有效线索”。
- 操作日志记录恢复有效。

### TC-011 批量选择与批量标记无效

步骤：

1. 勾选多条线索。
2. 点击批量操作区“标记无效”。
3. 提交无效原因。

期望：

- 已选数量正确。
- 多条线索状态变为无效。
- 接口 `/api/leads/batch-mark-invalid` 返回成功。
- 操作日志逐条记录或带 batch metadata。

### TC-012 导出选中线索

步骤：

1. 勾选至少一条线索。
2. 点击“导出”。

期望：

- 下载 CSV。
- 手机号为脱敏值，不导出明文手机号。
- 操作日志记录 `leads_exported`。
- 未选择线索时提示“请选择要导出的线索”。

### TC-013 手机号明文查看与审计

步骤：

1. 打开线索详情。
2. 在联系方式里点击“查看完整”。
3. 输入查看原因。

期望：

- 页面显示完整手机号。
- toast 提示已写入审计日志。
- `/api/operation-logs?event_type=phone_revealed` 可查询到记录。
- 日志 metadata 记录查看原因和手机号后四位，不记录完整手机号。

### TC-014 销售管理加载

步骤：

1. 点击左侧“销售管理”。
2. 查看销售卡片。

期望：

- 销售卡片来自 `/api/sales`。
- 展示销售姓名、启用/停用、是否参与轮询、排序、名下线索数。
- 名下线索数与新增/分配结果同步。

### TC-015 销售轮询开关

步骤：

1. 在销售卡片中切换“参与轮询”。
2. 再次刷新销售管理页。

期望：

- 开关状态保存。
- 操作日志记录 `sales_round_robin_changed`。
- 不会把脱敏手机号写回后端导致手机号数据被污染。

### TC-016 筛选与分页

步骤：

1. 在线索管理中输入关键词。
2. 切换状态筛选、销售筛选。
3. 切换每页条数。
4. 点击分页按钮。

期望：

- 请求参数包含 `keyword/status/sales_id/page/page_size`。
- 列表与总数正确刷新。
- 空结果时显示可理解的空状态。

### TC-017 后端未启动兜底

步骤：

1. 停止 Docker 后端。
2. 打开前端页面。
3. 点击线索管理。

期望：

- 页面不白屏。
- 保留静态预览。
- toast 提示后端服务未连接。
- 不把静态预览误判为真实接口测试通过。
