# AI智能客服售前跟进系统 PRD

版本：v0.1

模块：线索导入与线索分配

日期：2026-06-02

阶段：设计阶段第一步

范围说明：本版只覆盖运营后台的线索人工录入、线索列表、线索详情、线索分配以及服务端相关内容。批量导入仅作为非必做能力预留，暂不进入第一阶段必做范围。暂不做 RPA 自动添加微信好友，暂不做 AI 自动回复、自动召回和飞书接管。

## 1. 一句话结论

第一阶段先把“客户线索录入、去重、沉淀、分配给销售”做扎实，让后续加微信、AI 跟进、人工接管都能基于一条可追踪的线索继续流转。

## 2. 需求背景

当前第一阶段线索全部由运营人工录入。系统正式进入设计阶段后，需要先建立线索基础数据和分配能力。

本阶段不做自动加微信，原因是 RPA 加好友依赖微信环境、账号状态和执行器稳定性，应在“线索可管理、可分配、可追踪”完成后再接入。

本阶段完成后，运营或管理员可以先人工录入客户线索；系统按轮询规则自动分配给销售，销售后续可人工跟进。

## 3. 用户与场景

| 用户角色 | 使用场景 | 核心诉求 |
|---|---|---|
| 管理员 | 管理全部线索、销售、轮询规则和分配记录 | 数据完整、规则可控、能追踪 |
| 运营 | 人工新增线索、补充备注、查看分配结果 | 操作简单、错误可见、支持连续录入 |
| 销售 | 接收分配给自己的线索 | 知道客户是谁、从哪里来、怎么联系 |
| 技术/实施 | 对接后续服务端能力 | 数据结构稳定、状态清晰、可扩展 |

## 4. 产品目标

### 4.1 本阶段目标

- 支持手机号必填的人工新增客户线索。
- 支持线索去重、重复强提示、重复录入次数和重复日期记录。
- 支持重复手机号不新建线索，但将本次备注追加到原线索备注记录。
- 支持线索按销售轮询规则自动分配。
- 支持线索列表、详情和分配记录查看。
- 服务端建立标准线索数据模型，为后续 RPA、AI、召回模块预留状态和字段。

### 4.2 成功指标

| 指标 | 验收口径 |
|---|---|
| 人工新增成功 | 填写必填信息后，可成功创建线索并在线索列表看到 |
| 去重有效 | 相同手机号重复录入时不会创建多条有效线索 |
| 重复提示有效 | 重复手机号保存时提示已有线索、重复次数和重复日期 |
| 分配有效 | 新增线索可按轮询规则自动分配给启用销售，分配后状态和记录可见 |
| 错误可见 | 字段错误、重复录入、销售不可用等原因可见 |
| 数据可追踪 | 每条线索有创建人、创建时间、分配记录、备注记录和状态 |

## 6. 业务对象与状态

### 6.1 名词约定

| 名词 | 说明 |
|---|---|
| 客户 | 前台页面对用户可见的叫法，贴近附件中的“新增客户” |
| 线索 Lead | 服务端核心对象，一条客户售前跟进记录 |
| 联系方式 | 手机、微信、邮箱等可联系客户的信息 |
| 来源 | 第一阶段固定为人工录入，页面不展示来源配置 |
| 销售 | 负责跟进线索的人 |
| 分配 | 将线索指定给某个销售 |

### 6.2 线索状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| unassigned | 暂无可用销售，系统未能自动分配 | 编辑、触发重新分配线索、标记无效 |
| assigned | 已按轮询规则分配销售 | 编辑、标记无效 |
| invalid | 无效线索 | 查看、恢复 |

说明：本阶段不进入 `add_friend_pending`、`ai_chatting`、`watching` 等后续自动化状态。

### 6.3 分配状态

| 状态 | 含义 |
|---|---|
| unassigned | 未分配销售 |
| assigned | 已分配销售 |
| assign_failed | 无可用销售或分配失败 |

分配状态可由线索当前销售字段、分配失败原因和分配记录共同表达。

### 6.4 无效状态规则

线索被标记为无效时，不再进入销售轮询分配。无效状态不再细分更多状态，通过无效原因字段记录业务原因。

无效原因：

| 无效原因 | 说明 |
|---|---|
| 空号 | 手机号为空号、停机或不可联系 |
| 信息错误 | 手机号、客户名称或其他关键信息明显错误 |
| 非目标客户 | 不符合本业务跟进范围 |
| 测试数据 | 内部测试或演示数据 |
| 重复/误录 | 运营误录或确认属于重复无效数据 |
| 其他 | 以上原因均不适用 |

标记无效需记录：

- `invalid_reason`
- `invalid_remark`
- `invalid_at`
- `invalid_by`

恢复规则：

- 如果线索存在当前销售 `sales_id`，恢复后状态为 `assigned`。
- 如果线索不存在当前销售，恢复后状态为 `unassigned`，并可触发重新分配线索。
- P0 不记录无效前状态，不按无效前状态恢复。

## 7. 人工新增客户

### 7.1 页面入口

入口建议：

- 线索列表页右上角：`新增客户`

### 7.2 弹窗结构

参考附件，弹窗标题为 `新增客户`。

弹窗分区：

1. 基础信息
2. 自定义信息
3. 底部操作区

底部按钮：

- 取消
- 保存
- 保存并新建联系人

按钮文案建议：附件中是“保存并新建联系人”。本系统建议改为“保存并继续新增”，更符合线索连续录入场景。

### 7.3 字段说明

| 字段 | 类型 | 是否必填 | 规则 | 说明 |
|---|---|---|---|---|
| 客户名称 | 文本 | 是 | 1-50 字 | 可填真实姓名、昵称或客户称呼 |
| 手机 | 多值文本 | 是 | 默认中国大陆手机号 11 位；支持多个 | 手机是线索唯一识别和后续加微信的重要字段 |
| 微信 | 多值文本 | 否 | 2-64 字，去除首尾空格 | 支持微信号、微信昵称或备注号 |
| 邮箱 | 多值文本 | 否 | 标准邮箱格式 | 一期仅记录，不参与去重主键 |
| 备注 | 多行文本 | 否 | 0-1000 字 | 记录客户需求、车型、预算等 |
| 自定义信息 | 键值对/动态字段 | 否 | 由配置决定 | 可记录预算、意向车型、城市等 |

必填规则：客户名称和手机号必填。微信、邮箱、备注、自定义信息选填。

### 7.4 多联系方式交互

手机、微信、邮箱字段下方展示 `添加 +`。

规则：

- 点击 `添加 +` 后新增一行输入框。
- 每类联系方式最多 5 条。
- 第一条默认为主联系方式。
- 支持删除新增行。
- 同类联系方式不允许重复。
- 保存时统一去除首尾空格。

P0 暂不做显式主联系方式选择，默认第一条手机号为主手机号，第一条微信为主微信。

### 7.5 保存规则

点击 `保存`：

1. 前端校验必填项和格式。
2. 服务端执行标准化和去重。
3. 如手机号不重复，创建线索和联系方式记录。
4. 如手机号重复，不创建新线索，写入重复录入记录；若本次填写了备注，则追加到原线索备注记录。
5. 关闭弹窗并刷新列表。

点击 `保存并继续新增`：

1. 保存当前线索。
2. 清空表单。
3. 继续停留在新增弹窗，便于连续录入。

### 7.6 异常提示

| 场景 | 提示 |
|---|---|
| 客户名称为空 | 请输入客户名称 |
| 手机为空 | 请输入手机号 |
| 手机格式错误 | 手机号格式不正确 |
| 邮箱格式错误 | 邮箱格式不正确 |
| 联系方式重复 | 该联系方式已填写，请勿重复添加 |
| 系统中已有相同手机号 | 该手机号已存在，不能重复新建。已重复录入 {n} 次，日期：{yyyy-mm-dd}、{yyyy-mm-dd}。本次备注已追加到原线索。 |
| 系统中已有相同微信 | 该微信已存在，请检查是否为同一客户。P0 仅强制拦截手机号重复，微信重复作为提醒。 |

### 7.7 重复手机号处理

手机号是 P0 唯一强去重字段。运营录入时，只要任意手机号命中已有有效线索，系统不得创建新线索。

重复处理规则：

- 服务端返回重复命中的原线索信息：客户名称、主手机号脱敏、当前销售、创建日期、最近更新时间。
- 服务端返回该手机号历史重复录入次数和重复录入日期列表。
- 本次录入如果填写了备注，系统将备注追加到原线索的备注记录中，不覆盖原备注。
- 本次录入的客户名称、微信、邮箱、自定义字段默认不覆盖原线索。
- 页面必须强提示“不能重复新建”，并提供“查看原线索”入口。

重复备注追加格式建议：

```text
[重复录入追加][2026-06-02 14:30][操作人：张三]
本次录入备注：客户说预算 10 万左右，想看 SUV。
```

## 8. 批量导入预留

批量导入不作为第一阶段必做功能。本章仅作为后续预留口径，研发可在数据结构和接口上保留扩展空间，页面第一阶段不需要实现。

### 8.1 预留入口

左侧导航展示置灰的 `批量导入` 模块入口，线索管理顶部不展示 `导入线索`。

导入页包含：

- 下载模板
- 上传文件
- 字段说明
- 导入预校验结果
- 导入历史

### 8.2 模板字段

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 客户名称 | 是 | 客户姓名、昵称或称呼 |
| 手机 | 是 | 多个手机号用英文逗号分隔 |
| 微信 | 否 | 多个微信用英文逗号分隔 |
| 邮箱 | 否 | 多个邮箱用英文逗号分隔 |
| 备注 | 否 | 客户需求或线索备注 |
| 意向车型 | 否 | 自定义字段 |
| 预算 | 否 | 自定义字段 |
| 城市 | 否 | 自定义字段 |

必填规则：客户名称、手机号必填。

### 8.3 导入流程

```text
下载模板 -> 填写线索 -> 上传文件 -> 系统预校验 -> 展示错误/重复/可导入数量 -> 用户确认导入 -> 生成导入批次 -> 创建线索 -> 下载结果
```

### 8.4 导入结果

导入完成后展示：

- 总行数
- 成功数
- 失败数
- 重复数
- 跳过数
- 导入批次号
- 操作人
- 导入时间
- 下载导入结果

导入结果文件需包含每行处理结果：

- 成功
- 失败原因
- 重复原线索 ID
- 标准化后的手机号/微信

### 8.5 导入失败规则

| 场景 | 处理 |
|---|---|
| 缺少客户名称 | 该行失败 |
| 手机为空 | 该行失败 |
| 手机格式错误 | 该行失败 |
| 与系统已有手机号重复 | 不创建新线索；标记重复；备注追加到原线索备注记录 |
| 与本批次前面行重复 | 默认跳过，并标记批次内重复 |
| 单元格超长 | 该行失败 |

说明：批量导入正式实现时，也必须遵守手机号强去重和备注追加规则。

## 9. 运营后台框架

## 12. 线索详情抽屉

### 12.1 打开方式

线索详情采用右侧抽屉展示，不跳转独立详情页。

打开方式：

- 点击线索列表中的客户名称。
- 点击单条操作中的 `查看详情`。

交互规则：

- 打开抽屉后，左侧列表保持当前筛选、分页和滚动位置。

## 13. 线索分配

### 13.1 分配方式

第一阶段采用系统轮询自动分配，不提供运营手动选择销售的分配入口。

触发时机：

- 人工新增客户保存成功且手机号不重复时，系统立即触发轮询分配。
- 批量导入后续实现时，每条成功创建的线索也按同一轮询规则自动分配。
- 如果首次分配失败，管理员可点击 UI 按钮 `重新分配线索`，实际仍由系统重新轮询分配，不手动选择销售。

### 13.2 可分配销售条件

销售必须满足：

- 销售状态为启用。
- 未被删除。
- 有销售姓名。

本阶段不要求销售绑定 Worker，因为暂不做 RPA 自动加微信。

### 13.3 轮询规则

默认轮询规则：

- 系统维护一个全局轮询指针。
- 可分配销售按 `sort_order asc, sales_id asc` 排序。
- 每创建一条新线索，分配给当前指针指向的可用销售。
- 分配成功后，轮询指针移动到下一位可用销售。
- 停用销售不参与轮询。
- 如果销售被停用，不影响其历史已分配线索。
- 如果只有 1 个启用销售，所有新线索分配给该销售。
- 如果没有启用销售，线索保持 `unassigned`，记录分配失败原因。

示例：

```text
启用销售：A、B、C
线索 1 -> A
线索 2 -> B
线索 3 -> C
线索 4 -> A
```

### 13.4 分配失败处理

分配失败场景：

- 无启用销售。
- 销售数据异常。
- 系统并发锁获取失败或服务端异常。

失败处理：

- 线索状态保持 `unassigned`。
- 写入分配记录，状态为 `failed`。
- 线索列表展示分配失败原因。
- 管理员修复销售配置后，可点击 `重新分配线索`。

### 13.5 分配记录

每次自动分配或分配失败都写入记录：

| 字段 | 说明 |
|---|---|
| assignment_id | 分配记录 ID |
| lead_id | 线索 ID |
| from_sales_id | P0 为空，后续如支持重新分配再使用 |
| to_sales_id | 被分配销售；失败时为空 |
| assignment_type | round_robin、retry_round_robin |
| assignment_status | succeeded、failed |
| failure_reason | 失败原因 |
| round_robin_cursor_before | 分配前轮询指针 |
| round_robin_cursor_after | 分配后轮询指针 |
| operator_id | 系统自动分配为空；点击“重新分配线索”时记录触发人 |
| remark | 系统备注 |
| created_at | 分配时间 |

### 17.2 去重规则

去重优先级：

1. 手机号标准化后完全一致。
2. 微信不作为 P0 强去重键，只做潜在重复提示。
3. 邮箱不作为 P0 主去重键，只做潜在重复提示。

规则：

- 同一条线索内多个手机号，任意一个命中已有有效线索，则判定重复。
- invalid 状态参与潜在重复提示，但不强拦截。
- 号码标准化后写入 `contact_hash`，避免明文手机号直接做唯一索引。
- 重复手机号不创建新线索。
- 重复手机号必须写入 `lead_duplicate_events`。
- 重复手机号如填写备注，必须写入 `lead_notes`，`note_type=duplicate_append`。
- 原线索 `duplicate_count` 加 1，`last_duplicate_at` 更新为当前时间。

### 17.3 权限规则

本阶段建议只做轻量权限：

| 角色 | 权限 |
|---|---|
| 管理员 | 全部功能 |

| 只读 | 只能查看线索 |

- 管理员可查看完整手机号。
- 运营默认查看脱敏手机号，点击查看完整手机号需记录日志。

## 19. 页面验收标准

### 19.1 运营后台框架

- 进入后台后，左侧展示有权限的模块。
- 右侧默认空白，并提示选择左侧模块开始操作。
- 左侧 `线索管理`、`销售管理`、`操作日志` 可进入。
- 左侧 `批量导入`、`AI 跟进` 置灰不可用。

### 19.2 人工新增

- 客户名称必填。
- 手机号必填。
- 手机、微信、邮箱支持添加多条。
- 保存后列表出现新线索。
- 重复手机号不创建新线索，并强提示已有线索、重复次数和重复日期。
- 重复手机号录入时，本次备注会追加到原线索备注记录。
- 保存并继续新增后，表单清空并停留在新增弹窗。

### 19.3 批量导入预留

- 批量导入不纳入第一阶段页面验收。
- 后续实现时，必须遵守手机号必填、手机号强去重、重复手机号不新建、备注追加到原线索的规则。

### 19.4 线索列表

- 线索管理顶部展示今日新增、已分配、未分配、重复录入概览卡片。
- 支持按状态、销售、时间筛选。
- 支持按客户名称、手机号后四位、微信搜索。
- 展示轮询分配结果和分配失败原因。
- 手机号默认脱敏。
- 无效线索可通过状态筛选查看。
- 支持分页，包含总条数、每页条数、页码、上一页、下一页。

### 19.5 线索详情抽屉

- 点击客户名称或查看详情时，从右侧打开详情抽屉。
- 打开详情抽屉后，线索列表筛选、分页和滚动位置不丢失。
- 详情抽屉展示基础信息、联系方式、分配信息、分配记录、重复录入记录、任务链路和操作日志。
- 任务链路至少能展示手机号去重、轮询分配、重复备注追加、标记无效、恢复有效等关键节点。

### 19.6 无效线索

- 标记无效时必须选择无效原因。
- 无效原因支持空号、信息错误、非目标客户、测试数据、重复/误录、其他。
- 标记无效时可填写无效备注。
- 标记无效后记录 `invalid_reason`、`invalid_remark`、`invalid_at`、`invalid_by`。
- 恢复无效线索时，如存在当前销售，恢复为已分配。
- 恢复无效线索时，如不存在当前销售，恢复为未分配。

### 19.7 线索分配

- 新增线索保存成功后，系统自动按轮询规则分配给启用销售。
- 停用销售不参与新线索轮询分配。
- 多个销售启用时，新线索按轮询顺序依次分配。
- 无可用销售时，线索保持未分配，并展示分配失败原因。
- 管理员修复销售配置后，可以点击“重新分配线索”处理未分配线索。
- 每次自动分配成功或失败都有分配记录。

### 19.8 操作日志

- 点击左侧 `操作日志` 后，右侧展示操作日志列表。
- 无日志时展示空状态，不展示空白页面。
- 日志列表展示操作时间、操作人、操作类型、操作对象、对象名称、结果和说明。
- 支持按操作时间、操作人、操作类型、操作对象、结果筛选。
- 支持按客户名称、销售姓名、手机号后四位、说明搜索。
- 点击日志行可查看日志详情。
- 新增客户、编辑线索、标记无效、恢复线索、重复手机号录入、追加备注、轮询分配、重新分配线索、启用/停用销售、查看完整手机号均应产生日志。

## 22. P1a：Mac Worker 基础链路

P1a 是 P0 之后的串行阶段。本阶段只做 Worker 管理、统一任务列表、任务详情、任务状态、人工回传成功/失败和异常原因，不做真实 RPA、AI、飞书和召回。

### 22.1 P1a 范围

| 模块 | 做什么 |
|---|---|
| Worker 管理 | 管理 Mac Worker，查看在线状态、启用/停用、当前任务、最近心跳 |
| 统一任务列表 | 查看任务、筛选任务、查看任务状态和失败原因 |
| 任务详情 | 查看任务基础信息、线索信息、销售信息、Worker 信息、状态流转 |
| 任务状态 | 明确任务从创建到完成/失败/取消的状态 |
| 人工回传 | 人工点击回传成功或失败 |
| 异常原因 | 定义失败原因枚举和备注规则 |

### 22.2 P1a 不做

- 不做真实 RPA 自动添加微信好友。
- 不操作微信客户端。
- 不验收真实微信自动加好友。
- 不做 AI 自动回复。
- 不做图片识别。
- 不做飞书通知。
- 不做自动召回。
- 不要求 Worker 自动判断任务是否真实完成。
- 不要求 Worker 自动识别微信状态。
- 不要求截图取证。

### 22.3 P1a 主流程

```text
线索已创建并已分配销售
-> 后台创建任务
-> 任务进入 pending
-> Mac Worker 上线并领取/查看任务
-> 任务进入 running
-> 人工处理实际动作
-> 人工回传成功或失败
-> 后台展示任务最终状态、失败原因和操作记录
```

说明：P1a 的成功/失败来自人工回传，系统不自动验证微信动作是否真实完成。

### 22.4 Worker 管理

P1a 的 Worker 是 Mac 端执行入口，用于展示任务和人工回传结果。

Worker 状态：

| 状态 | 含义 |
|---|---|
| enabled | Worker 启用，可领取/查看任务 |
| disabled | Worker 停用，不再领取新任务 |
| online | 最近心跳正常 |
| offline | 超过心跳阈值未上报 |
| idle | 在线且无当前任务 |
| busy | 在线且存在 running 任务 |

Worker 列表字段：

| 字段 | 说明 |
|---|---|
| Worker 名称 | 设备或执行端名称 |
| Worker 编号 | 系统生成 ID |
| 管理状态 | 启用/停用 |
| 在线状态 | 在线/离线 |
| 运行状态 | 空闲/忙碌 |
| 当前任务 | 当前 running 任务 ID |
| 最近心跳 | 最近一次心跳时间 |
| 创建时间 | Worker 创建时间 |
| 备注 | 管理备注 |

Worker 操作：

- 新增 Worker
- 编辑 Worker
- 启用 Worker
- 停用 Worker
- 查看 Worker 详情

### 22.5 统一任务列表

P1a 先支持一种任务类型：

| task_type | 页面文案 | 说明 |
|---|---|---|
| add_friend_manual | 加好友任务 | 人工按线索信息处理，人工回传结果 |

说明：这里的“加好友任务”只是任务类型名称，不代表系统自动加微信。

任务状态：

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| pending | 待处理，尚未被 Worker 领取/查看 | 取消 |
| running | 处理中，Worker 已领取/开始处理 | 回传成功、回传失败、取消 |
| succeeded | 已人工回传成功 | 查看 |
| failed | 已人工回传失败 | 查看、重新创建任务 |
| cancelled | 已取消 | 查看 |

状态流转：

```text
pending -> running -> succeeded
pending -> running -> failed
pending -> cancelled
running -> cancelled
failed -> pending，新建一条重试任务，不复用原任务
```

规则：

- `succeeded`、`failed`、`cancelled` 是终态。
- 终态任务不可再次回传。
- 失败后如需重试，创建新任务，原任务保留。
- P1a 不做自动超时失败，可在后台展示长时间 running。

任务列表字段：

| 字段 | 说明 |
|---|---|
| 任务 ID | 系统生成 |
| 任务类型 | 加好友任务 |
| 任务状态 | pending、running、succeeded、failed、cancelled |
| 客户名称 | 来源线索 |
| 手机号后四位 | 脱敏展示 |
| 销售 | 线索当前销售 |
| Worker | 当前处理 Worker |
| 失败原因 | failed 时展示 |
| 创建时间 | 任务创建时间 |
| 开始时间 | 进入 running 时间 |
| 完成时间 | succeeded/failed 时间 |

任务筛选：

- 任务状态
- 任务类型
- 销售
- Worker
- 创建时间
- 失败原因
- 关键词：客户名称、手机号后四位、任务 ID

### 22.6 任务详情

任务详情展示：

| 区域 | 内容 |
|---|---|
| 任务基础信息 | 任务 ID、任务类型、任务状态、创建时间 |
| 线索信息 | 客户名称、手机号后四位、微信、备注 |
| 销售信息 | 销售姓名、销售微信、销售手机号 |
| Worker 信息 | Worker 名称、在线状态、最近心跳 |
| 状态流转 | pending、running、succeeded/failed/cancelled 时间线 |
| 回传结果 | 成功/失败、失败原因、回传备注、回传人、回传时间 |
| 操作日志 | 创建任务、领取任务、回传成功/失败、取消任务 |

任务详情操作：

| 操作 | 条件 |
|---|---|
| 取消任务 | pending 或 running |
| 回传成功 | running |
| 回传失败 | running |
| 重新创建任务 | failed |

### 22.7 人工回传

回传成功：

- 点击 `回传成功`。
- 弹出确认框。
- 可填写成功备注。
- 确认后任务状态变为 `succeeded`。
- 记录回传人和回传时间。

回传失败：

- 点击 `回传失败`。
- 必须选择失败原因。
- 必须填写失败备注。
- 确认后任务状态变为 `failed`。
- 记录回传人和回传时间。

失败原因：

| failure_reason | 页面文案 | 说明 |
|---|---|---|
| phone_invalid | 手机号无效 | 手机号格式或号码明显错误 |
| phone_not_found | 手机号未找到客户 | 人工处理时无法通过手机号找到客户 |
| already_friend | 已是好友 | 已经是微信好友，无需重复处理 |
| customer_rejected | 客户拒绝 | 客户明确拒绝添加或跟进 |
| account_limited | 账号受限 | 人工发现账号、平台或环境受限 |
| worker_unavailable | Worker 不可用 | Worker 离线、停用或无法处理 |
| lead_info_incomplete | 线索信息不完整 | 缺少必要信息 |
| manual_operation_failed | 人工操作失败 | 人工尝试后未完成 |
| other | 其他 | 必须填写备注 |

说明：

- 选择 `other` 时，失败备注必填。
- P1a 不自动判断失败原因，失败原因由人工选择。
