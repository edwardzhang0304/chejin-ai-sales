# Hook 0.10.4 客户端更新准入交接

当前状态：源码修复候选。继承灰度基线 `ffc6a97718d4d75f58b9fa90ae601a3132331101`；本次没有打包、部署或修改生产配置。前一版本的安装包及 Windows 证据保留，不冒充本版成品验收。

## 本轮改动

- Worker、包装入口、后台前端、后端、Compose 默认镜像与产品合同统一 0.10.4；C2 v3 / hook-v1 协议结构和业务含义不变。生成 schema 与来源登记摘要同步。
- 设置中的“检查更新”和协调器入口复用 TaskRunner 现有安装安全事实。无在途阻挡时，故障、人工暂停及业务离线可以检查；网络不可用则报告实际请求错误。
- 当前任务、租约、微信操作锁、自动化执行、未知操作结果、待上传和待结算记录会禁用按钮并说明原因。Hook 当前进程的未确认调用及未回传记录也纳入同一判断；经过原环境检查的新微信进程不把旧隔离进程记录当作正在运行，历史记录继续保留。无法读取安全状态时不放行。连接正在重新核验时返回明确等待原因，按钮投影不等待后台心跳持有的连接锁。
- 在新任务原准入锁内完成重新检查、登记请求和关闭新工作入口，按钮缓存不能放行。语音调用和可能启动模型的查询也遵循该锁；已登记流程照原职责收尾。检查进行中拒绝重复请求；无新版本、下载失败或取消只清本次请求的闸门。人工暂停与真实故障不会自动变为接单中。
- 原停止读取恢复交接仍可查询兼容版本；本地只认已有的停止读取证据。实际安装仍要求签名包能力、后台同一流程证明和停止全部旧写入后的再次核对，不能借此放过未知发送或删除旧记录。

## 运维后续验收

以5号通过的最终提交构建一次正式 Windows 包并封存，核对源码、合同、签名和包内清单对应。用最终包验证设置按钮在暂停/故障/离线无阻挡时可点，有在途阻挡时展示原因；模拟断网、重复点击、下载失败及取消，确认原状态和记录保留。验证正常安装、按钮升级和失败回退，不将源码测试视为成品验证。

实际点击生成的“工作微信”和 Worker 快捷方式，核对原部署配置的 EXE、工作目录、`StartPort=<配置端口>`、`ConnectType=http`、`RecvType=0`、组件、端口归属和 Worker 环境检查。仅 Worker 更新且旧写入退出、恢复检查通过时允许微信继续运行；不为了更新而要求无依据重启微信。

后台和后端部署、HTTPS/健康检查及正式包发放由运维单独验收。本次不自动恢复已撤回的旧版本，不清绑定、Flow、未知结果或客户数据来放行。
