# 飞鱼接入当前 Hook 系统

## 范围与代码来源

仅接入飞鱼转交线索的 API、持久收据及必要测试。参考 PR #17 的 `68094f4d3e55576f006d2bc076cab9babe30f708`；候选建立在当前 Hook `d242baa673ad1bed3114f2f2a2042283acf03256` 上，不合并旧程序的其他页面、Worker、AI、恢复流程或旧迁移链。

当前 Hook 已有统一联系方式校验，飞鱼指纹计算复用它；不恢复旧版 `ensure_no_duplicates`。建档、首次备注、轮询分配和加好友任务仍调用原生 `create_lead`。原生入口增加事务级建档锁，使人工录入与飞鱼录入共享手机号防重保护。锁仅用于 PostgreSQL；生产并发保证以 READ COMMITTED 为验证前提，SQLite 测试不构成并发证明。该锁串行化建档事务，未做吞吐压测。

## 交接接口

`POST /api/integrations/feiyu/leads`

请求头：

- `X-Feiyu-Forward-Secret`：服务端配置的独立接入密钥，不是后台管理员凭证。
- `X-Feiyu-Account-ID`：稳定的来源账号标识，必须在服务端白名单中。省略时使用配置默认账号；默认账号也必须在白名单。

配置：`FEIYU_FORWARD_SECRET`、`FEIYU_ACCOUNT_ID`、逗号分隔的 `FEIYU_ACCOUNT_IDS`。密钥未配置时接口拒绝接收。

合成示例：

```json
{
  "customer_name": "测试客户",
  "phones": ["13800000001"],
  "remark": "测试需求",
  "custom_fields": {"feiyu": {"id": "example-clue-001"}}
}
```

必须有有效手机号和稳定线索编号。`custom_fields.feiyu.clue_id` 可作为 `id` 的别名；同时提供时必须相同。不允许外部指定系统 `custom_fields.remark_code`。具体飞鱼拉取、字段转换和失败留存由接收器负责，本候选没有包含接收器实现。

## 首次、重复与拒收

| 请求 | 行为 |
| --- | --- |
| 首次有效线索 | 原生建档、保存首次备注和飞鱼来源、分配销售、生成加好友任务；事务提交后返回结果 |
| 同账号、同编号、同内容重传 | 返回已提交的原回执；不新增备注、重复计数、分配、任务，不推进轮询游标 |
| 同手机号、不同线索编号 | 原生重复录入事件及备注只记一次；保留原客户、销售和首次来源，不新建加好友任务；返回原生 409 重复结果，重传复用此回执 |
| 同编号但联系方式变化 | 409，拒绝写入，不把编号转交给另一个客户 |
| 同编号但姓名、备注等资料变化 | 409，`update_applied=false`；本期不自动更新，不提供 CRM 或人工待办模块。`manual_review_required` 是现有拒绝契约，不能理解为系统已创建人工工单 |
| 缺少编号、越权账号、伪造短码 | 拒收且不写业务数据 |

收到网络超时不代表业务未提交；接收器应保留原账号、原线索编号及原内容重试，不能生成新编号绕过幂等。原生重复录入的 409 与身份冲突/资料变化的 409 要按响应错误码区分。

## 迁移与回退

当前 Hook 单链迁移为 `20261028_0043 → 20261029_0044`。`0044` 新增 `feiyu_lead_receipts`：账号、线索编号、客户外键、联系方式/内容指纹、原始响应状态和响应体、创建时间；账号加线索编号唯一。不会重建已有客户或改写原归属。

不要把旧程序 PR 的 `20261029_0030`、`0031` 迁移文件直接复制进 Hook。候选尚未合并，不可直接将本文命令用于生产发布。

经批准实施时，在备份后、飞鱼流量关闭的条件下，于 `backend` 目录用该部署环境执行 `python -m alembic upgrade head`，确认单 head 为 `20261029_0044`，再配置并开放接入。

回退优先关闭飞鱼入口并回退本次 API 代码，**保留新增表、迁移版本和收据**；恢复接入后同编号仍能复用原结果。存在收据时迁移明确拒绝删表降级。只有测试空表允许降至 `0043`。禁止删收据后重新开放重试流量。

## 本地验收及边界

本地合成数据、专用 PostgreSQL 15、READ COMMITTED、真实回环 HTTP/独立事务：

- 飞鱼契约与原生入口 33 项；真实 HTTP 并发/回滚/重放 9 项（含移除身份锁的负向对照）。
- 新库初始化、现有 `0043` 合成客户升级、全表数据比较、重复升级、收据保护降级及关闭/恢复入口 1 项。
- 当前人工线索入口回归 10 项。
- 共 53 项通过。没有用 SQLite 代替并发证明；没有执行真实微信或发送客户消息。

并发用例包含 10 次同编号同时请求、同手机号不同编号、人工与飞鱼同时录入；事务用例包含新客户与重复客户提交失败、锁持有者回滚、提交后丢弃 HTTP 响应、重建应用/数据库连接后重放。实际调用 Worker 正式任务序列化，核对任务、归属和备注短码。

生产迁移、真实飞鱼接收器字段与重试策略、真实 Worker 领取执行、负载性能尚未验收。回退验证覆盖关闭入口并保留表的行为，未部署旧二进制程序。上述本地通过不等于生产交付通过。

测试文件：`backend/tests/test_feiyu_integration.py`、`test_feiyu_postgresql_http.py`、`test_feiyu_migration.py`。HTTP 测试需 `FEIYU_PG_TEST=1` 且 `DATABASE_URL` 指向回环专用库 `feiyu_verification`；迁移测试需 `FEIYU_MIGRATION_TEST=1` 且专用库 `feiyu_migration`。迁移测试会清空该专用库，禁止使用真实业务库。
