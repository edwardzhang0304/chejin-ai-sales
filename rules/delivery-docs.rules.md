# 文档与交付 Rules

版本：v0.1

日期：2026-06-03

适用对象：项目文档总目录、变更日志、日报、交付物、合同/报价边界、对外资料。

## 1. 文档管理原则

1. `项目文档总目录.md` 是统一入口。
2. `文档变更日志.md` 记录新增、删除、更新、口径调整和风险。
3. 关键项目口径变化必须同步更新总目录、变更日志、日报或责任分工。
4. 不再生成对外资料包，客户可见内容以后续正式交付物为准。
5. 旧模板、错误资料包、错误设计基准不得继续作为有效交付物引用。

## 2. 当前有效口径

1. 合同以 `contracts/车金_AI智能客服售前跟进系统_技术服务合同_2026-05-26.pdf` 为对外正式版。
2. 报价以 `deliverables/AI智能客服售前跟进系统_工程报价单_v1.0.xlsx` 为准。
3. 技术蓝图以 `deliverables/AI智能客服售前跟进系统_技术方案手册_v2.6_正式工程完整合并版.md` 为准。
4. 当前阶段执行范围以 PRD v0.1、本地设计稿、接口契约和 P0 测试结论为准。
5. 当前 P0 运营后台验收以 `deliverables/P0运营后台验收标准_2026-06-02.md` 为准，但 UI 基准需按本地设计稿校正。

## 3. 必须记录的变更

以下情况必须写入 `文档变更日志.md`：

1. PRD 范围变化。
2. 技术方案版本变化。
3. UI 基准变化。
4. 测试结论从通过改为不通过或有条件通过。
5. 新增 P0/P1 缺陷。
6. 删除模板、资料包或废弃文档。
7. 交付范围、验收口径、上线口径变化。

## 4. 日报要求

文档管理日报必须包含：

1. 今日新增/删除/修改文档。
2. 当前有效文档是否完整。
3. 是否存在旧版比新版更完整、正式版缩水、模板误保留等异常。
4. PRD、产品/UI设计稿、技术方案、验收标准在同一阶段交付范围上是否一致。
5. 次日需要用户确认的问题。

## 5. 禁止事项

1. 禁止让多个会话引用不同的有效文档版本。
2. 禁止用整体 v2.5 验收标准替代当前 P0 验收标准。
3. 禁止把 PRD 当前不做内容理解为技术蓝图删除。
4. 禁止把测试报告中的“有条件通过”改写成“完全通过”。
5. 禁止把本地设计稿和 Figma 混用而不说明当前优先级。
