# 交付与文档 Rules

版本：v0.5.5

日期：2026-08-04

适用对象：项目文档总目录、文档变更日志、日报、交付物、合同、报价、归档。

## 1. 文档入口规则

1. `项目文档总目录.md` 是当前唯一入口。
2. 未列为当前有效的文档不得作为排期、开发、测试、验收或客户沟通依据。
3. 除非用户明确要求追溯历史、清理旧版或比对旧版，交付与文档角色不得打开、引用或依据旧版/废弃文档判断当前文档有效性、范围、进度、测试、验收或客户交付状态。
4. 新增、废弃、删除文档必须同步更新 `项目文档总目录.md` 和 `文档变更日志.md`。

## 1.1 版本管理规则

1. 任何一次正式文档更新都必须更新版本号，不允许只改日期或写“内部修订”而不升版。
2. 模块级、大范围或阶段边界变化递增第二段，例如 `v0.4 -> v0.5`。
3. 字段、规则、文案、引用和已定口径同步等小更新递增第三段，例如 `v0.4.5 -> v0.4.6`；缺少第三段时先补为 `.1`。
4. 新增需求、废弃需求和验收范围变化必须同步更新文档总目录、变更日志和一致性检查。
5. 不能把新增需求或范围变化写成“内部修订”来规避升版。
6. 新增专项文档必须从自身 `v0.1` 或对应起始版本开始命名，文件名必须包含版本号和日期。

## 2. 当前活跃口径

1. P0 已收口，相关旧文档已从活跃目录清理，不作为当前依据。
2. 当前活跃范围按技术方案 C0-C4 分段管理：C0/C1 稳定，C2 文字/语音/图片已完成 Windows 实机验收，C3 自动回复此前已实机验证，C4 按计划推进。
3. 当前执行范围以 PRD v0.4.6、技术方案 v0.8、当前 PUML、本地静态稿、`v16.132.0 / 37139bfd` 当前代码和 `v16.130.0 / 8ee53e1` 正式回滚证据为准。
4. 当前 C2/C3 结论不得引用 P0、低于 v0.8 的技术方案或旧 C2 报告作为最终依据；双仓源码统一已经完成，后续车辆信息变更仍须按运行代码变化执行自动化和必要 Windows 冒烟。
5. 不再生成对外资料包，后续客户可见内容只看正式交付物。

## 4. 风险发现规则

以下情况必须指出：

1. 活跃目录出现已经废弃的 P0 或旧版本文档。
2. PRD、UI、技术方案对同一当前阶段功能范围不一致。
3. 代码已实现但文档总目录未更新。
4. 文档写“已完成”，但没有对应代码、自测或测试证据。
5. 测试报告引用了错误阶段的验收标准。
6. 活跃文档继续把 Mac Worker、人工传值主流程、PRD v0.2、PRD v0.4.1、技术方案 v0.4/v0.5 或“任务中心产品 check 中”作为当前执行口径。

## 5. 清理规则

1. 当前活跃目录只保留正在推进或仍作为依据的文档。
2. 旧版文档如需删除，先确认不属于当前有效入口或测试证据。
3. 历史脚本、截图、旧测试 JSON、旧验收报告不得散落在 `deliverables/` 根目录。
4. 用户明确要求“不留归档”时，不再创建 `archive/` 作为替代入口。
