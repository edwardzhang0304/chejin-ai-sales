# 交付与文档 Rules

版本：v0.6.4

日期：2026-09-11

适用对象：PRD、技术方案、版本更新记录、全流程图及工程证据。

## 1. 文档入口规则

1. 项目级权威文档固定为 PRD、技术方案、版本更新记录、全流程图四份，不再维护总目录。
2. 其他专项说明、交接、检查、矩阵和报告不得作为平行口径；有效内容按性质并入四份文档。
3. 除非用户明确要求追溯历史、清理旧版或比对旧版，交付与文档角色不得打开、引用或依据旧版/废弃文档判断当前文档有效性、范围、进度、测试、验收或客户交付状态。
4. 原则上禁止新增第五份项目文档；版本、提交、测试、包哈希与回滚只更新版本更新记录。

## 1.1 版本管理规则

1. 四份权威文档的主版本必须与本次已确认的机器合同 `contract_revision` 完全一致；带版本的文件名、文档版本栏、流程图标题及当前入口同步更新。不得把文档编辑次数加成 `0.9.75.4` 等另一套主版本。
2. 仅修改文档内容时，主版本不变，单列 `文档修订：rN` 和日期，每次修订递增。修订次数不是软件版本或合同号；历史修订及已发布来源记录保持原义。
3. 应用/合同正式升版时，四文档主版本一起升到同号，修订次数从 r1 重新登记；存在未发布候选时，明确区分候选与已发布版本，不把本地未提交合同当成线上合同。
4. 新增需求、废弃需求和验收范围变化必须同步 PRD、技术方案、全流程图和版本更新记录中的实际受影响部分，并递增文档修订；是否需要合同升版按已确认交付范围决定，不单独递增文档主版本。
5. 根规则中关于文档递增版本的通用说明，对四份权威文档统一解释为本节的主版本与修订次数管理。
6. 禁止新增第五份权威文档；原始测试日志、截图和 ZIP 只作证据文件。文件重命名时同步当前引用，历史证据路径按原提交追溯。

## 2. 当前活跃口径

1. 当前灰度候选为 `0.9.57`，机器合同 SHA 为 `c978438ece0b9e950fe234f1366b4074635200886b5e2872d50f6bb84944c4be`。
2. C0—C4 的当前范围和职责以四份权威文档及机器合同为准；历史版本只能用于追溯，不能覆盖当前口径。
3. 提交、包、来源与回滚基线以版本更新记录绑定的不可变证据为准；当前回滚分支为 `rollback-0.9.57` 及 `rollback-0.9.57-source`。
4. 代码变化只执行受影响测试，形成候选或正式发包时再按版本更新记录扩大门禁。
5. 不再生成对外资料包，后续客户可见内容只看正式交付物。

## 4. 风险发现规则

以下情况必须指出：

1. 活跃目录出现已经废弃的 P0 或旧版本文档。
2. PRD、UI、技术方案对同一当前阶段功能范围不一致。
3. 代码已实现但对应 PRD、技术方案或版本更新记录未更新。
4. 文档写“已完成”，但没有对应代码、自测或测试证据。
5. 测试报告引用了错误阶段的验收标准。
6. 活跃文档继续把 Mac Worker、人工传值主流程、PRD v0.2、PRD v0.4.1、技术方案 v0.4/v0.5 或“任务中心产品 check 中”作为当前执行口径。

## 5. 清理规则

1. 当前活跃目录只保留正在推进或仍作为依据的文档。
2. 旧版文档如需删除，先确认不属于当前有效入口或测试证据。
3. 历史脚本、截图、旧测试 JSON、旧验收报告不得散落在 `deliverables/` 根目录。
4. 用户明确要求“不留归档”时，不再创建 `archive/` 作为替代入口。
