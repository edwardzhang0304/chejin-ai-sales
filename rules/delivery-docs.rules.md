# 交付与文档 Rules

版本：v0.6.1

日期：2026-08-11

适用对象：PRD、技术方案、版本更新记录、全流程图及工程证据。

## 1. 文档入口规则

1. 项目级权威文档固定为 PRD、技术方案、版本更新记录、全流程图四份，不再维护总目录。
2. 其他专项说明、交接、检查、矩阵和报告不得作为平行口径；有效内容按性质并入四份文档。
3. 除非用户明确要求追溯历史、清理旧版或比对旧版，交付与文档角色不得打开、引用或依据旧版/废弃文档判断当前文档有效性、范围、进度、测试、验收或客户交付状态。
4. 原则上禁止新增第五份项目文档；版本、提交、测试、包哈希与回滚只更新版本更新记录。

## 1.1 版本管理规则

1. 任何一次正式文档更新都必须更新版本号，不允许只改日期或写“内部修订”而不升版。
2. 模块级、大范围或阶段边界变化递增第二段，例如 `v0.4 -> v0.5`。
3. 字段、规则、文案、引用和已定口径同步等小更新递增第三段，例如 `v0.4.5 -> v0.4.6`；缺少第三段时先补为 `.1`。
4. 新增需求、废弃需求和验收范围变化必须同步 PRD、技术方案、全流程图和版本更新记录中的实际受影响部分。
5. 不能把新增需求或范围变化写成“内部修订”来规避升版。
6. 禁止新增专项方案、专项合同、专项验收或个人交接文档；原始测试日志、截图和 ZIP 只作证据文件。

## 2. 当前活跃口径

1. 当前未发布候选除语音目标握手、连续跟踪、有限终态和图片 UI 后刷新外，还存在正常消息流程误入语音编排器及权威画面枚举不一致 P0；目标合同为 `3.13.2`，完成前不得提交、打包或 UAT。
2. C0/C1、C3/C4 的历史已验收范围不因当前 C2 候选自动失效，但也不能用历史证据证明当前候选通过。
3. 当前执行范围以 PRD v0.5.6、技术方案 v0.8.10、唯一全流程图 v0.3 和版本更新记录为准；提交、包、合同与回滚基线以版本更新记录绑定的不可变证据为准。
4. 当前 C2/C3 结论不得引用已删除专项报告或旧聊天记录作为最终依据；代码变化只执行受影响测试，达到候选/发包阶段再按版本更新记录扩大门禁。
5. 不再生成对外资料包，后续客户可见内容只看正式交付物。

## 4. 风险发现规则

以下情况必须指出：

1. 活跃目录出现已经废弃的 P0 或旧版本文档。
2. PRD、UI、技术方案对同一当前阶段功能范围不一致。
3. 代码已实现但对应 PRD、技术方案或版本更新记录未更新。
4. 文档写“已完成”，但没有对应代码、自测或测试证据。
5. 测试报告引用了错误阶段的验收标准。
6. 活跃文档继续把 Mac Worker、人工传值主流程、PRD v0.2、PRD v0.4.1、技术方案 v0.4/v0.5 或“任务中心产品 check 中”作为当前执行口径。

## 5. 清理规则

1. 当前活跃目录只保留正在推进或仍作为依据的文档。
2. 旧版文档如需删除，先确认不属于当前有效入口或测试证据。
3. 历史脚本、截图、旧测试 JSON、旧验收报告不得散落在 `deliverables/` 根目录。
4. 用户明确要求“不留归档”时，不再创建 `archive/` 作为替代入口。
