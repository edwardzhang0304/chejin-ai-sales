# 产品与 UI Rules

版本：v0.1

日期：2026-06-03

适用对象：PRD、范围、不做范围、设计稿、本地静态稿、UI 差异、视觉验收口径。

## 1. 当前设计基准

1. 当前 UI 验收以本地设计稿/本地静态稿为准。
2. Figma 因额度问题暂不能作为当前最终上传和同步基准。
3. 如果本地设计稿与 Figma 不一致，当前先按本地稿推进，不以 Figma 卡住前端和测试。
4. 本地设计稿基准必须明确到文件、截图或页面路径，不能只说“按设计稿”。

## 2. PRD 范围口径

本期 P0 做：

1. 人工新增客户线索。
2. 手机号强去重。
3. 重复录入提示、重复记录和备注追加。
4. 线索列表、详情、筛选、分页。
5. 自动轮询分配销售。
6. 无可用销售时未分配和重新分配。
7. 标记无效、恢复有效、批量无效。
8. 手机号脱敏、明文查看和审计。
9. 选中线索导出。
10. 销售基础管理和轮询开关。

本期不做：

1. 抖音 API、小风车、企业私信 Webhook。
2. RPA 自动添加微信。
3. AI 自动回复、图片识别、自动召回。
4. 飞书接管通知。
5. 批量导入正式交付。
6. 销售移动端工作台。
7. 复杂 CRM 商机、合同、订单、业绩。

## 3. 新增客户弹窗当前口径

1. 联系方式固定为手机、微信、邮箱三个字段。
2. 手机必填，微信和邮箱可选。
3. 不提供添加/删除联系方式。
4. 自定义信息支持添加字段和删除字段。
5. 自定义字段由“字段名称 + 字段内容”组成。
6. 自定义字段不固定为意向车型、预算、城市。
7. 弹窗底部如果已有“取消”按钮，右上角不再放 `X` 关闭入口，关闭动作统一由“取消”承担。

## 4. UI 差异处理口径

UI 差异必须分三类：

| 类型 | 定义 |
|---|---|
| 必须修改 | 影响业务理解、操作路径、信息层级、设计稿一致性 |
| 建议修改 | 不阻塞 P0 测试，但视觉或体验不够稳 |
| 可接受差异 | 不影响 P0 测试，可以先放过 |

发现差异时不允许直接说“可接受”，必须先列差异表，再由产品/UI确认。

## 5. 设计交付要求

给前端或测试的设计交付必须包含：

1. 最终基准声明：以哪个本地文件/截图/页面为准。
2. 页面范围：默认态、线索管理、销售管理、新增客户弹窗、标记无效弹窗、恢复有效弹窗、详情抽屉、分页。
3. 必须一比一项：布局、文案、主操作、状态、弹窗、表格字段、分页、字号层级。
4. 可接受轻微差异：阴影、1-2px 间距、浏览器默认 select/checkbox 样式。
5. 不测范围：抖音 API、RPA、AI、飞书、批量导入。
