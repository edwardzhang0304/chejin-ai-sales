# 产品与 UI Rules

版本：v0.9

日期：2026-08-05

适用对象：PRD、范围、不做范围、设计稿、本地静态稿、UI 差异、视觉验收口径。

## 1. 当前设计基准

1. 当前 UI 验收以本地设计稿/本地静态稿为准。
2. Figma 因额度问题暂不能作为当前最终上传和同步基准。
3. 如果本地设计稿与 Figma 不一致，当前先按本地稿推进，不以 Figma 卡住前端和测试。
4. 本地设计稿基准必须明确到文件、截图或页面路径，不能只说“按设计稿”。
5. 当前 P1a 运营后台静态稿基准为 `website/ops-admin.html`、`website/ops-admin.css`、`website/ops-admin.js`。
6. 当前 P1a Worker 工作台静态稿基准为 `website/worker-workbench.html`、`website/worker-workbench.css`、`website/worker-workbench.js`。
7. 除非用户明确要求追溯历史、清理旧版或比对旧版，产品和 UI 不得打开、引用或依据旧版/废弃文档判断当前 PRD、设计稿、UI 差异或验收口径。

## 1.1 运营后台登录当前口径

1. 未登录用户只看到账号、密码和登录按钮，不展示任何后台业务数据。
2. 账号由服务端预先创建；不做注册、短信、第三方登录、自助找回密码和账号管理页。
3. 登录成功进入默认空白工作区；所有账号拥有全部后台模块和操作权限，不展示角色、
   viewer、只读或无权限状态。
4. 左侧导航底部展示当前账号和退出入口；会话失效或退出后返回登录页，浏览器后退
   不能重新查看后台数据。
5. 登录错误只显示统一中文业务提示，不展示账号是否存在、内部错误堆栈或鉴权 Token。

## 2. P1a 已完成基础 UI 范围

本节保留销售、Worker 和任务中心基础 UI 约束，不再代表整个项目当前范围。登录、C2/C3 和车辆管理当前产品行为以 PRD v0.5.3 为准。

P1a 做：

1. 销售管理升级。
2. 销售新增时可选 Worker，且 Worker 非必填。
3. 销售详情抽屉原地编辑。
4. 销售详情内可绑定、更换、清空 Worker。
5. 销售列表展示当前 Worker、Worker 状态、阻塞任务数。
6. Worker 管理。
7. Worker 列表、指标、筛选、详情抽屉。
8. Worker ID 和 Worker Token 展示规则。
9. Worker 启用/停用。
10. Worker 心跳、在线/离线、空闲/忙碌、当前任务。
11. Worker 重置绑定。
12. 任务中心本地设计稿：任务列表、任务详情抽屉、任务状态、执行步骤、业务结果、异常原因和详情操作区。
13. 车金 Worker 客户端 Windows 单应用本地设计稿：首次绑定、暂停接单、接单中、等待任务、非接单时段、执行任务中、执行完成、离线、执行失败、设置页和本机执行日志明细页。

P1a 当时不做：

1. 独立自动化应用入口或第二个品牌概念。
2. AI 自动回复、图片识别、自动召回；其中 C2 图片和 C3 自动回复现已进入正式产品口径，不再沿用此历史范围判断当前状态。
3. 飞书接管通知。
4. 抖音 API、小风车、企业私信 Webhook。
5. 批量导入正式交付。
6. Mac Worker。
7. 销售移动端工作台。
8. 复杂 CRM 商机、合同、订单、业绩。

## 3. 销售管理当前口径

1. 销售列表展示销售姓名、手机号、微信号、状态、当前 Worker、Worker 状态、排序、今日分配、阻塞任务。
2. 销售详情通过右侧抽屉查看。
3. 点击 `编辑销售` 后，抽屉内字段原地变为输入控件，不再打开第二层表单。
4. 状态字段使用 `启用 / 停用`，提示为“启用/关闭分配线索”。
5. Worker 是销售字段之一；新增销售时可不选 Worker。
6. 销售详情编辑态可绑定、更换或清空 Worker。
7. 离线但启用的 Worker 可以绑定；已停用 Worker 不可绑定。
8. 已绑定其他销售的 Worker 不可重复绑定。
9. 销售未绑定 Worker 时，分配线索仍成功，但后续 add_friend 任务进入 blocked。

## 4. Worker 管理当前口径

1. Worker 列表展示 Worker 名称、Worker ID、状态、客户端绑定状态、在线状态、运行状态、当前任务、绑定销售、最近心跳。
2. Worker Token 不在列表展示，只在详情抽屉展示。
3. 新增 Worker 后服务端生成 Worker ID 和 Worker Token。
4. Worker 详情抽屉展示基础信息、客户端绑定、绑定销售和操作。
5. 绑定销售不在 Worker 详情中直接修改，需去销售管理编辑。
6. 重置绑定会生成新的 Worker Token，旧 Token 失效。
7. 如果存在 running 任务，重置绑定必须强提示，但不自动取消或改派任务。

## 5. 任务中心当前口径

1. 任务中心已进入本地 UI 设计稿阶段，当前基准为 `website/ops-admin.html?module=tasks`。
2. 任务中心前端开发必须以当前 PRD v0.5.3 和本地静态稿为业务口径；召回不新增 `follow_up` 任务，统一使用 `trigger_type=recall` 的 `chat_reply`。
3. 任务中心不放 `创建任务` 按钮，任务由服务端自动创建。
4. 任务中心列表不放 `操作 / 查看详情` 列，点击整行打开右侧任务详情抽屉。
5. `执行状态` 只展示 `Task.status`：阻塞、待处理、处理中、已完成、失败、已取消。
6. `业务结果 / 异常原因` 是聚合列：completed 显示 result_code，failed 显示 error_code，blocked 显示 block_code。
7. 任务详情抽屉必须展示基础信息、业务对象、执行信息、状态流转、备注和操作区。
8. `查看执行方` 前端必须跳转到 Worker 管理并打开对应 Worker 详情；`处理阻塞` 遇到 `SALES_WORKER_NOT_BOUND` 必须跳转销售管理，打开销售详情编辑态并聚焦 Worker 字段。
9. `标记线索无效` 不是所有 failed 任务都展示，必须按 `task_type + error_code` 判断；当前仅 `add_friend + PHONE_NOT_FOUND` 等线索质量类失败原因展示。
10. 本地设计稿里的任务操作按钮可作为静态预览，但前端实现不得只弹提示，必须按 PRD 跳转、确认或调用接口。
11. 车金 Worker 客户端已进入本地 UI 设计稿阶段，当前基准为 `website/worker-workbench.html`。
12. 本期只做 Windows 单应用客户端，不做 Mac 版；界面统一叫 `车金 Worker 客户端`，不得出现第二个应用或第二个品牌概念。
13. Worker 首页只展示当前绑定销售、连接状态/最近心跳、接单状态、自动化组件是否可用、微信是否已连接和当前是否有任务；不得展示今日任务统计、失败数、待处理数或最近错误列表。
14. Worker 首页不得直接展示本机执行日志明细；本机执行日志明细放在设置页。
15. 设置页只展示自动接单时段入口、本机执行日志入口和客户端版本号；自动接单时段的开关、开始时间、结束时间和说明必须放在 `设置 / 接单时段设置` 二级页，不得直接摊在设置首页。设置页不得展示当前 Worker ID、当前绑定销售、服务端连接状态、自动化组件状态、微信状态、重新绑定 Worker 或检查更新。
16. 自动接单时段用于控制 Worker 是否自动领取任务，不用于判断客户端是否在线；页面文案统一使用 `自动接单时段`，不得写成 `在线时段 / 离线时段`。
17. 自动接单时段默认关闭；第一版只支持每天一个接单时间段，支持跨天，不做每周不同时间表、节假日、多时段或临时强制接单。
18. 非接单时段客户端保持连接和心跳，自动化组件、微信状态仍正常展示，但不领取新任务；Worker 状态仍展示为 `暂停接单`，非接单原因由页面标题或说明文案表达。
19. 到达自动接单时段结束时间不打断当前 running 任务；当前任务完成或失败后再暂停接单。
20. 操作按钮统一使用 `开始接单 / 暂停接单`；状态文案统一使用 `接单中 / 暂停接单 / 离线`。
21. 暂停接单不打断当前 running 任务；当前任务完成或失败后不再领取下一条。
22. 任务链路只展示已发生和正在发生的步骤，不展示未到达步骤。
23. 任务失败不在客户端处理；客户端不得展示重试、标记线索无效、重新创建任务等按钮。
24. Worker 客户端展示完整手机号，仅用于当前任务执行。
25. 心跳超过 2 分钟未上报标记离线，running 任务不自动失败；超过 10 分钟未恢复时由任务中心提示运营介入。

## 6. 车辆管理当前口径

1. 第一期开且只开一个“车辆管理”模块，不新增独立知识规则页面。
2. 列表无操作列，点击整行打开右侧车辆详情抽屉；新增车辆使用居中弹窗，编辑在详情抽屉内原地完成。
3. 新增车辆只要求车辆展示名称，系统生成车辆编号，默认已下架，保存后自动打开详情。
4. 上架必须有展示名称、公开售价和至少一张有效图片；上下架均二次确认，下架不填原因。
5. 图片在车辆创建后维护，第一张自动为主图；支持多选上传、排序和删除，单张不超过 10MB。
6. Excel 使用上传、预览、确认导入三步流程；任何数据错误都不得确认，不提供跳过错误继续导入。
7. VIN、车牌号、采购价格和内部备注只在内部区域展示，不得进入客户证据。
8. 当前 UI 详细字段、错误文案和验收标准以 PRD v0.5.3 第 14、18.8 节为准。
9. 第一期不提供车辆删除；车辆退出客服范围统一使用下架。

## 7. UI 差异处理口径

UI 差异必须分三类：

| 类型 | 定义 |
|---|---|
| 必须修改 | 影响业务理解、操作路径、信息层级、设计稿一致性 |
| 建议修改 | 不阻塞当前阶段测试，但视觉或体验不够稳 |
| 可接受差异 | 不影响当前阶段测试，可以先放过 |

发现差异时不允许直接说“可接受”，必须先列差异表，再由产品/UI确认。

## 7. 设计交付要求

给前端或测试的设计交付必须包含：

1. 最终基准声明：以哪个本地文件/截图/页面为准。
2. 页面范围：当前已进入 UI 的为销售管理、Worker 管理、任务中心列表页、任务详情抽屉和车金 Worker 客户端 Windows 单应用第一版。
3. 必须一比一项：布局、文案、主操作、状态、弹窗、表格字段、分页、字号层级。
4. 可接受轻微差异：阴影、1-2px 间距、浏览器默认 select/checkbox 样式。
5. 不测范围：抖音 API、AI、飞书、批量导入、Mac Worker、第二个 Worker 应用概念。

## 8. 本地设计稿到前端一比一复现约束

1. 不允许只用“按设计稿”“看本地稿”作为前端实现说明，必须明确到页面路径、模块、截图或具体文件版本。
2. 本地 HTML/CSS 静态稿不是可直接复用的前端组件实现。交付给前端时，UI 必须同步给出可执行的复现约束。
3. 复现约束至少包含：颜色 token、字号、行高、按钮高度、输入框高度、圆角、弹窗宽度、抽屉宽度、表格行高、表格列字段、模块间距、空状态、加载状态、错误状态。
4. 前端不得基于组件库默认样式、Tailwind 默认间距、浏览器默认表单样式自行“差不多实现”。凡是设计稿已有明确规格的，必须按设计稿规格落地。
5. 如果前端技术栈与静态稿不同，例如 React/Vite/Tailwind/组件库，不能以“技术栈不同”为理由接受明显视觉差异。技术栈差异只影响实现方式，不改变验收标准。
6. UI 交付必须标注“必须一比一复现项”和“可接受轻微差异项”。未标注为可接受的差异，默认进入待确认或必须修改。
7. 前端实现完成后，必须用固定截图场景对比本地设计稿，包括：默认空白态、线索管理、销售管理、Worker 管理、任务中心、新增客户弹窗、新增销售弹窗、新增 Worker 弹窗、详情抽屉查看态、详情抽屉编辑态、标记无效/恢复有效/重置绑定弹窗。
8. UI/产品确认差异时必须按“必须修改 / 建议修改 / 可接受差异”列差异表，不允许用一句“整体可以”替代逐项确认。
9. 如果设计稿在实现过程中发生调整，必须同步更新本地设计稿文件和交付说明；前端不得同时拿旧截图、旧 HTML、旧 Figma 或口头描述混合作为实现依据。
10. 任何会影响一比一复现的规则变更，例如弹窗宽度、按钮规格、表格列、抽屉结构、导航项、状态文案，必须先更新本规则或对应设计交付说明，再通知前端修改。
11. UI 修改必须严格限定在用户明确指出的问题范围内；不得借机调整样式、结构、交互或其他未被要求的内容。如确实认为需要联动修改，必须先说明原因、影响范围和备选方案，等待用户确认后再改。
12. 所有图标必须使用 SVG、图标组件或成熟图标库资源，不允许用 CSS 线条、伪元素、box-shadow 等方式手画图标。状态点、时间线连接线、背景高亮和动效光晕不属于图标，但不得被设计成容易误认为图标的形态。
