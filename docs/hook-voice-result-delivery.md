# 语音结果补交与读取边界

语音转写的原始结果仍由 `hook_voice_attempts` 保存；上传前保存原绑定意图，后端确认后保存原回执。请求丢失、响应丢失或重启均沿用原消息、原绑定及原结果，不重新调用转写、不替换原授权。

## 一次调度只处理一批待办

`hook_voice_result_delivery` 是同一本机 SQLite 中可恢复的补交投影，按数据目录、账号、账号代次和原生消息 ID 区分。状态为未核对、待补交、已确认；已确认行保存原回执和原结果摘要，不以单独的内存布尔值认定完成。

调度入口每轮只调用一次统一核对，再按绑定 ID、修订号及微信 ID 分配待办，不为每个客户重复扫描全部回执文件。

- 旧数据每轮最多登记 32 条；未登记、未核对及待补交均阻止安全安装。
- 每轮从未核对与待补交队列各取最多 16 条，轮换处理顺序。文件核对最多 32 条；50 毫秒软预算在两次读取之间检查，不能中断单次操作系统读取。
- 已确认历史凭证正常轮次不重复打开；原始语音记录更新或删除时，同一事务中的触发器使对应投影失效。重新读取发现摘要不符时停止并报错。
- 实际补交沿待办顺序选择客户与该客户的消息，不被后台库存原始顺序覆盖。每次实际尝试前把该待办移到队尾并提交，再发 HTTP；即使异常退出或重启，下轮也给其他待办机会。相同绑定内重复的库存条目只处理一次。
- 这里只调整已有结果的补交顺序，不吞掉异常。可等待失败仍交原业务循环处理；账号、授权、原证据冲突和未知调用继续走原故障与恢复规则。
- 回执已写入、投影尚未提交就中断时，下轮从原回执恢复，不再上传。网络操作在数据库事务提交后执行。
- 安装边界只读查询数据库，不打开历史凭证文件；不存在投影时将旧终态记录视为待核对，结构或失效触发器异常时拒绝放行。

数据库查询仍需检查是否存在未登记的旧记录；这是元数据查询，不能宣称已经做到与历史记录数量完全无关。队列不会因单个离线结果一直占首位而饿死其他待办。

## 保护和取证

不清理绑定、旧结果、原回执、未知发送或原始消息。未知语音和发送继续走原恢复规则；投影不授予发送权限，不解除暂停或故障。原桌面故障 ZIP 收集此投影，未核对和待补交优先，仍遵循原脱敏、体积和完整性清单规则。

这是 Worker 本机投影的惰性初始化，无独立迁移程序、无后端数据库迁移、无新的安装依赖。原目录保留升级时也保留数据库；旧记录分批核对期间不得绕过安装保护。

## 本轮验证范围

合成 1,000／5,000 条已确认历史、20 个客户的真实调度入口：每条旧凭证在首次核对期间读取一次，随后五轮无额外历史凭证读取。另覆盖中断回滚、重启、数据目录隔离、记录变化失效、队列轮换和原故障 ZIP。

本地正式调度与 HTTP 链路覆盖原结果上传请求／响应丢失、重新启动、补交确认、保持暂停、手动恢复、回复发送和回执。确认原结果、绑定、消息 ID 不变，不重复转写或发送。以上是本地合成验证，不代表 Windows 封存安装包或销售原机已通过。`c16dfa6e` 复审已确认历史读取、恢复到发送回执及故障 ZIP，但实际补交公平性未通过。本轮追加真实调度→本地 HTTP 收据对照：首条持续失败时其他待办确认，重建与库存换序不影响，首条恢复后按原结果结清；补修仍待独立复审。
