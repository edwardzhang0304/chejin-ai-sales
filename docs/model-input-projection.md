# AI 输入投影职责

模型输入与故障证据分别维护：精简只作用于发给模型的副本，不修改原始消息、查询回执、冻结依据、回执指纹或业务恢复记录。

| 信息 | 模型入口 | 保留规则 |
| --- | --- | --- |
| 客户本轮原话与必要上下文 | conversation | 沿用现有历史策略，不新增裁剪 |
| 原始消息来源表 | catalog_protocol.sources | 所有阶段保留，包括理解阶段未引用的历史条件 |
| 筛选条件、范围、计数、排序及缺失资料 | catalog_protocol.receipt | 只传一份；保留完整语义与未知字段，推荐项引用车辆 ID |
| 本轮车辆公开资料 | content_basis.product_master.items | 保留全部已选公开字段，不二次截断或筛选 |
| 正式知识及引用 | content_basis.formal_knowledge / formal_knowledge_sources | 保留完整依据及引用身份 |
| 理解模型的原始查询 | 原始证据、现有审核入口 | 审核仍能检查理解结果；写回复阶段使用程序接受的条件 |
| 内部批次、查询版本、重复请求与发布元数据 | 原始证据 | 不作为回复素材重复输入 |

统一入口：catalog_query.prompt_protocol 负责查询输入投影，reply_evidence_builder.model_authority_view 负责公开事实投影，生成、修复和原有审核共用。历史理解指引在生成和修复的 system 中保留一次。

全库存筛选、输出协议、原有审核开关、发送许可、转人工和未知结果恢复不在本次变更范围。未启用程序准备流程的原 OCR 输入保持原结构。

验收必须检查：多条件、真实零匹配、未知字段、未支持条件、未被理解阶段引用的旧条件、预算与首付、生成与修复指引、冻结证据不变，以及模型实际产出的回复。模型实验失败也需保留；一次成功不表示模型输出格式永远正确。真实客户资料和模型密钥不进入源码或提交。
