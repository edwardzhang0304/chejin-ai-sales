模型输入与故障证据分别维护：精简只作用于发给模型的副本，不修改原始消息、查询回执、冻结依据、回执指纹或业务恢复记录。

统一入口：catalog_query.prompt_protocol 负责查询输入投影，reply_evidence_builder.model_authority_view 负责公开事实投影，生成、修复和原有审核共用。历史理解指引在生成和修复的 system 中保留一次。

全库存筛选、输出协议、原有审核开关、发送许可、转人工和未知结果恢复不在本次变更范围。未启用程序准备流程的原 OCR 输入保持原结构。

验收必须检查：多条件、真实零匹配、未知字段、未支持条件、未被理解阶段引用的旧条件、预算与首付、生成与修复指引、冻结证据不变，以及模型实际产出的回复。模型实验失败也需保留；一次成功不表示模型输出格式永远正确。真实客户资料和模型密钥不进入源码或提交。

本轮最小改动（本地候选，待用户确认）：原内容修复入口保留本稿审核的具体 `reason`，完整改稿要求只放在原 `repair_instruction` 字段一次；原查询重试入口补传校验器已有的字段路径、是否存在和实际值类型，不传原始拒绝值或哈希。确定事实冲突、必要审核、有限重试预算及发送核对规则保持不变。未发送草稿不因此进入已发送历史，旧终态不会因本次改动重新执行。

旧测试需按当前合同取数：查询回执位于 `catalog_protocol`，公开事实位于 `content_basis`；客户明确排序须有真实原话支持。含义/范围问题的合成审核不能一面固定返回“通过”，一面要求已移除的文字规则否决；这类测试验证原审核拒绝后不发送，并验证审核收到同源事实。合成测试通过只证明链路与门禁，不证明真实模型永远不会漏判或误判。

复审补充：查询失败指引作为完整字段经过后台、Brain 输入、普通/精简提示直至模型调用，不再使用 700/360 字符切片。统一模型调用入口对该字段设置 8192 字符上限；超过上限不调用模型、不发送残缺指引，沿既有 `input_capacity_exceeded` 路径明确转人工并保留记录，不追加自动重试。合成验收覆盖六字段同时缺失、恰好达到上限及超过上限，以及同一修复回复经正式 `HookFormalRuntime` 完成发送前核对、模拟 Hook 发送、历史核对、回执和任务结束；再次进入已结束批次不会重发。
