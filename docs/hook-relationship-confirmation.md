# 联系人备注二次复核与诊断证据

## 行为

备注比对沿用 `hook_contact_rules` 的同一套对象、身份和短码解析。正常匹配不增加读取或截图。

首次 `remark_changed` 在后端绑定的 `native_context` 中创建临时复核状态和一次性确认标识，不关闭 AI、不转人工、不取消欢迎语。统一发送授权入口暂缓该客户的新发送；库存也标注临时状态，调度器不为这个客户抢占新 Flow。已有消息回传、未知发送核对和其他客户调度继续使用原入口。

Worker 收到确认标识后重新调用一次 `GetFriendAndChatRoomList`，将新返回与确认标识一起提交。不得复制第一次数据充当第二次读取。

- 第二次匹配：只清除临时复核状态。没有设置 AI、销售或 Worker 为启用/接单，也不会关闭既有人工交接。
- 连续两次明确变化：沿用原转人工入口及 `HOOK_CONTACT_REMARK_CHANGED`，保留原发送与绑定凭证。
- 第二次缺失、重复、结构异常或读取失败：保留暂缓状态，不当成变化、删除或恢复。正常周期再核验；每轮每客户至多增加一次读取。
- 首次请求重放不计第二次。确认标识限定当前绑定修订、账号代次、进程代次，五分钟过期；过期重建复核，旧标识不能确认。中间不确定或正常观察打断“连续变化”。
- `HOOK_CONTACT_REMARK_CONFIRMATION_PENDING` 是暂态，不进入原未发送任务的取消结算分支。物理 begin 仍需原有授权，不能因这次复核绕过。

## 证据

共享比对器产生目标客户的必要字段：预期短码、目标身份、匹配数、备注字段名/类型/值、截断标记与摘要。最多两个目标对象、每对象十六字段、字符串保留前256字符；省略数量明确记录。完整联系人返回只保留摘要，不把其他客户通讯录写入文件。

Worker 在调用接口前留存比对，接口完成后留存后端结果；复核失败也记录失败阶段。每绑定修订保留固定 `latest.json` 与最近确认异常的 `confirmed.json`，普通匹配轮询不覆盖异常材料，重启不删除。后端保存最近复核对与转人工时的证据对；确认标识不写进导出内容。写文件失败产生专门日志。

原桌面诊断入口将 `transactions/hook/relationship-reviews` 优先纳入 ZIP 的 `receipts/hook/relationship-reviews`，沿用完整性清单、脱敏和读取/体积/时间限制说明。不新增销售操作入口，不修改历史凭证。

## 交付边界

这是后端与 Worker 配套变更：旧 Worker 不执行新的二次请求；只部署后端会让异常客户停留在安全的待复核状态，不能声称兼容完成。正式发布时按项目合同同步规则配套交付，本次代码变更没有升版本、打包、部署或更改现存客户状态。

本地验证包括真实本地 HTTP、隔离 SQLite、合成 Hook 返回和真实 ZIP 导出。Windows 提供方实机的两次返回仍待后续包验证。两次独立接口读取不等于证明提供方内部没有缓存，旧现场未保存的原始备注也不能补造。
