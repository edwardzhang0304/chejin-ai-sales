# 新好友首次备注确认与诊断证据

## 范围

按用户 2026-11-04 的进一步要求，备注只用于刚加好友的首次确认。确认通过后，使用已有 wxid、账号代次、绑定修订和授权校验，不在分段发送期间反复检查备注。不新增流程暂存、分段切换或旧许可重发机制。

新绑定创建时在 `native_context` 中记录 `relationship_initial_check=pending`，首次回复前进行确认。原库存标注待确认，调度器不为此客户申请发送 Flow；后端统一发送授权与 Flow 登记入口再次核对，确保待确认期间没有发送许可。消息回传与历史核对保留，其他客户继续使用原调度。已有绑定不追溯进入新检查，原人工接管、未知发送和故障记录不清除。

## 一次复核

共享 `hook_contact_rules` 负责对象、身份和短码解析。

- 首次正常匹配：完成初始确认，不增加第二次读取或截图。
- 首次明确备注变化：后端保留首次证据并给一次性确认标识，不关闭 AI、不转人工、不取消欢迎语。Worker 收到后重新调用一次联系人接口，不复用首次返回。
- 第二次正常匹配：完成初始确认，原排队回复按原发送条件执行。不会解除人工暂停、故障或既有人工接管。
- 连续两次明确变化：沿用原人工核对入口，保存两次目标证据。
- 缺失、重复、结构不明确或读取失败：仍为初始待确认，不推断删除或备注变化。后续周期重查，每轮每客户最多增加一次物理读取。
- 确认标识限定绑定修订、账号与进程代次，五分钟过期。旧请求不能再次确认。中间不确定或正常观察打断连续变化。

初始确认完成后库存不再安排此绑定的备注检查；迟到的备注观察不会重新创建暂缓状态。因此备注确认不会出现在已获准的同一条分段回复中，不会将其误送到“客户追加消息”的旧取消恢复分支。已有连续分段、未确认发送及恢复保护完全沿用。

## 证据

仅保存目标客户必要字段：预期短码、目标 wxid、匹配数、字段名/类型/值、截断标记与摘要。最多两个目标对象、每对象十六字段、字符串前 256 字符；省略数量明确。不保存其他联系人的通讯录内容。

记录包含账号代次、进程代次、绑定修订、读取尝试编号、时间、read/compare/post/complete 阶段及具体失败代码。首次或第二次读取的传输错误、非法响应、HTTP 拒绝、过大响应、身份异常均进入同一目标记录。身份异常仍向上抛出，不伪造关系结论。接口拒绝保留阶段和状态码。

每绑定修订保留 `latest.json` 与确认异常的 `confirmed.json`；普通匹配不覆盖旧异常。原桌面诊断入口优先将这些文件纳入故障 ZIP，沿用脱敏及收集清单。可选证据文件写失败时复用独立、有界的 `evidence-recorder-failures.jsonl`，保存原原因、目标和缺件说明，不再尝试写 SQLite 日志覆盖第一原因。全盘不可写时不能保证生成文件，现有全局存储与身份门禁不变。

## 验收边界

后端与 Worker 配套变更，发布时按现有合同同步流程交付。本轮不打包、不部署、不改生产客户。

本地使用隔离 SQLite、实际 HTTP 入口、生产库存与调度消费者、合成模型/联系人返回及实际故障 ZIP。物理微信发送用明确的测试边界代替，Windows 实机待验。两次独立接口调用不能证明提供方内部无缓存，旧现场未保存的联系人返回不能补造。
